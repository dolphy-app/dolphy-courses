# Promise API

Часто нужно запустить сразу несколько асинхронных действий: загрузить пять файлов, опросить три сервера, дождаться любого из двух источников. Перебирать их по очереди было бы медленно. У класса `Promise` есть шесть статических методов, которые помогают координировать несколько промисов. В этом уроке разберём каждый: что принимает, когда выполняется, когда отклоняется и какой результат возвращает.

Во всех примерах ниже будем использовать вспомогательную функцию, которая создаёт промис с заданной задержкой и исходом:

```js
const delay = (ms, value, fail = false) =>
  new Promise((resolve, reject) =>
    setTimeout(() => (fail ? reject(new Error(value)) : resolve(value)), ms),
  );
```

## Promise.all

`Promise.all(iterable)` принимает набор промисов (обычно массив) и возвращает один промис. Он выполняется, когда выполнены **все** входные промисы, и его значение — массив результатов в **том же порядке**, что и входные промисы (а не в порядке завершения):

```js
Promise.all([delay(30, 'a'), delay(10, 'b'), delay(20, 'c')]).then((results) => {
  console.log(results); // [ 'a', 'b', 'c' ]
});
```

Общее время — время самого долгого, то есть около 30 мс, а не 60. Это и есть выигрыш от параллельности.

Если хоть один из промисов отклонится, `Promise.all` тоже сразу отклонится с этой ошибкой. Результаты остальных будут потеряны, а сами они продолжат выполняться (отменить промис нельзя):

```js
Promise.all([delay(10, 'a'), delay(5, 'boom', true), 42]).catch((e) => {
  console.log(e.message); // boom
});
```

Среди элементов могут быть и обычные значения, не промисы: они попадают в результат как есть. Пустой массив даёт сразу выполненный пустой массив:

```js
Promise.all([1, 2, Promise.resolve(3)]).then((r) => console.log(r)); // [ 1, 2, 3 ]
Promise.all([]).then((r) => console.log(r)); // []
```

Типичная идиома — применить асинхронную функцию к каждому элементу массива:

```js
const names = ['a', 'b'];
Promise.all(names.map((n, i) => delay(5 * (2 - i), n.toUpperCase()))).then((r) =>
  console.log(r), // [ 'A', 'B' ]
);
```

## Promise.allSettled

`Promise.all` слишком строг, если нужны результаты всех операций, даже неудачных. `Promise.allSettled` ждёт **завершения** всех входных промисов и никогда не отклоняется. Результат — массив объектов: `{ status: 'fulfilled', value }` или `{ status: 'rejected', reason }`:

```js
Promise.allSettled([delay(5, 'ok'), delay(5, 'bad', true), 3]).then((results) => {
  for (const r of results) {
    console.log(r.status, r.status === 'fulfilled' ? r.value : r.reason.message);
  }
});
// fulfilled ok
// rejected bad
// fulfilled 3
```

Он подходит для «собрать всё, что получилось»: загрузить много независимых ресурсов и показать успешные, а по неудачным — вывести сообщения.

## Promise.race

`Promise.race` возвращает промис, который повторяет судьбу **первого завершившегося** входного промиса, неважно, успешного или нет:

```js
Promise.race([delay(20, 'медленный'), delay(5, 'быстрый')]).then(console.log); // быстрый

Promise.race([delay(20, 'медленный'), delay(5, 'сбой', true)]).catch((e) => console.log(e.message)); // сбой
```

Классическое применение — тайм-аут: гонка между реальной операцией и таймером, который отклоняется через заданное время. Остальные промисы никто не отменяет, их результат просто игнорируется. `Promise.race([])` с пустым набором навсегда остаётся в ожидании.

## Promise.any

`Promise.any` ждёт **первого успешного** результата. Отклонённые промисы он игнорирует, пока не останется надежд. Если отклонены все, результат отклоняется специальной ошибкой `AggregateError`, у которой в свойстве `errors` лежат все причины по порядку входных промисов:

```js
Promise.any([delay(5, 'e1', true), delay(10, 'победитель'), delay(20, 'позже')]).then(console.log);
// победитель

Promise.any([delay(5, 'e1', true), delay(10, 'e2', true)]).catch((e) => {
  console.log(e.constructor.name); // AggregateError
  console.log(e.errors.map((x) => x.message)); // [ 'e1', 'e2' ]
});
```

`Promise.any([])` с пустым набором сразу отклоняется `AggregateError` с пустым `errors`.

## Сводная таблица

| Метод | Выполняется, когда | Отклоняется, когда |
|---|---|---|
| `all` | выполнены все | отклонён любой (первая ошибка) |
| `allSettled` | завершены все | никогда |
| `race` | завершён любой (успешно) | завершён любой (с ошибкой) |
| `any` | выполнен любой | отклонены все (`AggregateError`) |

## Promise.resolve, Promise.reject, Promise.withResolvers

Готовые промисы создают `Promise.resolve(value)` и `Promise.reject(error)`. Они удобны, когда функция должна всегда возвращать промис, даже если результат уже известен.

В Node.js 22 есть и `Promise.withResolvers()`: он возвращает объект `{ promise, resolve, reject }`, позволяя завершить промис снаружи, не оборачивая код в исполнитель:

```js
const { promise, resolve } = Promise.withResolvers();
setTimeout(() => resolve('снаружи'), 5);
promise.then(console.log); // снаружи
```

## Итерируемое вместо массива

Все методы принимают любой итерируемый объект, а не только массив: строку, `Set`, генератор. Это иногда ведёт к курьёзам: `Promise.all('ab')` выдаст `['a', 'b']`, потому что строка итерируется по символам. Если передать не итерируемое значение, метод вернёт отклонённый промис с `TypeError`.

## Типичные ошибки

- Ожидать, что результаты `Promise.all` придут в порядке завершения: порядок всегда равен порядку входа.
- Использовать `all`, когда нужны результаты всех операций, включая неудачные (здесь нужен `allSettled`).
- Путать `race` и `any`: `race` завершается при первом *любом* исходе, `any` — при первом *успешном*.
- Запускать задачи по очереди через `await` в цикле там, где они независимы, и терять время.
- Думать, что после отклонения `all` остальные операции отменяются: они продолжают выполняться.
- Не обрабатывать `AggregateError` у `any`: сообщение в нём общее, подробности — в `errors`.

## Коротко

- `all` — параллельный запуск и массив результатов в порядке входа; первая ошибка отклоняет всё.
- `allSettled` — ждёт всех и возвращает статусы, не отклоняется.
- `race` — первый завершившийся, успешный или нет; `any` — первый успешный, иначе `AggregateError`.
- Обычные значения в массиве считаются выполненными промисами.
- `Promise.withResolvers()` создаёт промис и функции управления им без исполнителя.
