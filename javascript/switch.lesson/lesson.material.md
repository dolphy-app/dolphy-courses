# Конструкция switch

Когда одно и то же значение приходится сравнивать с несколькими вариантами подряд, цепочка `if ... else if` быстро разрастается. Конструкция `switch` записывает такой выбор компактнее и нагляднее. После урока вы будете понимать, как она сравнивает значения, зачем нужен `break` и что происходит, если его забыть.

## Синтаксис

`switch` состоит из выражения в скобках и набора ветвей `case`, плюс необязательной ветви `default`:

```js
const color = 'green';

switch (color) {
  case 'red':
    console.log('стоп');
    break;
  case 'green':
    console.log('можно ехать'); // сработает эта ветвь
    break;
  default:
    console.log('неизвестный сигнал');
}
// можно ехать
```

Порядок работы такой:

1. Вычисляется выражение в скобках `switch`.
2. Его значение по очереди сравнивается со значениями `case` сверху вниз.
3. На первом совпадении выполнение **входит** в эту ветвь и идёт дальше, пока не встретит `break` (или другой выход: `return`, `throw`, `continue`) либо не дойдёт до конца `switch`.
4. Если ни один `case` не подошёл, выполняется `default`. Если его нет, `switch` просто ничего не делает.

```js
let result = 'не менялось';

switch (7) {
  case 1:
    result = 'один';
}
console.log(result); // не менялось
```

## Провал сквозь ветви: что бывает без break

Ключевой момент: `case` — это не отдельный блок, а **метка**, с которой начинается выполнение. Как только вход найден, проверки остальных `case` больше не делаются, а код ниже идёт подряд, включая чужие ветви. Это называется «проваливанием» (fallthrough):

```js
const out = [];
const n = 1;

switch (n) {
  case 1:
    out.push('один');
  case 2:
    out.push('два');
  case 3:
    out.push('три');
    break;
  case 4:
    out.push('четыре');
}
console.log(out.join(', ')); // один, два, три
```

Ветвь `case 2` не сравнивалась с `1`, мы просто упали в неё сверху. Забытый `break` — самая частая ошибка с `switch`. Поэтому `break` ставят и в последней ветви: если позже кто-то допишет ещё один `case` ниже, провала не случится.

## Группировка case

Побочный эффект провала полезен: несколько `case` подряд без кода между ними делят один обработчик.

```js
function dayType(day) {
  switch (day) {
    case 'sat':
    case 'sun':
      return 'выходной';
    case 'mon':
    case 'tue':
    case 'wed':
    case 'thu':
    case 'fri':
      return 'будний';
    default:
      return 'неизвестно';
  }
}

console.log(dayType('sun')); // выходной
console.log(dayType('wed')); // будний
console.log(dayType('xyz')); // неизвестно
```

Здесь `break` не нужен: `return` и так завершает функцию, а вместе с ней и `switch`. Это удобный приём: функция с `switch`, где каждая ветвь возвращает значение.

## Сравнение строгое

`switch` сравнивает значения так же, как `===`: без приведения типов.

```js
const value = '3';

switch (value) {
  case 3:
    console.log('число');
    break;
  case '3':
    console.log('строка'); // сработает эта ветвь
    break;
}
```

В браузере `prompt` всегда возвращает строку, поэтому `case 3` после `prompt` никогда не сработает, а `case '3'` сработает. Если на входе строка, а ветви числовые, приведите значение явно: `switch (Number(input))` или `switch (+input)`.

Следствия строгого сравнения, как у `===`:

- `NaN` не равно ничему, даже самому себе, поэтому `case NaN` никогда не совпадёт, и такое значение уйдёт в `default`;
- `0` и `-0` равны, `case 0` сработает для обоих;
- объекты сравниваются по ссылке: `case {}` не совпадёт ни с каким другим объектом.

```js
switch (NaN) {
  case NaN:
    console.log('NaN');
    break;
  default:
    console.log('default'); // default
}
```

## В switch и case допустимы любые выражения

Значения в `case` не обязаны быть литералами, это любые выражения. Они вычисляются лениво, по мере сравнения, до первого совпадения:

```js
const a = '1';
const b = 0;

switch (+a) {
  case b + 1:
    console.log('совпало: +a равно 1, b + 1 тоже 1');
    break;
  default:
    console.log('не совпало');
}
// совпало: +a равно 1, b + 1 тоже 1
```

На этом основан приём `switch (true)`: выражение в скобках — `true`, а в `case` стоят условия. Выполнится первая ветвь, условие которой строго равно `true`, то есть вернуло именно булево `true`:

```js
function grade(score) {
  switch (true) {
    case score >= 90:
      return 'A';
    case score >= 75:
      return 'B';
    case score >= 50:
      return 'C';
    default:
      return 'F';
  }
}

console.log(grade(95)); // A
console.log(grade(80)); // B
console.log(grade(10)); // F
```

Для диапазонов это читается не хуже цепочки `if`, но условие должно быть настоящим булевым значением: `case score && 1` (получится число) не совпадёт с `true`.

## default не обязан быть последним

`default` можно поставить в любое место. Он проверяется только после всех `case`, но если вход нашёлся в нём, провал идёт дальше вниз как обычно:

```js
function trace(n) {
  const out = [];
  switch (n) {
    case 1:
      out.push('один');
    default:
      out.push('другое');
    case 2:
      out.push('два');
  }
  return out.join(', ');
}

console.log(trace(1)); // один, другое, два
console.log(trace(2)); // два
console.log(trace(9)); // другое, два
```

Такой код запутывает, поэтому `default` по общему соглашению ставят последним.

## Область видимости: let внутри case

Всё тело `switch` — один общий блок. Объявление `let` или `const` напрямую в `case` принадлежит всему `switch`, а не одной ветви:

```js
const n = 2;
switch (n) {
  case 1:
    let x = 'один';
    break;
  case 2:
    console.log(x); // ReferenceError: Cannot access 'x' before initialization
}
```

Переменная `x` существует во второй ветви, но объявление `let x` не выполнялось (мы вошли мимо него), поэтому доступ к ней — ошибка. Два одинаковых `let x` в разных `case` вовсе дадут `SyntaxError: Identifier 'x' has already been declared`. Лечится фигурными скобками вокруг ветви:

```js
const n = 2;
switch (n) {
  case 1: {
    const x = 'один';
    console.log(x);
    break;
  }
  case 2: {
    const x = 'два';
    console.log(x); // два
    break;
  }
}
```

## switch внутри цикла

`break` внутри `switch` выходит только из `switch`, а не из цикла вокруг. А `continue` относится к циклу и сразу переходит к следующей итерации:

```js
const out = [];
for (let i = 0; i < 5; i++) {
  switch (i) {
    case 1:
      continue; // к следующей итерации цикла
    case 3:
      break; // выход из switch, цикл продолжается
    default:
      out.push(i);
  }
}
console.log(out); // [ 0, 2, 4 ]
```

## Типичные ошибки

> [!WARNING]
>
> - Забытый `break` — выполнение проваливается в следующую ветвь.
> - Сравнение строки с числом: `case 1` не совпадёт со значением `'1'`.
> - `case NaN` или `case {}` — такие ветви мертвы по правилам строгого равенства.
> - `let` или `const` без фигурных скобок в `case` — общая область видимости на весь `switch`.
> - `switch (true)` с условием, которое возвращает не булево значение.

## Когда выбрать if, а когда switch

`switch` хорош, когда одно значение сравнивается с набором конкретных вариантов. Если условия разнородные, зависят от разных переменных или проверяют диапазоны, понятнее обычный `if`. Если `switch` нужен только чтобы по ключу получить значение, часто проще объект-словарь или `Map`.

## Коротко

> [!TIP]
>
> - `switch` сравнивает выражение с `case` строго, как `===`, сверху вниз, и входит в первую совпавшую ветвь.
> - Без `break`, `return` или `throw` выполнение проваливается в следующие ветви, а их проверки пропускаются.
> - Несколько `case` подряд без кода между ними образуют группу с общим обработчиком.
> - `default` срабатывает, если совпадений нет; `case NaN` не совпадает никогда.
> - В `case` допустимы любые выражения, а `let` и `const` в ветви лучше оборачивать в `{ }`.
> - `break` в `switch` внутри цикла выходит только из `switch`.
