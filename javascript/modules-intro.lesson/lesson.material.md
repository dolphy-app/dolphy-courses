# Модули: введение

Пока программа умещается в один файл, всё просто. Когда файлов десятки, возникают вопросы: как не допустить конфликта имён, как явно указать, что от чего зависит, и как не выполнять один и тот же код дважды. Для этого в JavaScript есть **модули** — файлы, которые имеют собственную область видимости, явно объявляют, что отдают наружу, и явно подключают то, что им нужно.

## Что такое модуль

Модуль — это обычный файл со скриптом. Две ключевые директивы делают его частью системы зависимостей:

- `export` помечает переменные и функции, доступные снаружи;
- `import` подключает значения из другого модуля.

```js
// sayHi.mjs
export function sayHi(user) {
  return `Привет, ${user}!`;
}

// main.mjs
import { sayHi } from './sayHi.mjs';
console.log(sayHi('Аня')); // Привет, Аня!
```

Подробный синтаксис — в следующем уроке, здесь важнее **свойства модулей**: чем они отличаются от обычных скриптов.

Как включить режим модуля: в браузере — `<script type="module" src="main.js"></script>`; в Node.js — расширение `.mjs` либо `"type": "module"` в `package.json`. Без этого файл считается скриптом (в Node — CommonJS с `require`). Песочница заданий этого курса исполняет код как обычный скрипт, поэтому в задачах мы **имитируем** идеи модулей обычными функциями и замыканиями.

## Свойства модулей

### Своя область видимости

Верхнеуровневые `var`, `let`, `const`, `function` модуля **не становятся глобальными**. Чтобы значение увидели другие файлы, его надо экспортировать.

```js
// secret.mjs
var secret = 42;

// main.mjs
import './secret.mjs';
console.log(typeof secret); // undefined
```

В классическом скрипте в браузере `var` на верхнем уровне создал бы свойство `window`; модули эту «утечку» исключают.

### Строгий режим по умолчанию

Модуль всегда исполняется в strict mode, без директивы `'use strict'`. Присваивание необъявленной переменной — ошибка:

```js
try {
  undeclared = 1;
} catch (e) {
  console.log(e.constructor.name); // ReferenceError
}
```

(Запустите это в `.mjs`: в обычном скрипте переменная молча создалась бы глобальной.)

### `this` на верхнем уровне — `undefined`

В скрипте браузера `this` на верхнем уровне указывает на `window`; в модуле — `undefined`.

```js
console.log(this); // undefined (в ES-модуле)
```

Осторожно: в CommonJS-файле Node.js на верхнем уровне `this` — это `module.exports`, то есть `{}`. Это другая система модулей.

### Модуль выполняется один раз

Сколько бы файлов ни подключали модуль, его код исполнится **один раз** при первом импорте, а все остальные получают те же самые экспортированные значения.

```js
// counter.mjs
console.log('counter evaluated');
export let count = 0;
export function inc() { count++; }

// a.mjs
import { inc } from './counter.mjs';
// b.mjs
import { count } from './counter.mjs';
// main.mjs
import './a.mjs';
import './b.mjs';
// в консоль выведется 'counter evaluated' ровно один раз
```

Отсюда полезный приём: экспортируемый объект — **общий** для всех. Если один модуль изменил свойство такого объекта, другие увидят изменение. Модуль можно использовать как синглтон: настройки приложения, кеш, реестр.

### Импорты поднимаются

Как и объявления функций, `import` «всплывает»: все зависимости загружаются и выполняются до кода самого модуля, где бы строка импорта ни стояла.

```js
// t.mjs
console.log('t body');
import './h.mjs'; // в h.mjs: console.log('h first')
// выведет: h first, затем t body
```

Поэтому `import` допустим только на верхнем уровне — его нельзя поместить в `if` или функцию (для этого есть динамический `import()`, третий урок этой части).

### Живые привязки

Импортированное имя — не копия значения, а **ссылка на привязку** в исходном модуле. Если экспортёр изменит переменную, импортёр увидит новое значение. Но присвоить импортированному имени нельзя: оно только для чтения.

```js
import { count, inc } from './counter.mjs';
console.log(count); // 0
inc();
console.log(count); // 1
try {
  count = 5;
} catch (e) {
  console.log(e.constructor.name); // TypeError
}
```

### Верхнеуровневый `await`

В модуле `await` можно писать вне `async`-функции. Модуль, который «ждёт», задерживает исполнение зависящих от него модулей.

```js
const data = await Promise.resolve([1, 2, 3]);
console.log(data.length); // 3
```

Это удобно для инициализации (чтение конфигурации, подключение к БД), но замедляет старт: не злоупотребляйте.

### `import.meta`

Объект `import.meta` хранит сведения о текущем модуле. Всегда есть `import.meta.url` — адрес файла (в Node это строка вида `file:///…`). В Node 22 также есть `import.meta.filename` и `import.meta.dirname`.

```js
console.log(typeof import.meta); // object
console.log(import.meta.url.startsWith('file://')); // true (в Node)
```

Переменных `__filename`, `__dirname`, `require` и `module` в ES-модуле **нет**: `typeof require` даёт `'undefined'`.

### Циклические зависимости

Модули могут импортировать друг друга. Загрузчик не зацикливается: каждый модуль выполняется один раз, но порядок определяется обходом графа. Если модуль обращается к `const`/`let`-экспорту, который ещё не инициализирован, будет `ReferenceError` (зона временной «мёртвости»).

```js
// c1.mjs
import { b } from './c2.mjs';
export const a = 'A';
console.log('c1', b); // c1 B

// c2.mjs
import { a } from './c1.mjs';
export const b = 'B';
try { console.log(a); } catch (e) { console.log(e.constructor.name); } // ReferenceError
```

Запускаем `c1.mjs`: сначала выполняется `c2.mjs` (a ещё не создана — отсюда ошибка), потом `c1.mjs`. Лучшее лекарство — не создавать циклов, а вынести общее в третий модуль.

## Модули без `import`: паттерн замыкания

До появления модулей изоляцию делали функциями: переменные внутри функции приватны, наружу отдаётся объект с методами. Приём работает и сегодня, а в этом курсе — основа задач.

```js
function makeCounter(start) {
  let value = start; // приватно
  return {
    inc() { return ++value; },
    get() { return value; },
  };
}
const c = makeCounter(10);
c.inc();
console.log(c.get()); // 11
console.log(c.value); // undefined
```

## Типичные ошибки

- Ожидать, что `var` или функция верхнего уровня модуля попадёт в `globalThis`.
- Забыть, что модуль выполняется один раз, и надеяться «перезапустить» его повторным `import`.
- Писать `import` внутри `if` — это синтаксическая ошибка.
- Присваивать импортированному имени: `count = 5` — `TypeError`.
- Открыть страницу с модулем через `file://` в браузере: модули требуют HTTP (CORS).

## Коротко

- Модуль — файл со своей областью видимости; наружу идёт только то, что помечено `export`.
- Модули всегда в strict mode, `this` на верхнем уровне — `undefined`.
- Код модуля исполняется один раз, импорты поднимаются и выполняются раньше тела.
- Импорт — живая привязка только для чтения, а не копия значения.
- В модулях доступны верхнеуровневый `await` и `import.meta`.
- Замыкание — классический способ получить приватное состояние без модулей.
