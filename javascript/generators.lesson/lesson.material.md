# Генераторы

Обычная функция выполняется от начала до конца и возвращает одно значение. Генератор — функция, которую можно приостанавливать посреди тела, отдавать наружу очередное значение и возобновлять позже, с того же места. Это удобный способ описывать последовательности значений (в том числе бесконечные) и делать объекты перебираемыми без ручного написания итератора.

## Функция-генератор и объект-генератор

Функция-генератор объявляется через `function*`. Внутри неё доступен оператор `yield`:

```js
function* seq() {
  yield 1;
  yield 2;
  return 3;
}

const g = seq();
console.log(String(g)); // [object Generator]
```

Вызов `seq()` **не выполняет ни одной строки тела**. Он только создаёт объект-генератор. Тело начнёт работать, когда у генератора вызовут `next()`:

```js
function* seq() {
  yield 1;
  yield 2;
  return 3;
}

const g = seq();
console.log(g.next()); // { value: 1, done: false }
console.log(g.next()); // { value: 2, done: false }
console.log(g.next()); // { value: 3, done: true }
console.log(g.next()); // { value: undefined, done: true }
```

Каждый `next()` возобновляет тело до ближайшего `yield` (или `return`, или конца функции) и возвращает объект `{ value, done }`. Значение из `return` приходит с `done: true`. После завершения генератор «пуст»: все последующие вызовы `next()` возвращают `{ value: undefined, done: true }` и не бросают ошибок.

Выполнение действительно ленивое — код между `yield` работает только по запросу:

```js
function* logged() {
  console.log('start');
  yield 1;
}

const lz = logged();
console.log('created'); // created
lz.next();              // start
```

Несколько нюансов объявления:

- `function *f()` и `function* f()` — одно и то же; принято писать звёздочку у слова `function`;
- в объектах и классах есть краткая форма: `*method() {}` и `*[Symbol.iterator]() {}`;
- стрелочных генераторов не существует;
- генератор нельзя вызвать через `new`: `new seq()` даёт `TypeError: seq is not a constructor`.

## Генераторы — это итераторы

Объект-генератор сам является итератором и итерируемым объектом одновременно: его метод `[Symbol.iterator]()` возвращает его же самого. Поэтому генератор работает везде, где ждут итерируемое: `for..of`, `...`, `Array.from`, деструктуризация, `new Set(...)`, `Promise.all`.

```js
function* seq() {
  yield 1;
  yield 2;
  return 3;
}

console.log([...seq()]); // [ 1, 2 ]
for (const v of seq()) console.log(v); // 1, затем 2
```

Обратите внимание: `3` не попало ни в массив, ни в цикл. Конструкции, которые перебирают итератор, останавливаются, как только видят `done: true`, и значение этого последнего результата не используют. Если значение нужно в переборе — отдавайте его через `yield`, а не `return`.

Так как генератор — это один и тот же итератор, а не фабрика итераторов, пройти по нему дважды нельзя:

```js
function* seq() {
  yield 1;
  yield 2;
}

const g = seq();
console.log(g[Symbol.iterator]() === g); // true
console.log([...g], [...g]);             // [ 1, 2 ] []
```

Для повторного перебора нужно вызвать функцию-генератор заново. Именно поэтому `*[Symbol.iterator]()` в объекте работает правильно: каждый `for..of` вызывает метод и получает свежий генератор.

```js
const range = {
  from: 1,
  to: 4,
  *[Symbol.iterator]() {
    for (let v = this.from; v <= this.to; v++) yield v;
  },
};

console.log([...range], [...range]); // [ 1, 2, 3, 4 ] [ 1, 2, 3, 4 ]
```

Это та же задача, что в уроке про итерируемые объекты, но без ручного объекта `{ next() }` и без хранения состояния в полях: состояние живёт в локальных переменных функции.

## Бесконечные последовательности

Раз значения вычисляются по запросу, генератор может быть бесконечным. Важно, чтобы потребитель остановился сам:

```js
function* naturals() {
  let n = 1;
  while (true) yield n++;
}

function* take(iterable, count) {
  if (count <= 0) return;
  for (const v of iterable) {
    yield v;
    if (--count === 0) return;
  }
}

console.log([...take(naturals(), 4)]); // [ 1, 2, 3, 4 ]
const [a, b] = naturals();
console.log(a, b); // 1 2
```

Деструктуризация `[a, b]` берёт ровно два значения и закрывает итератор. Но `[...naturals()]` без ограничения повесит программу — расширение будет ждать конца, которого нет.

## Композиция: `yield*`

`yield* iterable` делегирует перебор другому итерируемому объекту: все его значения прозрачно отдаются наружу, как будто они сгенерированы текущим генератором. Промежуточный массив не создаётся.

```js
function* codes(from, to) {
  for (let c = from; c <= to; c++) yield c;
}

function* hexDigits() {
  yield* codes(48, 57);  // 0..9
  yield* codes(65, 70);  // A..F
}

console.log([...hexDigits()].map((c) => String.fromCharCode(c)).join('')); // 0123456789ABCDEF
```

`yield*` принимает любой итерируемый объект (массив, строку), а не только генератор. Само выражение `yield* inner()` имеет значение — это результат `return` вложенного генератора:

```js
function* inner() {
  yield 'a';
  return 'inner-result';
}

function* outer() {
  const r = yield* inner();
  yield r;
}

console.log([...outer()]); // [ 'a', 'inner-result' ]
```

Здесь видно ещё раз: `return` внутреннего генератора не попал в перебор сам по себе, но `outer` получил его как значение выражения и отдал уже через `yield`.

Удобное применение `yield*` — рекурсивный обход вложенных структур: дерево, вложенные массивы, каталоги. Рекурсивный вызов вместе с `yield*` превращается в одну строку.

## Двусторонний `yield`: `next(value)`

`yield` не только отдаёт значение наружу, но и сам является выражением. Аргумент, переданный в `next(value)`, становится его результатом:

```js
function* quiz() {
  const a = yield 'q1';
  const b = yield 'q2';
  return a + b;
}

const t = quiz();
console.log(t.next('ignored')); // { value: 'q1', done: false }
console.log(t.next(4));         // { value: 'q2', done: false }
console.log(t.next(9));         // { value: 13, done: true }
```

Правила «пинг-понга»:

1. Первый `next()` только запускает генератор и доходит до первого `yield`; его аргумент некуда подставить и он теряется.
2. Каждый следующий `next(x)` подставляет `x` вместо приостановленного `yield` и бежит до следующего `yield`.
3. Генератор может ждать сколько угодно — между вызовами внешний код делает что хочет (например, ждёт ответа от пользователя или сети).

## `throw()` и `return()`

Внешний код может не только отдать значение, но и бросить ошибку в точку `yield`: `gen.throw(err)`. Исключение возникнет на строке с приостановленным `yield`; если генератор его перехватит, он продолжит работу и вернёт следующий результат, а если нет — ошибка выйдет из `throw()` наружу, и генератор завершится:

```js
function* guarded() {
  try {
    yield 1;
  } catch (e) {
    console.log('caught', e.message); // caught boom
    yield 'recovered';
  }
}

const g = guarded();
g.next();
console.log(g.throw(new Error('boom'))); // { value: 'recovered', done: false }
```

Метод `gen.return(value)` досрочно завершает генератор: возвращает `{ value, done: true }`, а блоки `finally` внутри выполняются. Именно так срабатывает очистка, когда цикл `for..of` прерывают через `break`, `return` или исключение — итератору автоматически вызывается `return()`:

```js
function* resource() {
  try {
    yield 1;
    yield 2;
  } finally {
    console.log('cleanup');
  }
}

for (const v of resource()) {
  console.log(v); // 1
  break;          // cleanup
}
```

То же касается деструктуризации: `const [first] = resource()` возьмёт одно значение и закроет генератор.

## Типичные ошибки

> [!WARNING]
>
> - Ждать, что вызов функции-генератора что-то выполнит: без `next()` (или цикла) тело не стартует.
> - Использовать `return` как «ещё одно значение» для `for..of` и `...` — оно будет проигнорировано.
> - Перебирать один и тот же объект-генератор дважды: вторая итерация пуста.
> - Писать `yield` внутри обычной вложенной функции (колбэка `forEach`, стрелки): `yield` работает только непосредственно в теле `function*`. Для вложенного обхода используйте `for..of` или `yield*`.
> - Вызвать `next()` изнутри самого генератора, пока он работает: получите `TypeError: Generator is already running`.
> - Забыть про ограничитель при бесконечном генераторе.

## Коротко

> [!TIP]
>
> - `function*` создаёт генератор: вызов не выполняет тело, а `next()` исполняет его до очередного `yield`.
> - Результат `next()` — `{ value, done }`; значение из `return` приходит с `done: true` и не попадает в `for..of` и `...`.
> - Генератор — итератор и итерируемое одновременно, но одноразовый; повторный перебор требует нового вызова функции.
> - `yield*` делегирует другому итерируемому и возвращает его `return`-значение.
> - `next(value)` подставляет значение в приостановленный `yield`, `throw()` бросает ошибку в эту точку, `return()` завершает генератор с выполнением `finally`.
