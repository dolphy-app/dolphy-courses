# Устаревшее ключевое слово var

До появления `let` и `const` в 2015 году все переменные в JavaScript объявлялись через `var`. В современном коде `var` почти не нужен, но он встречается в старых проектах, библиотеках и вопросах на собеседованиях. Чтобы читать такой код и не наступать на грабли, нужно знать три особенности `var`: у него нет блочной области видимости, объявление «поднимается» (hoisting), а повторное объявление разрешено.

## Область видимости: функция, а не блок

`let` и `const` ограничены ближайшим блоком `{ ... }`. `var` игнорирует блоки `if`, `for`, `while` и видит только границы **функции** (или всего скрипта, если функции нет).

```js
if (true) {
  var a = 1;
}
console.log(a); // 1

for (var i = 0; i < 3; i++) {}
console.log(i); // 3
```

Переменная `i` «утекла» из цикла. С `let` такой код выдал бы `ReferenceError`. Внутри функции `var` остаётся локальным:

```js
function f() {
  if (false) {
    var z = 1;
  }
  return z; // переменная есть, но присваивание не выполнялось
}
console.log(f()); // undefined
```

## Повторное объявление

С `var` можно объявить одно и то же имя дважды в одной области. Второй `var` ничего нового не создаёт, лишь присваивает значение, если оно указано:

```js
var user = 'Аня';
var user = 'Боря';
console.log(user); // Боря
```

С `let` повторное объявление в том же блоке — `SyntaxError`. Это защита от случайных опечаток, которой у `var` нет.

## Hoisting: объявление поднимается

Все `var` внутри функции обрабатываются в самом начале её выполнения, где бы они ни стояли в тексте. Говорят, что объявления «поднимаются» к началу области. Но поднимается **только объявление**, присваивание остаётся на своём месте, поэтому до присваивания переменная равна `undefined`:

```js
console.log(x); // undefined
var x = 5;
console.log(x); // 5
```

Это эквивалентно тексту, в котором `var x;` стоит в начале, а `x = 5;` — на прежней строке. Из-за подъёма локальная `var` перекрывает внешнюю одноимённую переменную во всей функции, даже в строках выше объявления:

```js
var q = 1;
function r() {
  console.log(q); // undefined: локальная q уже существует
  var q = 2;
}
r();
```

Функции-**объявления** (`function name() {}`) поднимаются целиком и доступны с начала области, а вот функция-**выражение**, присвоенная `var`, — нет:

```js
console.log(typeof g); // function
function g() {}

try {
  hi();
} catch (e) {
  console.log(e.message); // hi is not a function
}
var hi = function () {};
```

Для `let`/`const` тоже есть «подъём» в смысле существования имени с начала блока, но до объявления действует временная мёртвая зона (TDZ), и обращение — `ReferenceError`, а не тихий `undefined`. Это намного безопаснее.

## Замыкания в цикле с var

Так как `var i` в цикле одна на всю функцию, все функции, созданные в теле, видят одну общую переменную. К моменту их вызова цикл давно завершён:

```js
const fns = [];
for (var i = 0; i < 3; i++) {
  fns.push(() => i);
}
console.log(fns.map((fn) => fn())); // [ 3, 3, 3 ]
```

Исправления: заменить `var` на `let` (новая `i` на каждой итерации) либо вынести тело в функцию, чтобы значение попало в её параметр. Этот же эффект ломает отложенные вызовы `setTimeout` в цикле.

## IIFE: самовызывающаяся функция

Раньше, чтобы получить отдельную область видимости, код оборачивали в функцию и сразу вызывали. Круглые скобки превращают объявление в выражение:

```js
(function () {
  var secret = 1; // видна только внутри
})();

console.log(typeof secret); // undefined
```

Такой приём называется IIFE (Immediately Invoked Function Expression). Он служил для создания «модулей» и защиты глобальных имён. Сегодня для этого есть блоки `{ let ... }` и ES-модули, но IIFE ещё полезна, например, чтобы выполнить `async`-код на верхнем уровне скрипта или скрыть приватное состояние.

## Типичные ошибки

- Ожидать блочной области: переменная `var` из `if` или `for` видна дальше.
- Читать переменную до присваивания и получать `undefined` вместо ошибки.
- Вызывать функцию, присвоенную через `var`, до строки присваивания: `TypeError`, а не работающая функция.
- Забыть `var`/`let`/`const` вовсе — это создаёт глобальную переменную (в строгом режиме — `ReferenceError`).

## Коротко

- `var` видит границы функции, но не блока; `let` и `const` — блочные.
- Объявление `var` поднимается к началу функции, присваивание остаётся на месте — до него значение `undefined`.
- Повторный `var` с тем же именем допустим; повторный `let` — ошибка.
- Функции-объявления поднимаются целиком, функции-выражения в `var` — нет.
- IIFE создаёт локальную область; в новом коде вместо `var` используйте `let`/`const`.
