# Конструктор и оператор new

Литерал `{...}` создаёт один объект. Когда нужно много однотипных объектов (пользователи, товары, пункты меню), писать литерал каждый раз неудобно. Для этого есть функции-конструкторы и оператор `new`. После урока вы поймёте, что именно происходит при `new`, как конструктор может вернуть чужой объект и как отличить вызов с `new` от обычного вызова.

## Функция-конструктор

Технически конструктор — обычная функция. Отличают его два соглашения:

1. имя начинается с заглавной буквы;
2. вызывать его принято только через `new`.

```js
function Product(title, price) {
  this.title = title;
  this.price = price;
  this.inStock = true;
}

const book = new Product("Книга", 450);
console.log(book.title);   // Книга
console.log(book.inStock); // true
console.log(book instanceof Product); // true
```

Вызов `new Product(...)` выполняет три шага:

1. создаётся новый пустой объект и становится значением `this`;
2. выполняется тело функции — обычно оно дописывает свойства в `this`;
3. результатом выражения становится `this`.

Иначе говоря, функция словно устроена так:

```js
function Product(title, price) {
  // this = {};  (неявно)
  this.title = title;
  this.price = price;
  // return this;  (неявно)
}
```

Каждый вызов `new` даёт новый независимый объект:

```js
function Counter() {
  this.count = 0;
}
const a = new Counter();
const b = new Counter();
a.count++;
console.log(a.count, b.count); // 1 0
console.log(a === b);          // false
```

Использовать как конструктор можно любую обычную функцию (`function`-объявление или выражение). Исключения — стрелочные функции и методы в сокращённой записи `{ m() {} }`: у них нет внутреннего механизма конструирования, и `new` на них бросает `TypeError`.

```js
const arrow = () => {};
try { new arrow(); } catch (e) { console.log(e.name); } // TypeError

const obj = { method() {} };
try { new obj.method(); } catch (e) { console.log(e.name); } // TypeError
```

## Забыли new

Если вызвать конструктор без `new`, он превратится в обычную функцию. Тогда `this` — не новый объект: в строгом режиме это `undefined`, в нестрогом — глобальный объект. В первом случае получите ошибку, во втором молча засорите глобальную область.

```js
"use strict";
function User(name) {
  this.name = name;
}
try {
  User("Ann");
} catch (e) {
  console.log(e.name); // TypeError (this равен undefined)
}
```

Внутри классов (тема появится позже) и модулей код всегда строгий, так что такая ошибка проявляется сразу.

## new.target

Внутри функции доступно специальное выражение `new.target`. При вызове через `new` оно равно самой функции, при обычном вызове — `undefined`.

```js
function Demo() {
  return new.target === undefined ? "обычный вызов" : "через new";
}
console.log(Demo());       // обычный вызов
console.log(typeof new Demo()); // object
```

Здесь `new Demo()` вернул объект, а не строку — об этом правиле ниже. А вот как `new.target` помогает сделать конструктор «терпимым» к пропущенному `new`:

```js
function Point(x, y) {
  if (!new.target) {
    return new Point(x, y);
  }
  this.x = x;
  this.y = y;
}
console.log(Point(1, 2).x);     // 1
console.log(new Point(3, 4).y); // 4
```

Библиотеки иногда так делают ради гибкого синтаксиса, но в прикладном коде лучше придерживаться правила «конструктор — только с `new`»: явное `new` сразу показывает читателю, что создаётся новый объект.

## return в конструкторе

Обычно конструктор ничего не возвращает. Но если `return` есть, действует простое правило:

- `return` с **объектом** — вместо `this` вернётся этот объект;
- `return` с **примитивом** (или пустой `return`) — значение игнорируется, вернётся `this`.

```js
function Big() {
  this.name = "this";
  return { name: "другой объект" };
}
function Small() {
  this.name = "this";
  return 42;
}
console.log(new Big().name);   // другой объект
console.log(new Small().name); // this
```

Массив и функция — тоже объекты, поэтому `return []` заменит результат на пустой массив. Это редко нужно, но позволяет, например, вернуть один и тот же заранее созданный объект при каждом вызове.

## Методы в конструкторе

В `this` можно записывать не только данные, но и функции:

```js
function Account(owner) {
  this.owner = owner;
  this.balance = 0;
  this.deposit = function (sum) {
    this.balance += sum;
    return this;
  };
}
const acc = new Account("Олег");
acc.deposit(100).deposit(50);
console.log(acc.balance); // 150
```

Минус подхода: каждый `new` создаёт новую копию функции. Позже вы узнаете про прототипы и классы — там методы хранятся один раз. А пока важно усвоить механику `new`.

## Скобки и new function

Если аргументов нет, скобки после имени можно опустить: `new Counter` равно `new Counter()`. Но так писать не стоит — это ухудшает читаемость.

Бывает приём `new function() { ... }`: конструктор создаётся и сразу вызывается. Так оформляют сложную одноразовую инициализацию объекта с локальными переменными, которые не должны «протекать» наружу:

```js
const settings = new function () {
  const base = 10;        // локальная переменная
  this.timeout = base * 2;
};
console.log(settings.timeout); // 20
```

## Типичные ошибки

- Вызов конструктора без `new`. В строгом режиме это `TypeError`, в нестрогом — запись свойств в глобальный объект.
- `new` для стрелочной функции — `TypeError`: используйте `function` или класс.
- Ожидание, что `return 5` в конструкторе что-то изменит. Примитив игнорируется.
- Запись в `this` чего-то лишнего: свойства попадут в каждый создаваемый объект.

## Коротко

- Конструктор — обычная функция с именем с заглавной буквы, вызываемая через `new`.
- `new` создаёт пустой `this`, выполняет тело и возвращает `this`.
- Если конструктор возвращает объект, результатом будет он; примитив игнорируется.
- `new.target` отличает вызов через `new` (функция) от обычного (`undefined`).
- Стрелочные функции и методы сокращённой записи конструкторами быть не могут.
