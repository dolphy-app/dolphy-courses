# Копирование объектов и ссылки

Главное отличие объектов от примитивов — способ хранения и копирования. Строки, числа и логические значения копируются «как есть». С объектами всё иначе, и непонимание этого — источник большинства «странных» багов у новичков: изменил одну переменную, а поменялась другая. Разберёмся, почему так происходит и как получить настоящую независимую копию.

## Примитивы копируются значением

```js
let message = 'Привет!';
let phrase = message;   // phrase получила свою копию строки
phrase += '?';

console.log(message); // Привет!
console.log(phrase);  // Привет!?
```

Две переменные — два независимых значения. Менять одну можно сколько угодно: вторая не заметит.

## Объекты копируются ссылкой

Переменная, которой присвоили объект, хранит не сам объект, а *ссылку* на него — по сути, его адрес в памяти. Образно: переменная — листок с адресом шкафчика, а не сам шкафчик. Читая `user.name`, движок идёт по адресу и смотрит в шкафчик.

Когда вы копируете такую переменную, копируется только листок с адресом:

```js
const user = { name: 'John' };
const admin = user;          // скопирована ссылка, объект один

admin.name = 'Pete';         // меняем через одну ссылку
console.log(user.name);      // Pete — видно через другую
```

Объект по-прежнему один, у него просто два «ключа». Не имеет значения, через какую переменную вы входите — вы попадаете в тот же шкафчик.

Так же ведёт себя передача объекта в функцию: параметр получает копию ссылки.

```js
function rename(o) {
  o.name = 'Новое';   // меняет объект снаружи
}

function replace(o) {
  o = { name: 'Другой' }; // переприсваивает только локальную переменную
}

const item = { name: 'Старое' };
replace(item);
console.log(item.name); // Старое
rename(item);
console.log(item.name); // Новое
```

Функция может изменить *содержимое* объекта, но не может заставить внешнюю переменную указывать на другой объект: присваивание параметру затрагивает лишь параметр.

## Сравнение по ссылке

Операторы `==` и `===` для объектов сравнивают ссылки: «равны» только те, что указывают на один и тот же объект.

```js
const a = {};
const b = a;     // та же ссылка
const c = {};    // новый, независимый объект

console.log(a === b); // true
console.log(a == b);  // true
console.log(a === c); // false — похожи, но это разные объекты
console.log([1] == [1]); // false — с массивами то же самое
```

Поэтому, чтобы сравнить содержимое, нужна своя функция (она обходит свойства) или готовая из библиотеки. Сравнения вида `obj1 > obj2` и `obj == 5` приводят объекты к примитивам; это редко нужно и чаще всего является ошибкой.

## Поверхностная копия

Чтобы получить независимый объект, нужно создать новый и перенести в него свойства. Вручную это цикл:

```js
const user = { name: 'John', age: 30 };
const clone = {};

for (const key in user) {
  clone[key] = user[key];
}

clone.name = 'Pete';
console.log(user.name); // John — оригинал не тронут
```

Встроенный способ — `Object.assign(dest, ...sources)`: он копирует собственные перечислимые свойства всех источников в `dest` по очереди и возвращает `dest`. Совпавшие имена перезаписываются — побеждает последний источник.

```js
const user = { name: 'John' };
const permissions1 = { canView: true };
const permissions2 = { canEdit: true };

const result = Object.assign(user, permissions1, permissions2);
console.log(user);           // { name: 'John', canView: true, canEdit: true }
console.log(result === user); // true — возвращён сам dest

const copy = Object.assign({}, { name: 'John' }, { name: 'Pete' });
console.log(copy);           // { name: 'Pete' }
```

Обратите внимание на первый аргумент: `Object.assign(user, ...)` *меняет* `user`, а `Object.assign({}, ...)` создаёт новый объект. Для копирования почти всегда нужен второй вариант.

Современная и более краткая запись — оператор расширения (spread):

```js
const base = { a: 1 };
const extended = { ...base, b: 2, a: 5 };
console.log(extended); // { a: 5, b: 2 }
```

Порядок важен и здесь: что записано позже, то перекрывает записанное раньше. Это удобный способ задавать значения по умолчанию: `{ ...defaults, ...options }`.

## Вложенные объекты

Копия, сделанная любым из способов выше, *поверхностная*. Примитивные свойства копируются значением, а свойства-объекты — ссылкой, поэтому у оригинала и копии они общие:

```js
const user = { name: 'John', sizes: { height: 182, width: 50 } };
const clone = Object.assign({}, user);

console.log(user.sizes === clone.sizes); // true — один и тот же вложенный объект

user.sizes.width++;
console.log(clone.sizes.width); // 51 — изменение видно в «независимой» копии
```

Для полной независимости нужно *глубокое клонирование*: функция, которая обходит значения и, встретив объект, копирует и его (рекурсивно). Варианты:

- `structuredClone(obj)` — встроенная функция, есть в Node.js начиная с 17-й версии и в современных браузерах. Не умеет копировать функции и бросает исключение, встретив их. В окружении заданий этого курса она недоступна, поэтому там клонирование пишут руками.
- `_.cloneDeep(obj)` из библиотеки lodash.
- Собственная рекурсивная функция для простых объектов и массивов.
- Трюк `JSON.parse(JSON.stringify(obj))` годится только для «чистых данных»: он теряет функции и `undefined`, превращает даты в строки и падает на циклических ссылках.

```js
const data = { d: new Date(0), f() {}, u: undefined, n: 1 };
console.log(JSON.stringify(data)); // {"d":"1970-01-01T00:00:00.000Z","n":1}
```

## Типичные ошибки

- Думать, что `const b = a` создаёт копию объекта.
- Использовать `Object.assign(a, b)` как «объединение без изменений»: он меняет `a`. Нужен `Object.assign({}, a, b)` или `{ ...a, ...b }`.
- Считать поверхностную копию полной: вложенные объекты остаются общими.
- Менять переданный в функцию объект, когда вызывающий этого не ожидает. Если функция должна вернуть новое значение, создайте копию и меняйте её.
- Хранить «значения по умолчанию» в общем объекте и менять его через `Object.assign(DEFAULTS, ...)`: после первого вызова значения по умолчанию испорчены.

## Коротко

- Переменная с объектом хранит ссылку; присваивание и передача в функцию копируют ссылку, а не объект.
- `==` и `===` для объектов сравнивают ссылки: два одинаковых по содержимому объекта не равны.
- Независимую поверхностную копию дают `Object.assign({}, obj)` и `{ ...obj }`.
- Вложенные объекты при поверхностном копировании остаются общими; для полной копии нужно глубокое клонирование.
- `const` не защищает содержимое объекта: запрещено лишь переприсвоить переменную.
