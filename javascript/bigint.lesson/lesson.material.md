# BigInt

Обычное число `number` — это 64-битная дробь, и целые в нём точны только до `2 ** 53 - 1`. Для идентификаторов из баз данных, криптографии, точных финансовых счётчиков в минимальных единицах и временных меток в наносекундах этого мало. Для таких случаев есть отдельный примитивный тип `BigInt` — целые числа произвольной длины.

## Зачем нужен BigInt

```js
console.log(Number.MAX_SAFE_INTEGER);       // 9007199254740991
console.log(Number.MAX_SAFE_INTEGER + 2);   // 9007199254740992
console.log(9007199254740991n + 2n);        // 9007199254740993n
console.log(2n ** 64n);                     // 18446744073709551616n
```

Первая строка с `+ 2` показывает проблему: ответ должен быть `…993`, но обычное число уже не различает соседние целые и округляет результат. У `BigInt` такого предела нет — только память.

## Создание значений

Литерал — число с суффиксом `n`. Также есть функция `BigInt(value)` (без `new`).

```js
const a = 123n;
const b = BigInt(456);
const c = BigInt('123456789012345678901234567890');
const d = BigInt('0x1f');
console.log(typeof a, b, c, d); // bigint 456n 123456789012345678901234567890n 31n
```

`BigInt` принимает только целые. Дробь или строка не из целого числа вызывают ошибку:

```js
try { BigInt(1.5); } catch (e) { console.log(e.constructor.name); }    // RangeError
try { BigInt('1.5'); } catch (e) { console.log(e.constructor.name); }  // SyntaxError
```

Осторожно с большими числовыми литералами: `BigInt(2 ** 53 + 1)` создаёт значение уже **после** потери точности. Большие числа записывайте сразу литералом `…n` или строкой.

## Арифметика

Поддерживаются `+ - * / % **`, унарный минус и инкременты. Деление целочисленное — дробная часть отбрасывается (усечение к нулю), а знак остатка совпадает со знаком делимого:

```js
console.log(5n / 2n);   // 2n
console.log(-5n / 2n);  // -2n
console.log(-5n % 2n);  // -1n
console.log(2n ** 100n); // 1267650600228229401496703205376n
try { 5n / 0n; } catch (e) { console.log(e.constructor.name); } // RangeError
```

**Смешивать `BigInt` и `number` в арифметике нельзя** — будет `TypeError`. Язык сознательно требует явного преобразования, потому что любое неявное привело бы к потере точности или дроби:

```js
try { 1n + 1; } catch (e) { console.log(e.constructor.name); } // TypeError
console.log(1n + BigInt(1)); // 2n
console.log(Number(2n ** 53n) + 1); // 9007199254740992
```

Унарный плюс тоже не работает: `+1n` — `TypeError`. Чтобы превратить в число, используйте `Number(x)`, но помните: для больших значений это потеря точности. Встроенные функции `Math.*` не принимают `BigInt` (`Math.max(1n)` — `TypeError`), `parseInt('12n')` вернёт `12`, а `Number.isInteger(5n)` — `false`.

## Сравнение и приведение типов

Сравнения смешанных типов работают корректно, потому что сравнивается математическое значение:

```js
console.log(2n > 1, 1n < 2, 1n < 1.5); // true true true
console.log(1n == 1, 1n === 1);        // true false
console.log(typeof 1n);                // bigint
console.log([3n, 1, 2n, 0].sort((x, y) => (x < y ? -1 : x > y ? 1 : 0))); // [ 0, 1, 2n, 3n ]
```

Строгое равенство `===` учитывает тип, поэтому `1n === 1` ложно, а нестрогое `==` сравнивает значения. В сортировке не вычитайте элементы друг из друга: `x - y` для смеси типов бросит `TypeError`, а результат для двух `BigInt` — не число.

В логическом контексте `0n` ложно, остальные значения истинны, как и у чисел:

```js
console.log(Boolean(0n), !!1n, 0n || 5); // false true 5
```

В строку `BigInt` превращается без суффикса `n`: `String(10n)` — `'10'`, ``${7n}`` — `'7'`, а `(255n).toString(16)` — `'ff'`. Консоль Node показывает суффикс `n` только при выводе самого значения.

## Побитовые операции и ограничение разрядности

У `BigInt` есть `& | ^ ~ << >>` — но **без** `>>>` (беззнаковый сдвиг не имеет смысла для бесконечной длины). Они работают с «бесконечным» дополнительным кодом, а не с 32 битами.

```js
console.log(7n & 3n, 7n | 8n, 5n ^ 1n, ~5n); // 3n 15n 4n -6n
console.log(5n << 3n, -5n >> 1n);            // 40n -3n
try { 5n >>> 1n; } catch (e) { console.log(e.constructor.name); } // TypeError
console.log(BigInt.asUintN(8, 257n));  // 1n
console.log(BigInt.asIntN(8, 255n));   // -1n
console.log(BigInt.asUintN(64, -1n));  // 18446744073709551615n
```

`BigInt.asUintN(bits, x)` и `BigInt.asIntN(bits, x)` обрезают значение до заданной разрядности — так эмулируют 64-битную арифметику.

## JSON и вывод

`JSON.stringify` не умеет сериализовать `BigInt`:

```js
try { JSON.stringify({ a: 1n }); } catch (e) { console.log(e.constructor.name); } // TypeError
console.log(JSON.stringify({ a: 1n }, (key, value) => (typeof value === 'bigint' ? String(value) : value))); // {"a":"1"}
console.log((1234567n).toLocaleString('en-US')); // 1,234,567
```

Обычно такие значения передают строками. Через `JSON.parse` в `BigInt` они сами не превратятся: большие числа в JSON будут округлены до `number` ещё при чтении.

## Типичные ошибки

> [!WARNING]
>
> - **Смесь типов:** `value + 1`, где `value` — `BigInt`. Пишите `value + 1n`.
> - **Конструктор из большого `number`:** точность уже потеряна, используйте строку или литерал.
> - **`Math` и `JSON`:** для `BigInt` они не работают без ручной обработки.
> - **Ожидание дробей:** `5n / 2n` — `2n`, а не `2.5`.
> - **`new BigInt(1)`:** `BigInt` — не конструктор, будет `TypeError`.
> - **Производительность:** операции с `BigInt` медленнее, чем с `number`; не применяйте его там, где хватает безопасных целых.

## Коротко

> [!TIP]
>
> - `BigInt` — отдельный примитив для целых произвольного размера; литерал `123n`, функция `BigInt(x)`.
> - Деление целочисленное, арифметика со смешением `BigInt` и `number` запрещена (`TypeError`).
> - Сравнения `<`, `>`, `==` между типами работают, `===` — нет.
> - Нет `>>>`, нет `Math.*`, `JSON.stringify` требует ручной обработки.
> - Большие значения создавайте из строк и литералов, а не из `number`.
