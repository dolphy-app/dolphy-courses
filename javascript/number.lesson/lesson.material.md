# Числа

Все числа в JavaScript — один тип `number`: целые и дробные хранятся одинаково, в 64-битном формате с плавающей точкой. Это удобно, но порождает знаменитые странности вроде `0.1 + 0.2 !== 0.3`. После урока вы сможете записывать числа разными способами, округлять их, переводить из строк и не попадаться на неточности вычислений.

## Как записывать числа

Помимо обычной записи есть краткая «научная» форма и другие системы счисления:

```js
console.log(1e3); // 1000 — «1, умноженное на 10 в степени 3»
console.log(1.5e-3); // 0.0015
console.log(0xff); // 255 — шестнадцатеричная запись
console.log(0b101); // 5 — двоичная
console.log(0o17); // 15 — восьмеричная
console.log(1_000_000); // 1000000 — разделитель _ для читаемости
```

Разделитель `_` существует только в исходном тексте — на значение он не влияет.

Обратная операция — метод `toString(base)`, который выводит число в системе счисления от 2 до 36. Для обратного перевода строки используйте `parseInt(str, base)`:

```js
console.log((255).toString(16)); // ff
console.log((255).toString(2)); // 11111111
console.log(parseInt('ff', 16)); // 255
```

## Округление

Для округления есть четыре функции объекта `Math`. Различие заметно на отрицательных числах:

| Функция | 3.7 | -1.5 | Что делает |
|---|---|---|---|
| `Math.floor` | 3 | -2 | вниз, к меньшему |
| `Math.ceil` | 4 | -1 | вверх, к большему |
| `Math.round` | 4 | -1 | к ближайшему; ровно половина — вверх |
| `Math.trunc` | 3 | -1 | отбрасывает дробную часть |

```js
console.log(Math.round(2.5)); // 3
console.log(Math.round(-2.5)); // -2 — половина уходит в сторону +∞
```

Если нужно округлить до заданного числа знаков, есть `toFixed(digits)`. Он возвращает **строку**, и это частая причина багов:

```js
const x = 12.36;
console.log(x.toFixed(1)); // 12.4
console.log(typeof x.toFixed(1)); // string
console.log((1.2).toFixed(1) + 1); // 1.21 — склеились строки
console.log(+(1.2).toFixed(3)); // 1.2 — унарный плюс вернул число
console.log((5).toFixed(2)); // 5.00 — дополняет нулями
```

Ещё один способ — умножить, округлить через `Math.round` и разделить обратно, но он страдает от тех же неточностей, что описаны ниже.

## Неточные вычисления

Числа хранятся в двоичном виде, а многие десятичные дроби (0.1, 0.2) в двоичной системе бесконечны, как 1/3 в десятичной. Их приходится обрезать, и ошибка накапливается:

```js
console.log(0.1 + 0.2); // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3); // false
console.log((0.1 + 0.2).toFixed(2)); // 0.30
console.log((1.005).toFixed(2)); // 1.00 — 1.005 хранится как 1.00499999…
```

Это свойство формата, а не JavaScript: так же ведут себя Python, Java и другие языки. Практические правила:

- для сравнения дробей используйте допуск: `Math.abs(a - b) < 1e-9`;
- деньги удобно хранить целым числом копеек или центов;
- целые числа точны только до `Number.MAX_SAFE_INTEGER` (`9007199254740991`); дальше точность теряется: `2 ** 53 === 2 ** 53 + 1` — это `true`. Для огромных целых есть тип `BigInt`.

## Бесконечность и NaN

Деление на ноль не ошибка: `1 / 0` даёт `Infinity`, `-1 / 0` — `-Infinity`. Бессмысленная операция даёт `NaN` («не число»), например `0 / 0` или `Number('abc')`. У `NaN` необычное свойство: он не равен ничему, даже себе, а любая операция с ним снова даёт `NaN`.

Проверки:

```js
console.log(NaN === NaN); // false
console.log(isNaN('abc')); // true — глобальная функция сначала приводит к числу
console.log(Number.isNaN('abc')); // false — строгая проверка: только значение NaN
console.log(isFinite('15')); // true
console.log(Number.isFinite('15')); // false — строка не число
console.log(Number.isInteger(5.0)); // true
console.log(Number.isInteger(5.1)); // false
```

Предпочитайте `Number.isNaN`, `Number.isFinite` и `Number.isInteger`: они не приводят тип и не дают сюрпризов.

## Из строки в число: Number и parseInt

`Number(str)` и унарный плюс требуют, чтобы вся строка была числом (пробелы по краям допускаются). Пустая строка превращается в 0:

```js
console.log(Number(' 12 ')); // 12
console.log(Number('12px')); // NaN
console.log(Number('')); // 0
console.log(+'1e3'); // 1000
```

`parseInt` и `parseFloat` читают число с начала строки и останавливаются на первом неподходящем символе — удобно для значений вроде `'100px'`:

```js
console.log(parseInt('100px')); // 100
console.log(parseFloat('12.5em')); // 12.5
console.log(parseInt('12.9')); // 12 — дробная часть отброшена
console.log(parseInt('a12')); // NaN — начало строки не число
console.log(parseInt('')); // NaN, в отличие от Number('')
```

## Другие функции Math

`Math.max(...)` и `Math.min(...)` принимают любое число аргументов; `Math.pow(a, b)` равно `a ** b`; есть `Math.sqrt`, `Math.abs`, `Math.hypot`, `Math.sign`. Случайное число из диапазона от 0 (включительно) до 1 (не включая) даёт `Math.random()`. Чтобы получить целое из диапазона `min..max` включительно, нужно растянуть диапазон на `max - min + 1` и округлить вниз: `Math.floor(min + Math.random() * (max - min + 1))`. Округление через `Math.round` здесь даёт перекос: крайние значения выпадают вдвое реже.

## Типичные ошибки

> [!WARNING]
>
> - Складывать строки из ввода: `'1' + '2'` даёт `'12'`, сначала приведите их к числам.
> - Сравнивать дроби через `===`.
> - Использовать `toFixed` и забывать, что результат — строка.
> - Проверять `x === NaN` вместо `Number.isNaN(x)`.
> - Писать `isNaN('')` и ждать `true`: пустая строка приводится к 0, поэтому `false`.

## Коротко

> [!TIP]
>
> - Числа — 64-битные дроби; дробные результаты бывают неточными, сравнивайте с допуском.
> - `Math.floor`, `ceil`, `round`, `trunc` по-разному округляют отрицательные числа; `toFixed` возвращает строку.
> - `NaN !== NaN`; используйте `Number.isNaN`, `Number.isFinite`, `Number.isInteger`.
> - `Number(str)` строгий, `parseInt` и `parseFloat` читают число с начала строки.
> - Для случайного целого в диапазоне `min..max`: `Math.floor(min + Math.random() * (max - min + 1))`.
