# Побитовые операторы

Побитовые операторы работают с числами как с последовательностью битов — нулей и единиц. В повседневном коде они встречаются нечасто, но без них не обойтись в флагах доступа, масках, упаковке цветов, хешах, бинарных протоколах и в старых приёмах оптимизации. Полезно знать и то, как они ведут себя на «неожиданных» входах: дробях, отрицательных и больших числах.

## Как JavaScript считает биты

Обычные числа в JS — 64-битные дроби (`number`). Но все побитовые операторы (кроме операций над `BigInt`) сначала приводят операнды к **32-битному целому со знаком**, выполняют операцию и возвращают обычное число. Отрицательные числа хранятся в дополнительном коде (two's complement): `-1` — это 32 единицы подряд.

```js
console.log((5).toString(2));              // 101
console.log((5).toString(2).padStart(8, '0')); // 00000101
console.log(parseInt('1010', 2));          // 10
console.log(0b101, 0o17, 0xff);            // 5 15 255
console.log((-5 >>> 0).toString(2));       // 11111111111111111111111111111011
```

Литералы `0b…` (двоичные), `0o…` (восьмеричные) и `0x…` (шестнадцатеричные) удобны при работе с масками.

## Список операторов

| Оператор | Название | Действие |
|---|---|---|
| `a & b` | И (AND) | бит равен 1, если он 1 в обоих операндах |
| `a \| b` | ИЛИ (OR) | бит равен 1, если он 1 хотя бы в одном |
| `a ^ b` | исключающее ИЛИ (XOR) | бит равен 1, если биты различаются |
| `~a` | НЕ (NOT) | инвертирует все 32 бита |
| `a << n` | сдвиг влево | сдвигает биты влево, справа нули |
| `a >> n` | сдвиг вправо со знаком | сохраняет знаковый бит |
| `a >>> n` | сдвиг вправо без знака | слева всегда нули |

```js
console.log(6 & 3, 6 | 3, 6 ^ 3); // 2 7 5
// 110 & 011 = 010,  110 | 011 = 111,  110 ^ 011 = 101
console.log(~5);                   // -6
console.log(1 << 3);               // 8
console.log(-16 >> 2);             // -4
console.log(-16 >>> 2);            // 1073741820
console.log(-1 >>> 0);             // 4294967295
```

Запомнить `~`: для любого целого `~x` равно `-(x + 1)`. Поэтому `~-1` равно `0`, а `~0` равно `-1`.

Разница между `>>` и `>>>` видна только на отрицательных числах. `>>` копирует знаковый бит слева (поэтому знак сохраняется, это деление на степень двойки с округлением вниз), `>>>` подставляет нули и превращает результат в **беззнаковое** число от 0 до 4294967295. Приём `x >>> 0` — стандартный способ получить беззнаковое 32-битное представление.

## Размер сдвига берётся по модулю 32

Количество бит сдвига тоже сводится к диапазону 0–31 (берутся младшие 5 бит). Поэтому сдвиг на 32 ничего не делает, а не обнуляет число:

```js
console.log(1 << 31);  // -2147483648
console.log(1 << 32);  // 1
console.log(1 << 33);  // 2
```

Сдвиг `1 << 31` попадает в знаковый бит, потому результат отрицательный. Если нужно положительное значение, используйте `(1 << 31) >>> 0`, это даст `2147483648`.

## Что происходит с дробями и большими числами

Приведение к int32 отбрасывает дробную часть (обрезка к нулю, не округление вниз) и берёт остаток по модулю 2³². Всё, что не число или не конечно, превращается в 0.

```js
console.log(3.7 | 0, -3.7 | 0);        // 3 -3
console.log(~~7.9, ~~-7.9);            // 7 -7
console.log(2 ** 31 | 0);              // -2147483648
console.log(2 ** 32 | 0);              // 0
console.log((2 ** 32 + 5) | 0);        // 5
console.log(NaN | 0, Infinity | 0);    // 0 0
console.log(null | 0, undefined | 0);  // 0 0
console.log('7' | 0, ~'abc');          // 7 -1
```

Отсюда популярные трюки: `x | 0` и `~~x` — «усечь дробь». Они короче `Math.trunc`, но работают только в диапазоне int32: для `2 ** 31` и больше вы получите мусор. В современном коде лучше `Math.trunc`, а побитовое усечение оставить для горячих участков, где это оправдано измерениями.

## Маски и флаги

Главное практическое применение — хранить несколько булевых признаков в одном числе: каждому признаку отдаётся свой бит.

```js
const READ = 1;   // 001
const WRITE = 2;  // 010
const EXEC = 4;   // 100

let mode = READ | WRITE;            // установить
console.log(mode);                  // 3
console.log((mode & WRITE) !== 0);  // true  — проверить
console.log((mode & EXEC) !== 0);   // false
mode = mode & ~WRITE;               // снять
console.log(mode);                  // 1
mode = mode ^ READ;                 // переключить
console.log(mode);                  // 0
```

Схема: **установить** — `|`, **снять** — `& ~mask`, **переключить** — `^`, **проверить** — `&` с последующим сравнением. Сравнивайте результат `&` с `0` или с самой маской, а не просто приводите к булевому: для составной маски `READ | WRITE` нужно проверять `(mode & m) === m`, если требуются оба бита.

## Полезные приёмы

```js
console.log(13 & 1);          // 1 — число нечётное
console.log(12 & 1);          // 0 — чётное
console.log(8 & (8 - 1));     // 0 — 8 степень двойки
console.log(6 & (6 - 1));     // 4 — 6 нет
console.log(12 & -12);        // 4 — младший установленный бит
console.log(0b1010 ^ 0b0110); // 12
```

Проверка «степень двойки»: у такого числа ровно один бит, и `n & (n - 1)` обнуляет самый младший из установленных, так что остаётся 0. Для `0` выражение тоже даёт 0, поэтому нужна отдельная проверка `n > 0`.

Упаковка цвета: три канала по 8 бит собираются сдвигами и извлекаются обратно сдвигом и маской `0xff`.

```js
const color = (255 << 16) | (128 << 8) | 7;
console.log(color.toString(16));   // ff8007
console.log((color >> 16) & 0xff); // 255
console.log(color & 0xff);         // 7
```

Обмен значений через XOR (`a ^= b; b ^= a; a ^= b`) работает для int32, но читается хуже деструктуризации `[a, b] = [b, a]` и ничего не выигрывает.

## Типичные ошибки

- **Приоритет операторов.** У `==` приоритет выше, чем у `&`, `^` и `|`, поэтому `5 & 3 == 3` — это `5 & (3 == 3)`, то есть `5 & true`, то есть `1`. Оборачивайте побитовые подвыражения в скобки. А арифметика выше сдвигов: `1 << 2 + 1` равно `1 << 3`, то есть 8.
- **Путаница `&` и `&&`.** Первый работает с битами и не делает ленивых вычислений.
- **Числа больше 2³¹.** Побитовые операции их молча искажают. Для больших значений используйте `BigInt` (у него свои побитовые операторы, кроме `>>>`).
- **Знаковый результат.** `0xFFFFFFFF | 0` — это `-1`; добавляйте `>>> 0`, если нужно беззнаковое значение.
- **Магия вместо ясности.** `~arr.indexOf(x)` вместо `arr.indexOf(x) !== -1` экономит символы, но запутывает читателя: используйте `includes`.

## Коротко

- Побитовые операторы приводят операнды к int32; результат — обычное `number`.
- `>>` сохраняет знак, `>>>` даёт беззнаковый результат; величина сдвига берётся по модулю 32.
- `x | 0`, `~~x` отбрасывают дробь, но ломаются за пределами int32.
- Флаги: `|` устанавливает, `& ~mask` снимает, `^` переключает, `&` проверяет.
- Следите за приоритетом: заключайте побитовые выражения в скобки.
