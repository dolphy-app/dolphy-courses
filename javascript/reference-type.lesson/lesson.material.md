# Ссылочный тип

Почему `user.hi()` работает, а `(user.hi = user.hi)()` — уже нет, хотя «значение то же самое»? Ответ — в «ссылочном типе» (Reference Type): внутреннем типе спецификации языка. Он не виден в коде напрямую, но объясняет, как именно определяется `this` при вызове метода. Тема нужна, чтобы понимать, почему `this` иногда «теряется», и не гадать, а предсказывать поведение.

> Ссылочный тип — механизм спецификации. Вы не можете создать значение такого типа или проверить его через `typeof`. Он существует только в момент вычисления выражения.

## Пример, который ломается

В примерах ниже метод возвращает результат сравнения `this === user`, чтобы было видно, получил ли он нужный контекст.

```js
const user = {
  name: 'Ann',
  hi() { return this === user; },
  bye() { return this === user; },
};

console.log(user.hi()); // true

// вызов метода в скобках
console.log((user.hi)()); // true

// присваивание в скобках
console.log((user.hi = user.hi)()); // false

// выбор через тернарный оператор
console.log((user.name ? user.hi : user.bye)()); // false
```

Все четыре выражения вызывают «один и тот же» метод. Но `this` получает только тот вызов, где точка (или квадратные скобки) стоит непосредственно перед скобками вызова. Остальные дают `false`: контекст потерян (в нестрогом режиме `this` — глобальный объект, в строгом — `undefined`).

## Как устроено: тройка (base, name, strict)

Когда движок вычисляет выражение `user.hi`, результатом будет не функция, а значение ссылочного типа — тройка:

- `base` — объект, у которого ищем свойство (`user`);
- `name` — имя свойства (`'hi'`);
- `strict` — признак строгого режима.

Дальше работают два правила:

1. Если сразу после ссылки идут скобки `()`, движок читает свойство и вызывает функцию, передавая `base` в качестве `this`. Поэтому `user.hi()` получает `this === user`.
2. Если над ссылкой выполняется **любая другая операция**, ссылка «разворачивается» в обычное значение — функцию. Информация о `base` теряется, остаётся только значение.

Круглые скобки — это просто группировка, они ссылку не разворачивают, поэтому `(user.hi)()` работает как `user.hi()`.

Что разворачивает ссылку:

- присваивание `=` (результат присваивания — значение);
- оператор «запятая» `(0, user.hi)()`;
- логические операторы `||`, `&&`, `??`;
- тернарный оператор `?:`;
- присвоение функции в переменную `const f = user.hi`.

```js
const user = { hi() { return this === user; } };

const f = user.hi;
console.log(f()); // false
console.log((0, user.hi)()); // false
console.log((false || user.hi)()); // false
console.log([user.hi][0]()); // false
```

В последней строке точка вообще не участвует: `[user.hi]` — массив, и `[0]` читает элемент из него. Базой для вызова становится массив, а не `user`.

## Квадратные скобки и вложенность

Квадратные скобки тоже дают ссылку: `user['hi']()` и `user[key]()` передают `this` так же, как точка. Для цепочек важен только **последний** объект перед вызовом.

```js
const user = { hi() { return this === user; } };
const key = 'hi';
console.log(user['hi']()); // true
console.log(user[key]()); // true

const outer = { inner: { hi() { return this === outer.inner; } } };
console.log(outer.inner.hi()); // true: this — outer.inner, не outer
```

## Опциональная цепочка

Вызов через `?.` контекст сохраняет, потому что вся цепочка вычисляется как одна ссылка:

```js
const user = { hi() { return this === user; } };
console.log(user?.hi()); // true
console.log(user.hi?.()); // true
```

## Как вернуть контекст

Если функцию нужно передать «отдельно» (в обработчик, в `setTimeout`, в `map`), контекст приходится привязать явно:

```js
const user = {
  name: 'Ann',
  hi() { return this === user; },
};

const bound = user.hi.bind(user);
console.log(bound()); // true

const wrapped = () => user.hi();
console.log(wrapped()); // true

console.log(user.hi.call(user)); // true
```

`bind` создаёт новую функцию с фиксированным `this`, стрелочная обёртка вызывает метод «через точку» внутри, а `call` и `apply` передают `this` явно. Что выбрать — зависит от ситуации: `bind` подходит, когда функцию передают дальше; обёртка — когда нужны ещё и другие действия.

## Почему это важно на практике

Типичный источник ошибок — передача метода как колбэка:

```js
const counter = {
  count: 0,
  inc() { this.count++; return this.count; },
};

const inc = counter.inc;
try {
  inc();
} catch (e) {
  console.log('ошибка');
}
console.log(counter.count); // 0
```

В нестрогом режиме Node `this` здесь — глобальный объект, и `inc` молча увеличивает `globalThis.count` вместо `counter.count`; в строгом режиме (или внутри класса и модуля) `this` был бы `undefined`, и вызов выбросил бы `TypeError`. В обоих случаях `counter.count` остаётся нулём.

## Типичные ошибки

> [!WARNING]
>
> - **Считать, что `this` определяется местом объявления функции.** Для обычных функций он определяется способом вызова, и ссылочный тип — механизм, который это реализует.
> - **Думать, что скобки `(obj.method)()` ломают контекст.** Они только группируют; контекст сохраняется.
> - **Забывать про `||`, `?:`, `,` и присваивание.** Любая из этих операций превращает ссылку в обычное значение.
> - **Вызывать через массив или другой контейнер.** `[obj.method][0]()` даёт `this`, равный массиву.
> - **Ждать такого поведения от стрелочных функций.** У них нет собственного `this`, и ссылочный тип на него не влияет: берётся `this` внешней области.

## Коротко

> [!TIP]
>
> - `obj.method` и `obj['method']` дают внутреннюю ссылку `(base, name, strict)`, а не просто функцию.
> - Если сразу следует вызов `()`, `base` становится `this`; любая другая операция превращает ссылку в обычное значение.
> - Скобки группировки ссылку не разворачивают: `(obj.method)()` работает как `obj.method()`.
> - Присваивание, `,`, `||`, `?:`, сохранение в переменную и чтение из массива теряют `this`.
> - Для явной привязки используйте `bind`, `call`, `apply` или стрелочную обёртку.
