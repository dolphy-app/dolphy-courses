# Отладка

Рано или поздно код начинает вести себя не так, как вы задумали. Отладка — это поиск причины такого поведения и её исправление. Для этого есть два основных приёма: остановить программу и осмотреться в отладчике либо оставить в коде «следы» в виде вывода в консоль. После урока вы поймёте, что умеет отладчик, как им управлять по шагам и когда достаточно обычного логирования.

## Что даёт отладчик

Отладчик — это часть среды выполнения: браузера (вкладка Sources в DevTools), Node.js, редактора вроде VS Code. Он умеет главное: **приостановить программу в нужный момент**. В паузе код «замирает», и вы можете:

- посмотреть значения всех доступных переменных;
- вычислить любое выражение в консоли в контексте текущей строки;
- увидеть цепочку вызовов, которая привела к этой точке;
- выполнять код по одной инструкции и следить, как меняется состояние.

Без отладчика приходится гадать, что происходит между строками; с ним — смотреть.

В браузере откройте DevTools (`F12`, на Mac — `Cmd+Opt+I`) и перейдите на вкладку Sources. Слева — навигатор по файлам страницы, в центре — редактор исходного кода, справа — панель отладки. Консоль можно вызвать в любой вкладке клавишей `Esc`. В Node.js отладчик подключается иначе: `node --inspect-brk app.js` запускает программу и ждёт подключения (например, через `chrome://inspect` или встроенный отладчик VS Code), а `node inspect app.js` даёт консольный отладчик без графики.

## Как остановить выполнение

Есть три способа приостановить скрипт.

**1. Точка останова (breakpoint).** Щёлкните по номеру строки в редакторе кода: отладчик остановится перед выполнением этой строки. Точки собираются в списке справа, их можно временно отключать или удалять. Через правый щелчок по номеру строки создаётся *условная* точка останова: она срабатывает, только если выражение истинно. Это спасает в цикле на тысячу итераций, когда ошибка проявляется, скажем, при `i === 742`: останавливаться на каждом проходе было бы мучением.

**2. Оператор `debugger`.** Это обычная инструкция языка — «точка останова, записанная в коде»:

```js
function double(a) {
  debugger; // здесь отладчик остановится, если он подключён
  return a * 2;
}

console.log(double(2)); // 4
```

Если отладчик не подключён (инструменты разработчика закрыты, программа запущена обычным `node app.js`), инструкция ничего не делает, и код просто работает дальше. Перед отправкой кода в продакшен такие строки удаляют.

**3. Пауза при ошибке.** В DevTools есть режим «Pause on exceptions»: как только возникает необработанное исключение, выполнение останавливается прямо в месте броска. Откройте отладчик, включите режим и перезапустите страницу — увидите не только сообщение об ошибке, но и все значения на момент падения.

## Что показывает панель отладки

В паузе важны три раздела.

- **Watch** — список ваших выражений (`list.length`, `total / count`). Их значения пересчитываются на каждом шаге.
- **Call Stack** — цепочка вложенных вызовов. Верхний элемент — функция, внутри которой мы стоим сейчас; ниже — та, что её вызвала, и так до самого начала. Щелчок по элементу стека показывает код вызывающей функции вместе с её переменными.
- **Scope** — переменные: локальные (Local), из внешних функций (Closure) и глобальные (Global). В Local видно и значение `this`.

Стек можно увидеть и без отладчика: у объекта ошибки есть свойство `stack`. Вот как выглядит стек из трёх вложенных вызовов (показаны только имена функций, самая внутренняя — первая):

```js
function c() {
  return new Error().stack.split('\n').slice(1, 4).map((line) => line.trim().split(' ')[1]);
}
function b() {
  return c();
}
function a() {
  return b();
}
console.log(a()); // [ 'c', 'b', 'a' ]
```

## Пошаговое выполнение

Когда программа на паузе, управлять ею помогают кнопки в верхней части правой панели:

| Кнопка | Клавиша | Что делает |
|---|---|---|
| Resume | `F8` | продолжает работу до следующей точки останова или до конца |
| Step over | `F10` | выполняет текущую строку целиком; если там вызов функции, выполняет его не заходя внутрь |
| Step into | `F11` | заходит внутрь вызываемой функции и встаёт на её первой строке |
| Step out | `Shift+F11` | довыполняет текущую функцию и останавливается сразу после возврата в вызывающую |

Простое правило выбора. Хотите понять, что делает вызов `calc(x)` внутри, — Step into. Уверены в `calc` и нужна только следующая строка вызывающего кода — Step over. Вошли не туда — Step out. Есть ещё пункт контекстного меню «Continue to here»: выполнение идёт до выбранной строки, будто вы поставили там одноразовую точку останова.

## Логирование

Отладчик не всегда под рукой: код работает на сервере, в чужом браузере, ошибка плавающая. Тогда выручает `console.log`. Хороший лог — это подпись плюс значение:

```js
const user = { name: 'Аня', age: 30 };
console.log('user =', user); // user = { name: 'Аня', age: 30 }
```

Подпись нужна, чтобы в десятке строк вывода понять, какая откуда. Для массивов объектов удобен `console.table`, для ошибок — `console.error`, а `console.trace` печатает стек вызовов в момент вызова.

Логи пригодятся, когда нужно увидеть **ход** выполнения, а не один срез. Например, цикл с лишним проходом:

```js
function average(list) {
  let sum = 0;
  for (let i = 0; i <= list.length; i++) {
    sum += list[i];
  }
  return sum / list.length;
}

console.log(average([2, 4, 6])); // NaN
```

Мы ждали `4`, получили `NaN`. Добавим строку внутри цикла: `console.log('i =', i, 'item =', list[i], 'sum =', sum)`. Вывод покажет, что на последней итерации `list[3]` равен `undefined`, и сумма превращается в `NaN`. Причина — `<=` вместо `<`: индексы массива из трёх элементов идут от 0 до 2. В отладчике то же самое обнаруживается, если поставить точку останова на `sum += list[i]` и следить за `i` в Watch.

## Как искать ошибку

- **Воспроизведите.** Найдите минимальный вход, на котором ошибка проявляется стабильно.
- **Сузьте область.** Остановитесь в середине подозрительного участка и проверьте: данные уже неверны или ещё верны? Так вы делите код пополам, как при двоичном поиске.
- **Сравнивайте ожидание и факт.** Перед каждым шагом скажите себе, чему должна быть равна переменная, и сверьтесь с Scope.
- **Читайте сообщение об ошибке.** `Cannot read properties of null (reading 'x')` прямо говорит, что слева от точки оказался `null`; в стеке — файл и строка.
- **Меняйте одну вещь за раз.**

## Типичные ошибки

> [!WARNING]
>
> - Оставленные `debugger` и отладочные `console.log` в итоговом коде.
> - Точка останова поставлена на строку, которая не выполняется (например, в ветке `else`, в которую вход не заходит) — пауза не наступит.
> - Ожидание, что `Step over` пропускает вызов, то есть не выполняет его. Вызов выполняется, просто вы не заходите внутрь.
> - Вывод объекта в консоль и вера в то, что она показывает состояние «на момент вызова»: браузерная консоль может показывать *актуальное* состояние объекта при раскрытии.

## Коротко

> [!TIP]
>
> - Отладчик останавливает программу и позволяет изучить переменные, стек и значения выражений.
> - Остановить код можно точкой останова (в том числе условной), оператором `debugger` и паузой при ошибке.
> - `Step over` не заходит в функцию, `Step into` заходит, `Step out` выходит из текущей.
> - Call Stack показывает цепочку вызовов, Watch — ваши выражения, Scope — переменные.
> - Когда отладчика нет под рукой, используйте `console.log` с подписями.
