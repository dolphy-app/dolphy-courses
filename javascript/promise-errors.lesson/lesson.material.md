# Промисы: обработка ошибок

В асинхронном коде нельзя обернуть вызов в `try..catch`: к моменту ошибки блок `try` давно закончился. Промисы решают это по-своему: ошибка превращается в отклонение промиса и «всплывает» по цепочке до первого обработчика. В этом уроке разберёмся, как работает `catch`, что значит «неявный try..catch», как пробрасывать и восстанавливаться после ошибок и что делать с необработанными отклонениями.

## catch ловит отклонения

Метод `.catch(handler)` — сокращение для `.then(undefined, handler)`. Он вызывается, если промис отклонён — любым способом:

```js
Promise.reject(new Error('A')).catch((e) => console.log(e.message)); // A

new Promise((resolve, reject) => reject(new Error('B'))).catch((e) => console.log(e.message)); // B
```

## Неявный try..catch

Код исполнителя `new Promise(executor)` и код обработчиков `then`/`catch`/`finally` окружён невидимым `try..catch`. Если внутри брошено исключение, оно превращается в отклонение промиса:

```js
new Promise(() => {
  throw new Error('внутри исполнителя');
}).catch((e) => console.log(e.message)); // внутри исполнителя

Promise.resolve()
  .then(() => {
    throw new Error('внутри then');
  })
  .catch((e) => console.log(e.message)); // внутри then
```

Это работает и для «случайных» ошибок — например, `TypeError` из-за `undefined.x` внутри обработчика тоже попадёт в ближайший `catch` ниже по цепочке.

Важная граница: неявный `try..catch` действует **только на синхронную часть**. Если исключение возникает позже — в колбэке `setTimeout`, например, — исполнитель к тому моменту давно завершился, и промис ничего не узнает:

```js
new Promise((resolve, reject) => {
  setTimeout(() => {
    throw new Error('в таймере'); // промис это не отклонит
  }, 5);
}).catch((e) => console.log('сюда не попадём'));
```

Эта ошибка станет необработанным исключением процесса. Правильно внутри асинхронных колбэков вызывать `reject`:

```js
new Promise((resolve, reject) => {
  setTimeout(() => reject(new Error('в таймере')), 5);
}).catch((e) => console.log(e.message)); // в таймере
```

## Проброс и восстановление

Отклонение «протекает» вниз по цепочке мимо всех `then` без обработчика ошибки, пока не встретит `catch`. Но на этом цепочка не заканчивается: если `catch` отработал и **ничего не бросил**, то результат его работы становится значением нового выполненного промиса. Так можно «вылечить» ошибку:

```js
Promise.resolve()
  .then(() => {
    throw new Error('C');
  })
  .catch((e) => {
    console.log('поймали', e.message); // поймали C
    return 'запасное значение';
  })
  .then((v) => console.log(v)); // запасное значение
```

Если же обработчик не может справиться с этой ошибкой, он должен бросить её снова, так же как в обычном `try..catch`:

```js
Promise.reject(new TypeError('T'))
  .catch((e) => {
    if (e instanceof RangeError) return 'обработано';
    throw e; // не наша ошибка — пробрасываем
  })
  .catch((e) => console.log('снаружи:', e.name)); // снаружи: TypeError
```

## Расположение catch имеет значение

`catch` обрабатывает ошибки только **выше** себя по цепочке. Ошибка в `then`, который стоит после `catch`, мимо него уже не пройдёт:

```js
Promise.reject(new Error('one'))
  .catch((e) => console.log('первый catch:', e.message)) // первый catch: one
  .then(() => {
    throw new Error('two');
  })
  .catch((e) => console.log('второй catch:', e.message)); // второй catch: two
```

Поэтому типичный шаблон — один `catch` в конце цепочки, который обрабатывает любую ошибку на любом шаге. Пара `then(a, b)` — иное дело: `b` не видит ошибок из `a` (подробнее — в уроке про цепочки).

## finally и ошибки

`finally(handler)` не меняет результат и не получает его, но влияет на цепочку в двух случаях:

- если `handler` бросает ошибку (или возвращает отклонённый промис), цепочка становится отклонённой с *этой* ошибкой;
- если `handler` возвращает обычное значение, оно игнорируется, и исходный результат или ошибка идут дальше.

```js
Promise.resolve(1)
  .finally(() => {
    throw new Error('из finally');
  })
  .catch((e) => console.log(e.message)); // из finally

Promise.reject(new Error('исходная'))
  .finally(() => 'это значение игнорируется')
  .catch((e) => console.log(e.message)); // исходная
```

## Необработанные отклонения

Если промис отклонён, а к моменту завершения текущего «хода» цикла событий на него никто не подписался с обработчиком ошибки, Node.js считает отклонение необработанным. Движок генерирует событие `unhandledRejection`, и начиная с Node.js 15 по умолчанию процесс завершается с ошибкой. В браузере аналог — событие `unhandledrejection` на `window`.

```js
process.on('unhandledRejection', (reason) => {
  console.log('необработанное отклонение:', reason.message);
});

Promise.reject(new Error('никто не ждёт'));
// необработанное отклонение: никто не ждёт
```

Глобальный обработчик годится для журналирования и аварийного завершения, но не как способ «починить» ошибку. Задача хорошего кода — чтобы он не срабатывал. Любая цепочка промисов должна либо заканчиваться `catch`, либо вернуться наружу (`return promise`), чтобы ответственность за ошибку взял вызывающий код.

## Типичные ошибки

> [!WARNING]
>
> - Ожидать, что `try..catch` вокруг `promise.then(...)` поймает отклонение: он увидит только синхронные исключения.
> - Бросать исключения в асинхронных колбэках внутри исполнителя вместо `reject`.
> - Поставить `catch` в середину цепочки и ожидать, что он поймает ошибки последующих `then`.
> - «Проглотить» ошибку пустым `catch(() => {})`: цепочка продолжается, как будто ничего не случилось.
> - Забыть `throw e` в `catch`, когда ошибка не обработана полностью: вместо проброса получится «успех» с `undefined`.
> - Создать промис и забыть вернуть или подписаться на его результат: отклонение останется без обработчика.

## Коротко

> [!TIP]
>
> - `catch(f)` — то же, что `then(undefined, f)`; ловит отклонения и исключения в исполнителе и обработчиках выше по цепочке.
> - Исключение в обработчике превращается в отклонение следующего промиса; неявный `try..catch` не охватывает асинхронные колбэки внутри исполнителя.
> - Обработчик `catch`, который не бросает ошибку, «лечит» цепочку, а проброс делается через `throw`.
> - `finally` не меняет результат, но брошенная в нём ошибка заменяет его.
> - Необработанные отклонения в Node.js завершают процесс; всегда заканчивайте цепочку `catch` или возвращайте её наружу.
