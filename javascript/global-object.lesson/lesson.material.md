# Глобальный объект

Встроенные функции и значения — `Array`, `Math`, `JSON`, `setTimeout`, `console` — доступны из любого места программы без импортов. Они хранятся в особом объекте, который называется **глобальным**. В этом уроке разберём, что это за объект, как к нему обратиться в любой среде и какие переменные в нём оказываются, а какие нет.

## Как называется глобальный объект

Исторически в каждой среде у него своё имя:

| Среда | Имя |
|---|---|
| браузер | `window` (в воркерах — `self`) |
| Node.js | `global` |
| любая среда | `globalThis` |

Имя `globalThis` стандартизировано в 2020 году и работает везде: и в браузере, и в Node.js, и в других движках. В новом коде используйте только его. Браузерные `window`, `document`, `alert` и прочее в этом курсе в проверяемом коде недоступны; в таких задачах работает язык, а не браузерное окружение.

```js
console.log(typeof globalThis); // object
console.log(globalThis.Array === Array); // true
console.log('Array' in globalThis); // true
```

Встроенные имена — это обычные свойства глобального объекта (только они неперечисляемые). Поэтому `Array` и `globalThis.Array` — одно и то же значение.

## Какие переменные становятся свойствами

В классическом скрипте (не модуле) верхнеуровневые `var` и функции-объявления становятся свойствами глобального объекта. А вот `let`, `const` и `class` остаются в глобальном лексическом окружении и свойствами **не становятся**:

```js
var a = 1;
let b = 2;
const c = 3;
function d() {}

console.log(globalThis.a, globalThis.b, globalThis.c, typeof globalThis.d);
// 1 undefined undefined function
console.log('a' in globalThis, 'b' in globalThis); // true false
```

Последствия: объявление через `var` на верхнем уровне «засоряет» глобальный объект и может случайно затереть чужое одноимённое значение. Это одна из причин отказаться от `var`.

**Важный нюанс.** Всё сказанное верно только для классических скриптов (например, `<script>` в браузере). В ES-модулях и в файлах Node.js (CommonJS) верхний уровень — это область модуля или функции-обёртки, и `var` там глобальным не становится. Поэтому полагаться на то, что переменная окажется в `globalThis`, нельзя; для намеренно общих данных пишите в него явно.

## Явная запись в глобальный объект

Если значение нужно сделать доступным везде, присвойте его свойству `globalThis` явно. Так видно, что это сделано намеренно:

```js
globalThis.appVersion = '1.2';
console.log(appVersion); // 1.2
```

Но злоупотреблять этим не стоит: глобальные имена конфликтуют между библиотеками и усложняют тестирование. Чем меньше глобальных переменных, тем лучше; функции должны получать данные через параметры.

## Присваивание без объявления

В нестрогом режиме присваивание необъявленной переменной молча создаёт свойство глобального объекта. В строгом режиме (`'use strict'`, модули, классы) то же самое — `ReferenceError`:

```js
leak = 5;
console.log(globalThis.leak); // 5

function strictAssign() {
  'use strict';
  nope = 1; // ReferenceError: nope is not defined
}
try {
  strictAssign();
} catch (e) {
  console.log(e.name); // ReferenceError
}
```

Это одна из самых частых причин «странных» багов: опечатка в имени создаёт новую глобальную переменную. Строгий режим превращает её в явную ошибку.

Заметьте разницу между чтением и записью: чтение необъявленной переменной всегда бросает `ReferenceError`, а оператор `typeof` — единственное исключение, он возвращает `'undefined'`:

```js
console.log(typeof neverDeclared); // undefined
```

## `this` и глобальный объект

В обычной (нестрогой) функции, вызванной без объекта, `this` указывает на глобальный объект. В строгом режиме `this` там `undefined`:

```js
function plain() {
  return this === globalThis;
}
function strict() {
  'use strict';
  return this === globalThis;
}
console.log(plain(), strict()); // true false
```

## Полифилы: зачем проверять глобальный объект

Глобальный объект удобен для проверки возможностей среды. **Полифил** — это код, добавляющий отсутствующую функцию в старую среду. Правило: добавлять только если её ещё нет, и делать свойство неперечисляемым, как у встроенных:

```js
if (!('myFeature' in globalThis)) {
  Object.defineProperty(globalThis, 'myFeature', {
    value: () => 'работает',
    writable: true,
    configurable: true,
  });
}
console.log(myFeature()); // работает
```

Проверка `in` надёжнее, чем `if (!globalThis.name)`: свойство может существовать со значением `0`, `''` или `undefined`.

## Типичные ошибки

> [!WARNING]
>
> - Надеяться, что верхнеуровневый `let`/`const` лежит в `globalThis`.
> - Предполагать, что `var` на верхнем уровне всегда глобален: в модулях и Node.js это не так.
> - Писать `window` в коде, который должен работать и вне браузера: используйте `globalThis`.
> - Забыть `let`/`const` и получить неявную глобальную переменную.
> - Проверять наличие свойства через истинность значения вместо `in`.

## Коротко

> [!TIP]
>
> - Глобальный объект хранит встроенные имена; универсальное имя — `globalThis` (`window`/`global` — среды-специфичные).
> - В классическом скрипте `var` и функции-объявления становятся его свойствами, а `let`, `const`, `class` — нет.
> - В модулях и в Node.js верхнеуровневые переменные локальны для модуля.
> - Присваивание без объявления создаёт глобальную переменную; в строгом режиме — `ReferenceError`.
> - Полифилы добавляют только отсутствующее и проверяют наличие через `in`.
