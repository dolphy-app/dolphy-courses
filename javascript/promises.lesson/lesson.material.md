# Промисы

Колбэки справляются с одним асинхронным действием, но плохо масштабируются. Промис (Promise) — это объект-«обещание»: он представляет результат, который появится позже. Вместо того чтобы передавать функцию в чужой код и надеяться, что её вызовут правильно, вы получаете объект и сами решаете, как на него подписаться. В этом уроке разберём, как промис создаётся, в каких состояниях бывает и как на него подписываться.

## Состояния промиса

У промиса всегда одно из трёх состояний:

| Состояние | Что означает |
|---|---|
| `pending` («ожидание») | результата ещё нет |
| `fulfilled` («выполнен») | операция успешна, есть значение |
| `rejected` («отклонён») | операция провалилась, есть причина (обычно объект `Error`) |

Состояния `fulfilled` и `rejected` вместе называют «завершённым» (settled) состоянием. Главное свойство: промис меняет состояние **один раз** и навсегда. Когда он выполнен или отклонён, дальнейшие попытки изменить результат игнорируются.

## Создание промиса

Промис создаётся конструктором, которому передают функцию-**исполнитель** (executor). Она запускается сразу и синхронно и получает две функции: `resolve(value)` для успеха и `reject(error)` для ошибки:

```js
const p = new Promise((resolve, reject) => {
  console.log('executor');
  resolve(1);
  resolve(2); // игнорируется
  reject(new Error('no')); // тоже игнорируется
});

console.log('после конструктора');
// executor
// после конструктора
```

Исполнитель вызывается немедленно, поэтому `executor` напечатано раньше. Повторные вызовы `resolve`/`reject` после первого ничего не меняют. Если внутри исполнителя брошена ошибка, промис автоматически отклоняется с ней, как если бы вы вызвали `reject(error)`:

```js
new Promise(() => {
  throw new Error('внезапно');
}).catch((e) => console.log(e.message)); // внезапно
```

Принято передавать в `reject` именно объект `Error`, а не строку: у него есть стек вызовов.

## Подписка: then, catch, finally

Способ получить результат — подписаться методом `.then(onFulfilled, onRejected)`. Обработчики вызываются **асинхронно**, даже если промис уже завершён: сначала доработает текущий синхронный код.

```js
const ok = new Promise((resolve) => resolve('данные'));
ok.then((value) => console.log('успех:', value));
console.log('синхронный код');
// синхронный код
// успех: данные
```

Второй аргумент `then` обрабатывает ошибку:

```js
const failed = new Promise((_, reject) => reject(new Error('плохо')));
failed.then(
  (value) => console.log('успех', value),
  (error) => console.log('провал:', error.message),
);
// провал: плохо
```

Для ошибок есть более читаемая запись: `.catch(onRejected)` — это то же самое, что `.then(undefined, onRejected)`.

Метод `.finally(handler)` выполняется при любом исходе. Он не получает ни значения, ни причины и предназначен для «уборки» (скрыть индикатор загрузки и т. п.); результат или ошибка при этом **проходят дальше**:

```js
new Promise((resolve) => resolve('готово'))
  .finally(() => console.log('уборка'))
  .then((value) => console.log(value));
// уборка
// готово
```

Подписаться можно и на уже завершённый промис, и в любой момент позже: обработчик всё равно будет вызван с сохранённым результатом. Этим промис выгодно отличается от событий, которые легко «пропустить», если подписаться поздно.

## Готовые промисы

Иногда нужен уже завершённый промис, чтобы вернуть единообразный тип. Для этого есть статические методы:

```js
Promise.resolve(5).then((v) => console.log(v)); // 5
Promise.reject(new Error('x')).catch((e) => console.log(e.message)); // x
```

`Promise.resolve(value)` вернёт выполненный промис. Если передать ему «thenable» (объект с методом `then`), он дождётся его:

```js
const thenable = {
  then(resolve) {
    resolve('из thenable');
  },
};
Promise.resolve(thenable).then(console.log); // из thenable
```

## Пример: задержка на промисах

Классический компактный пример: превращаем `setTimeout` в промис.

```js
function delay(ms) {
  return new Promise((resolve) => setTimeout(resolve, ms));
}

delay(10).then(() => console.log('прошло 10 мс'));
```

Это та самая идея, что и в «промисификации»: взять API с колбэком и обернуть его в промис. Функция не возвращает значение в `resolve`, и результатом будет `undefined`, но нам оно и не нужно, мы ждём лишь момента.

## Промис и колбэки: что изменилось

- Результат приходит один раз и не пропадает, подписаться можно позже.
- Вызывающий код сам выбирает момент подписки, а не «отдаёт» управление чужой функции.
- Можно подписать несколько обработчиков на один и тот же промис.
- Ошибку можно перехватить в одном месте (дальше мы увидим это в цепочках).

## Типичные ошибки

- Писать `return value` в исполнителе вместо `resolve(value)`: значение, которое вернул исполнитель, игнорируется, и промис остаётся в ожидании.
- Вызывать `resolve` несколько раз, рассчитывая на «последнее значение»: сработает только первый вызов.
- Отклонять промис строкой: теряется стек.
- Забыть про обработчик ошибки: отклонённый промис без обработчика в Node.js (начиная с 15 версии) приводит к аварийному завершению процесса с `unhandledRejection`.
- Путать момент вызова исполнителя (сразу) и момент вызова обработчиков `then` (позже).

## Коротко

- Промис — объект-обещание с состояниями `pending`, `fulfilled`, `rejected`; состояние меняется один раз.
- Исполнитель в `new Promise(executor)` запускается сразу; `resolve` и `reject` работают только при первом вызове.
- Подписка через `then`, `catch`, `finally`; обработчики вызываются асинхронно, даже на готовом промисе.
- Бросок исключения в исполнителе отклоняет промис.
- `Promise.resolve` и `Promise.reject` создают готовые промисы.
