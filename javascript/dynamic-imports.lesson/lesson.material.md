# Динамические импорты

Статические `import` и `export` просты и удобны для анализа, но у них есть ограничения: они только на верхнем уровне, путь — строковый литерал, и все зависимости загружаются до старта модуля. Когда нужно подгрузить код по условию, по клику или по имени, вычисленному в рантайме, используется **динамический импорт** `import()`.

## Выражение `import()`

`import(specifier)` загружает модуль и возвращает **промис**, который выполняется объектом-пространством имён модуля (тем же, что даёт `import * as ns`).

```js
// m.mjs
export const m = 1;
export default function hello() { return 'hi'; }
console.log('m evaluated');

// main.mjs
const ns = await import('./m.mjs');
console.log(ns.m);         // 1
console.log(ns.default()); // hi
```

Два важных следствия:

1. **Default лежит в свойстве `default`.** Сам результат `import()` — не функция, а объект: `ns()` даст `TypeError`, нужно `ns.default()`. Частая запись: `const { default: hello, m } = await import('./m.mjs');`.
2. Загрузка асинхронна: код после `import()` продолжает выполняться, а результат доступен в `.then` или после `await`.

```js
console.log('a');
import('./m.mjs').then(() => console.log('loaded'));
console.log('b');
// a
// b
// m evaluated
// loaded
```

## Где можно использовать

В отличие от статического `import`, динамический работает **везде**: внутри функций, `if`, обработчиков событий, а также в обычных скриптах, не только в модулях. Например, в CommonJS-файле Node.js это единственный способ подключить ES-модуль:

```js
// node -e "import('./m.mjs').then(ns => console.log(ns.m))"
// m evaluated
// 1
```

Путь может быть вычисляемым:

```js
async function loadLang(code) {
  const ns = await import(`./lang/${code}.mjs`);
  return ns.default;
}
```

Правила разрешения путей такие же, как у статического импорта (в Node — полное имя файла с расширением; в браузере — URL, относительный к текущему модулю).

## Это не функция

Хотя запись похожа на вызов, `import()` — **синтаксис**, как `super()`. Его нельзя присвоить переменной или вызвать через `call/apply`:

```js
const i = import;        // SyntaxError
import.call(null, 'x'); // SyntaxError
```

Если нужна функция-обёртка, оберните сами: `const load = (path) => import(path);`.

## Однократное выполнение сохраняется

Динамический импорт использует тот же кеш модулей, что и статический. Повторный `import()` того же модуля не выполняет код заново, а возвращает тот же объект:

```js
const n = './m.mjs';
const [a, b] = await Promise.all([import(n), import(n)]);
console.log(a === b); // true
// 'm evaluated' появится один раз
```

Поэтому `import()` можно вызывать «на всякий случай» много раз: после первой загрузки это дешёвое обращение к кешу.

## Ошибки загрузки

Если модуль не найден, не загрузился или бросил исключение при выполнении, промис отклоняется. Ошибку ловят `catch` у промиса или `try/catch` вокруг `await`:

```js
try {
  await import('./nope.mjs');
} catch (e) {
  console.log(e.code); // ERR_MODULE_NOT_FOUND (в Node)
}
```

Синхронный `try/catch` **без** `await` ничего не поймает: ошибка придёт позже, как отклонение промиса, и необработанное отклонение завершит процесс Node.

## Зачем это нужно

- **Разделение кода (code splitting).** Тяжёлый редактор, графики или локаль грузятся только когда понадобились; сборщики превращают каждый `import()` в отдельный файл.
- **Условная загрузка.** Разные реализации для разных окружений.
- **Плагины и маршруты.** Имя модуля известно только во время работы.
- **Совместимость.** Подключение ES-модулей из CommonJS.

## Ленивая загрузка своими руками

Идея «загрузить один раз по требованию и запомнить» легко выражается через кеш **промисов**, а не готовых значений: тогда два одновременных запроса не запустят две загрузки.

```js
function lazy(load) {
  const cache = new Map();
  return (name) => {
    if (!cache.has(name)) {
      const p = load(name).catch((err) => {
        cache.delete(name); // неудачу не запоминаем
        throw err;
      });
      cache.set(name, p);
    }
    return cache.get(name);
  };
}
```

Здесь загрузчик `load` передан параметром — так код проще тестировать (в заданиях урока вместо реального `import()` мы подставляем функцию-имитацию). Заметьте удаление записи при ошибке: иначе временный сбой сети застрянет в кеше навсегда.

## Типичные ошибки

> [!WARNING]
>
> - Вызывать результат как функцию, забыв про `.default`.
> - Не дождаться промиса: использовать `ns` до `await`.
> - Ловить ошибку синхронным `try/catch` без `await`.
> - Ожидать повторной инициализации при втором `import()` — модуль выполняется один раз.
> - Использовать динамические пути там, где сборщик не может их проанализировать: он либо включит в пакет лишнее, либо не найдёт файл.

## Коротко

> [!TIP]
>
> - `import(path)` возвращает промис с пространством имён; default — в свойстве `default`.
> - Работает в любом месте кода, в том числе в обычных скриптах.
> - Это синтаксис, а не функция: присвоить или `call`-нуть его нельзя.
> - Кеш модулей общий со статическим импортом: код выполняется один раз.
> - Ошибки загрузки — отклонённый промис.
