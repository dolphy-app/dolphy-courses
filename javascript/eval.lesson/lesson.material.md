# Eval

Встроенная функция `eval(code)` принимает строку, разбирает её как JavaScript-код и выполняет. Звучит мощно, но на практике `eval` нужен почти никогда: он опасен, замедляет код и в современных проектах считается плохой практикой. Тем не менее знать, как он работает, необходимо — чтобы читать чужой код, понимать область видимости и уметь заменить `eval` безопасными инструментами.

## Как работает eval

Результат `eval` — значение последнего выражения в выполненном коде:

```js
console.log(eval('1 + 2 * 3')); // 7
console.log(eval('let q = 5; q * 2')); // 10
```

Если передать не строку, `eval` вернёт аргумент как есть, ничего не выполняя:

```js
console.log(eval(42), eval({ a: 1 })); // 42 { a: 1 }
```

Если код — объявление без выражения, результатом будет `undefined`:

```js
console.log(eval('var k = 1')); // undefined
```

Ещё одна ловушка: фигурные скобки в начале строки `eval` читает как блок, а не как объект. Чтобы получить объект, оберните литерал в круглые скобки:

```js
console.log(eval('({a:1})'), eval('{a:1}')); // { a: 1 } 1
```

Во втором случае `{a:1}` — блок с меткой `a`, а значение последнего выражения — `1`.

Синтаксические ошибки в строке проявятся только в момент вызова и как обычное исключение:

```js
try {
  eval('1 +');
} catch (e) {
  console.log(e.name); // SyntaxError
}
```

## Область видимости: прямой вызов

Когда `eval` вызван напрямую (`eval(...)`, именно под этим именем), код выполняется в текущей лексической области и видит, а также может менять локальные переменные:

```js
function g() {
  const x = 'local';
  return eval('x');
}
console.log(g()); // local

let a = 1;
eval('a = a + 10');
console.log(a); // 11
```

Переменные, объявленные через `let` и `const` внутри `eval`, живут только внутри этого вызова:

```js
eval('let q = 5');
console.log(typeof q); // undefined
```

А вот `var` и объявления функций в нестрогом режиме «протекают» в окружающую функцию:

```js
eval('var v = 7');
console.log(v); // 7
```

В строгом режиме у `eval` собственная область: `var` не выходит наружу.

```js
function sloppy() {
  eval('var v = 7');
  return typeof v;
}
function strict() {
  'use strict';
  eval('var v = 7');
  return typeof v;
}
console.log([sloppy(), strict()]); // [ 'number', 'undefined' ]
```

## Косвенный вызов: глобальная область

Если вызвать `eval` не напрямую — через другое имя или выражение, — код выполняется в глобальной области видимости и локальных переменных не видит:

```js
function f() {
  const x = 1;
  return [eval('typeof x'), (0, eval)('typeof x')];
}
console.log(f()); // [ 'number', 'undefined' ]
```

Запись `(0, eval)(code)` — стандартный приём косвенного вызова: оператор запятая возвращает функцию, но вызов перестаёт быть «прямым». То же происходит, если сделать `const e = eval; e(code)`.

В Node.js есть оговорка: модули CommonJS обёрнуты в функцию, и «глобальной» для файла является не область модуля, а настоящая глобальная. Поэтому `var`, объявленный в вашем файле, косвенному `eval` не виден (в браузерном скрипте был бы виден).

## Почему eval считается вредным

1. **Безопасность.** Если в строку попадают данные пользователя, злоумышленник получает возможность выполнить произвольный код с вашими правами: прочитать токены, послать запросы, изменить страницу. Фильтрация «опасных» символов ненадёжна.
2. **Производительность.** Движок не может заранее знать, что окажется в строке и какие переменные код тронет. Из-за прямого `eval` оптимизация функции затруднена: приходится сохранять все имена переменных.
3. **Минификация.** Минификаторы переименовывают локальные переменные (`counter` → `a`). Строка с `eval('counter + 1')` после такой замены сломается.
4. **Отладка и ошибки.** Синтаксис не проверяется до запуска, статические анализаторы и IDE строку не видят.
5. **Разбор чужих данных.** Раньше `eval` использовали для чтения JSON, но он принимает любой код, а не только данные.

## Чем заменить eval

**Данные в формате JSON** — `JSON.parse`. Он принимает только данные и не выполняет код:

```js
console.log(JSON.parse('{"a":[1,2]}').a); // [ 1, 2 ]
try {
  JSON.parse('{a:1}');
} catch (e) {
  console.log(e.name); // SyntaxError
}
```

`{a:1}` — корректный JavaScript, но не JSON: ключи должны быть в двойных кавычках.

**Нужна функция из строки** — `new Function`. Она выполняется в глобальной области и не видит локальные переменные, зато аргументы передаются явно:

```js
console.log(new Function('a', 'b', 'return a + b')(1, 2)); // 3

const fx = new Function('return typeof a');
(function () {
  const a = 1;
  console.log(fx()); // undefined
})();
```

Это лучше `eval`, так как область видимости явная, но и `new Function` остаётся «исполнением строки»: безопасностью проблема не решается. Подробнее — в уроке про `new Function`.

**Нужны вычисления над данными пользователя** — разбирайте ввод сами или проверяйте его по строгому списку допустимых символов. Компромиссный вариант для арифметики:

```js
function calc(expr) {
  if (!/^[\d+\-*/().\s]+$/.test(expr)) throw new Error('bad');
  return Function(`"use strict"; return (${expr})`)();
}
console.log(calc('2 * (3 + 4)')); // 14
try {
  calc('process.exit()');
} catch (e) {
  console.log(e.message); // bad
}
```

Белый список из цифр, знаков операций, скобок и пробелов не даёт вызвать функцию или обратиться к переменной. Для чего-то сложнее лучше написать маленький парсер или взять библиотеку.

**Нужны динамические имена** — используйте объекты и `Map`: `config[name]` вместо `eval(name)`. **Нужен код по расписанию** — передавайте функции, а не строки.

## Типичные ошибки

> [!WARNING]
>
> - `eval('{...}')` для объектного литерала без круглых скобок.
> - Использование `eval` для JSON.
> - Ожидание, что `const e = eval; e('x')` видит локальную переменную `x`.
> - Ожидание, что `var` из строгого `eval` попадёт наружу.
> - Проверка пользовательского ввода «чёрным списком» запрещённых слов.

## Коротко

> [!TIP]
>
> - `eval(str)` выполняет код из строки и возвращает значение последнего выражения.
> - Прямой вызов видит локальную область; косвенный (`(0, eval)(...)`) работает в глобальной.
> - `let`/`const` внутри `eval` остаются внутри; `var` в нестрогом режиме выходит наружу.
> - Минусы: безопасность, оптимизации, минификация, проверка ошибок только при запуске.
> - Вместо `eval`: `JSON.parse`, `new Function`, парсер с белым списком, объекты и `Map`.
