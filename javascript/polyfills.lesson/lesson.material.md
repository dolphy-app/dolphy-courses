# Полифилы и транспайлеры

JavaScript развивается постоянно: каждый год в стандарт ECMAScript попадают новые возможности. Но написать код на новом синтаксисе — не значит, что он запустится везде. У пользователей разные браузеры и версии Node.js, а производители движков сами решают, что и когда реализовать. Эта тема — о том, как писать современный код и всё же не потерять старых пользователей.

## Почему возможности поддерживаются неравномерно

Новая возможность проходит путь от предложения комитета TC39 до включения в спецификацию. Движки (V8, SpiderMonkey, JavaScriptCore) могут реализовать её ещё на стадии черновика, а могут отложить уже утверждённую, потому что она сложная или нужна не многим. Поэтому в любой момент часть стандарта в части окружений просто отсутствует. Актуальное положение дел показывают таблицы совместимости (compat-table), MDN и сервис caniuse.

Новые возможности бывают двух видов, и решение для них разное:

| Вид | Пример | Чем закрыть |
|---|---|---|
| Синтаксис | `?.`, `??`, стрелочные функции, `class`, `async/await` | транспайлер |
| Библиотечная функция | `Array.prototype.at`, `Object.hasOwn`, `Promise.allSettled` | полифил |

Синтаксис нельзя «подключить» библиотекой: старый движок не сможет даже разобрать файл и упадёт с `SyntaxError` до выполнения первой строки. А вот отсутствующий метод можно добавить самим, ведь язык динамический.

## Транспайлер

Транспайлер (transpiler) — это программа, которая переписывает код из нового синтаксиса в старый. Самый известный — Babel. Вы запускаете его на своей машине, он читает исходники и выдаёт результат, который поймут старые движки. Обычно это встроено в сборщик (Vite, webpack, esbuild) и срабатывает при каждой сборке.

Например, оператор `??` можно выразить через старые конструкции:

```js
// исходник
const name = user ?? "аноним";

// что получится после преобразования (упрощённо)
const user = null;
const name2 = user !== null && user !== void 0 ? user : "аноним";
console.log(name2); // аноним
```

Важно, что поведение должно остаться тем же: `0` и `""` не должны заменяться (в отличие от `||`):

```js
console.log(0 ?? "x");  // 0
console.log(0 || "x");  // x
```

Какие именно возможности нужно преобразовывать, определяется списком целевых окружений (например, `browserslist`): чем более старые браузеры поддерживаются, тем больше преобразований и тем тяжелее итоговый код. Если целиться только в свежие версии, транспайлер почти ничего не изменит.

## Полифил

Полифил (polyfill) — скрипт, который «заполняет» недостающую функциональность: проверяет, есть ли в окружении нужная функция, и если нет, добавляет свою реализацию, ведущую себя по стандарту. Известная коллекция — `core-js`, из которой можно подключать только нужное. Обычно сборщик и Babel подтягивают полифилы автоматически на основе целевых окружений.

Принципиальная схема всегда одна:

```js
if (!Array.prototype.myLast) {
  Object.defineProperty(Array.prototype, "myLast", {
    value() {
      return this[this.length - 1];
    },
    writable: true,
    configurable: true,
  });
}

console.log([1, 2, 3].myLast()); // 3
```

Разберём детали, из-за которых полифилы пишут именно так.

**Проверка наличия.** Нативная реализация быстрее и надёжнее, поэтому мы устанавливаем свою только когда нужного нет. Без проверки вы затрёте встроенный метод своей версией.

**`Object.defineProperty` вместо присваивания.** При простом присвоении `Array.prototype.last = function () {...}` свойство получается перечисляемым, и оно «протекает» в цикл `for...in` по массивам:

```js
Array.prototype.last = function () { return this[this.length - 1]; };

const keys = [];
for (const key in ["a", "b"]) keys.push(key);
console.log(keys); // [ '0', '1', 'last' ]

delete Array.prototype.last;
```

Встроенные методы не перечисляются; с `defineProperty` и значением `enumerable` по умолчанию (`false`) полифил ведёт себя так же:

```js
Object.defineProperty(Array.prototype, "last", {
  value() { return this[this.length - 1]; },
  writable: true,
  configurable: true,
});

const keys = [];
for (const key in ["a", "b"]) keys.push(key);
console.log(keys); // [ '0', '1' ]

delete Array.prototype.last;
```

**Повторяйте поведение стандарта.** Спецификация описывает и крайние случаи: как обработать `NaN`, отрицательные индексы, пустые массивы, не-массивы. Например, `includes` сравнивает алгоритмом SameValueZero и поэтому находит `NaN`, а `indexOf` использует строгое равенство и не находит:

```js
console.log([NaN].includes(NaN));  // true
console.log([NaN].indexOf(NaN));   // -1
```

Значит, полифил для `includes`, написанный через `indexOf`, будет ошибаться.

## Свой полифил: на примере `Object.entries`

Метод возвращает массив пар `[ключ, значение]` собственных перечислимых строковых свойств:

```js
console.log(Object.entries({ a: 1, b: 2 })); // [ [ 'a', 1 ], [ 'b', 2 ] ]
```

Реализовать его можно через `Object.keys`: пройти ключи и собрать пары. Наследуемые и символьные свойства сюда не попадают — как раз такое поведение у `Object.keys`.

## Когда полифилы не нужны

- Если вы пишете для Node.js 22 и знаете версию окружения, большинство полифилов бессмысленны.
- Если нужен только синтаксис, достаточно транспайлера.
- Расширять прототипы встроенных объектов своими нестандартными методами не стоит: они могут конфликтовать с будущим стандартом (так случилось, например, с `Array.prototype.flatten`, ставшим `flat`). Полифилить можно только то, что уже есть в спецификации.

## Типичные ошибки

- Путать транспайлер и полифил: синтаксис не «дополифилить».
- Добавлять метод в прототип обычным присваиванием: он попадает в `for...in`.
- Забыть проверку наличия и перезаписать нативную реализацию.
- Реализовать «примерно так же», пропустив граничные случаи спецификации.

## Коротко

- Движки реализуют стандарт неравномерно, поэтому современный код нужно адаптировать к целевым окружениям.
- Транспайлер (Babel) переписывает новый синтаксис в старый; полифил добавляет отсутствующие встроенные функции.
- Полифил ставят только если функции нет, и определяют через `Object.defineProperty` — чтобы он не был перечисляемым.
- Повторяйте поведение по спецификации, включая граничные случаи (`NaN`, отрицательные индексы).
- Состав преобразований определяет список целевых окружений; для современных сред часто хватает минимума.
