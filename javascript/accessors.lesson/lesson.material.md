# Геттеры и сеттеры

Свойства бывают двух видов. Первые — **свойства-данные**: просто хранят значение. Вторые — **аксессоры**: по сути это функции, которые вызываются при чтении и записи, но снаружи выглядят как обычное свойство. С их помощью можно вычислять значения «на лету», проверять присваиваемое и скрывать внутреннее устройство.

## get и set в литерале

В объектном литерале аксессор задают ключевыми словами `get` и `set`:

```js
const person = {
  firstName: 'Анна',
  lastName: 'Орлова',

  get fullName() {
    return this.firstName + ' ' + this.lastName;
  },

  set fullName(value) {
    [this.firstName, this.lastName] = value.split(' ');
  },
};

console.log(person.fullName); // Анна Орлова
person.fullName = 'Иван Петров';
console.log(person.firstName); // Иван
console.log(person.lastName); // Петров
```

Снаружи `fullName` — обычное свойство: без скобок при чтении и через `=` при записи. Но на самом деле при `person.fullName` вызывается геттер, а при присваивании — сеттер с присвоенным значением.

Геттер вызывается без аргументов, сеттер — с одним. Внутри `this` — объект, у которого обратились к свойству.

## Только геттер

Если задан только `get`, свойство доступно только для чтения. Запись в обычном режиме молча игнорируется, в строгом — `TypeError`:

```js
const rect = {
  w: 3,
  h: 4,
  get area() {
    return this.w * this.h;
  },
};
rect.area = 100;
console.log(rect.area); // 12
rect.w = 10;
console.log(rect.area); // 40
```

Вычисляемое свойство всегда актуально: оно пересчитывается при каждом чтении. Если вычисление дорогое, результат придётся кэшировать самому.

## Дескрипторы аксессоров

У аксессора в дескрипторе нет `value` и `writable`, зато есть `get` и `set` (функции или `undefined`). Остаются `enumerable` и `configurable`. Смешивать `value`/`writable` с `get`/`set` в одном дескрипторе нельзя:

```js
const o = {};
Object.defineProperty(o, 'now', {
  get() {
    return 42;
  },
  enumerable: true,
  configurable: true,
});
console.log(Object.getOwnPropertyDescriptor(o, 'now').set); // undefined

try {
  Object.defineProperty({}, 'bad', { value: 1, get() {} });
} catch (err) {
  console.log(err.name); // TypeError
}
```

Те же правила перебора действуют и здесь: аксессоры, объявленные в литерале, перечислимы, а в классах — нет (они лежат на прототипе и скрыты).

## Умные сеттеры: проверка значения

Главное применение сеттера — валидация. Реальное значение хранят в «скрытом» свойстве. Обычно его называют с подчёркиванием `_name`: это соглашение «не трогать снаружи», а не защита языка:

```js
const account = {
  _balance: 0,

  get balance() {
    return this._balance;
  },

  set balance(value) {
    if (typeof value !== 'number' || value < 0) {
      throw new RangeError('Баланс должен быть неотрицательным числом');
    }
    this._balance = value;
  },
};

account.balance = 50;
console.log(account.balance); // 50
try {
  account.balance = -1;
} catch (err) {
  console.log(err.message); // Баланс должен быть неотрицательным числом
}
```

Настоящую приватность дают приватные поля классов `#balance`; о них — в разделе про классы.

## Совместимость

Аксессоры удобны при развитии кода. Допустим, раньше `user.age` было обычным полем, а потом возраст понадобилось вычислять из даты рождения. Заменяем поле геттером, и весь код, читавший `user.age`, продолжает работать без изменений:

```js
function makeUser(name, birthYear) {
  return {
    name,
    birthYear,
    get age() {
      return 2026 - this.birthYear;
    },
  };
}
console.log(makeUser('Лев', 2000).age); // 26
```

## Аксессоры и наследование

Геттеры и сеттеры наследуются через прототип, и `this` в них — тот объект, через который обратились. Это важно: запись в унаследованный аксессор не создаёт собственное свойство, а вызывает сеттер:

```js
const base = {
  _v: 1,
  get v() {
    return this._v;
  },
  set v(x) {
    this._v = x;
  },
};
const child = Object.create(base);
child.v = 5;
console.log(Object.keys(child)); // [ '_v' ]
console.log(base._v); // 1
```

Запись `child.v = 5` вызвала сеттер из `base` с `this = child`, поэтому `_v` появилось в `child`, а `base._v` не тронут. Если бы вместо аксессора в прототипе было обычное данное, присваивание создало бы собственное свойство `v`.

## Типичные ошибки

- Геттер и свойство с одним и тем же именем: `get name() { return this.name; }` вызывает сам себя бесконечно (переполнение стека). Храните данные под другим именем.
- Ожидать, что присваивание геттеру без сеттера сработает: в строгом режиме это `TypeError`.
- Делать в геттере дорогие или побочные действия: чтение свойства принято считать дешёвым.
- Рассчитывать на защиту `_name`: свойство остаётся доступным.

```js
const bad = {
  get name() {
    return this.name;
  },
};
try {
  bad.name;
} catch (err) {
  console.log(err.name); // RangeError
}
```

## Коротко

- Аксессор — пара функций `get`/`set`, замаскированная под свойство.
- Только `get` делает свойство вычисляемым и доступным лишь для чтения.
- Дескриптор аксессора содержит `get`, `set`, `enumerable`, `configurable`, но не `value` и `writable`.
- Сеттеры нужны для проверки и нормализации значений; данные хранят в другом свойстве.
- Аксессоры позволяют менять реализацию, не меняя интерфейс для внешнего кода.
