# Синтаксис new Function

Почти всегда функцию создают через объявление или выражение. Но у языка есть ещё один способ: собрать функцию из строки с исходным кодом уже во время выполнения программы. Урок объясняет, как это работает, чем такая функция отличается от обычной и почему её замыкание «не видит» локальные переменные.

## Как это выглядит

Конструктор `Function` принимает любое число строк: все, кроме последней, — имена параметров, последняя — тело функции.

```js
const sum = new Function('a', 'b', 'return a + b');
console.log(sum(1, 2)); // 3
```

Это эквивалентно записи `function sum(a, b) { return a + b; }`, только текст функции появился как значение строки. Строку можно получить откуда угодно: из конфигурации, от пользователя, из ответа сервера, из шаблона.

Параметры можно перечислить и в одной строке через запятую, а можно вообще не передавать: тогда единственный аргумент — тело.

```js
const mul = new Function('a, b', 'return a * b');
console.log(mul(6, 7)); // 42

const hello = new Function('return "привет"');
console.log(hello()); // привет
```

Значения по умолчанию, остаточные параметры и деструктуризация в списке параметров тоже работают, ведь строки разбираются тем же парсером, что и остальной код:

```js
const f = new Function('a', 'b = 2', '...rest', 'return a + b + rest.length');
console.log(f(1)); // 3
console.log(f(1, 10, 0, 0)); // 13
```

Свойства у такой функции обычные: у `mul` есть `length` и `name`.

```js
console.log(mul.length); // 2
console.log(mul.name); // anonymous
```

## Главная особенность: замыкание на глобальное окружение

Обычная функция запоминает в скрытом свойстве `[[Environment]]` окружение, в котором была создана, и поэтому видит локальные переменные внешней функции. У функции из `new Function` в `[[Environment]]` записано не текущее лексическое окружение, а **глобальное**. Локальные переменные места создания ей недоступны:

```js
function makeGetter() {
  const secret = 'local';
  return new Function('return secret');
}

try {
  makeGetter()();
} catch (err) {
  console.log(err.name); // ReferenceError
}
```

Для сравнения — та же функция, написанная обычным образом, замыкание сохраняет:

```js
function makeGetterNormal() {
  const secret = 'local';
  return function () {
    return secret;
  };
}
console.log(makeGetterNormal()()); // local
```

Глобальные переменные (точнее, свойства глобального объекта) видны и из `new Function`:

```js
globalThis.limit = 10;
const check = new Function('n', 'return n < limit');
console.log(check(5)); // true
console.log(check(50)); // false
```

Замечание про окружение: `let` и `const` верхнего уровня в скрипте попадают в глобальное лексическое окружение, а в модуле и в CommonJS-файле Node.js они локальны для модуля и «снаружи» не видны. Поэтому не рассчитывайте, что `new Function` увидит переменные вашего файла; свойства `globalThis` увидит всегда.

## Почему так сделано

Причина практическая. Современный код перед публикацией сжимают: минификатор переименовывает локальные переменные в `a`, `b`, `c`. Если бы функция, собранная из строки, могла обращаться к локальным именам, она сломалась бы после минификации: в строке осталось бы старое имя `secret`, а в коде его уже нет. Заодно это защищает от случайного доступа к приватным данным из чужого текста.

Если нужно передать значение, делайте это явно — параметром:

```js
const triple = new Function('x', 'return x * 3');
const price = 14;
console.log(triple(price)); // 42
```

## Когда это нужно

На практике `new Function` встречается редко. Типичные случаи: шаблонизаторы, которые компилируют шаблон в функцию; калькуляторы формул; генерация кода по описанию. Для простого «выполнить строку» есть `eval`, но он видит локальные переменные, и поэтому опаснее и хуже поддаётся оптимизации. `new Function` изолирует код от локальной области, но **не** изолирует от глобальной: он всё ещё может читать и менять `globalThis`, вызывать `fetch` и так далее.

## Типичные ошибки

- Ожидать, что функция из строки видит локальные переменные: получите `ReferenceError`.
- Подставлять в код строки от пользователя. Это исполнение чужого кода: никаких проверок нет, внедрение кода неизбежно.
- Забыть `return`: тело — это инструкции, а не выражение. `new Function('a', 'a + 1')` вернёт `undefined`.

```js
const noReturn = new Function('a', 'a + 1');
console.log(noReturn(1)); // undefined
```

## Коротко

- `new Function(arg1, ..., body)` создаёт функцию из строк: аргументы — имена параметров, последняя строка — тело.
- Имена параметров можно передать одной строкой через запятую.
- `[[Environment]]` такой функции указывает на глобальное окружение, локальные переменные ей недоступны.
- Нужные значения передавайте параметрами; для замыканий используйте обычные функции.
- Строки с кодом из ненадёжных источников исполнять нельзя.
