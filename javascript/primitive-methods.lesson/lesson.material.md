# Методы примитивов

Строка — примитив, а у неё есть методы: `'abc'.toUpperCase()`. Число — примитив, но `(5).toFixed(2)` работает. Как это совмещается с правилом «у примитивов нет свойств и методов»? В этом уроке разберём механизм объектов-обёрток и посмотрим, где он даёт неожиданные результаты.

## Примитив и объект: в чём разница

В JavaScript семь примитивных типов: `string`, `number`, `bigint`, `boolean`, `symbol`, `null` и `undefined`. Примитив хранит одно значение, не имеет собственных свойств и неизменяем. Объект — это набор пар «ключ–значение», который может хранить и функции-методы.

Методы удобны, поэтому хочется иметь их и у строк с числами, но превращать каждую строку в тяжёлый объект ради этого нельзя: примитивы быстрые и лёгкие. Язык решает задачу компромиссом.

## Объекты-обёртки

Для большинства примитивов существуют встроенные конструкторы-обёртки: `String`, `Number`, `BigInt`, `Boolean`, `Symbol`. Когда вы обращаетесь к свойству или методу примитива, движок:

1. Временно создаёт объект-обёртку нужного типа, внутри которого лежит значение примитива.
2. Берёт у этой обёртки метод или свойство.
3. Вызывает метод. Результат возвращается как обычное значение.
4. Сразу «выбрасывает» обёртку, а примитив остаётся нетронутым.

Поэтому код работает так, как будто методы есть у самого примитива:

```js
const word = 'hello';
console.log(word.toUpperCase()); // HELLO
console.log(word); // hello — исходная строка не изменилась
console.log(word.length); // 5
```

Строки неизменяемы, и методы возвращают новое значение, а не меняют старое. Это важно запомнить уже сейчас: к строкам и числам мы вернёмся в следующих уроках.

Современные движки оптимизируют этот процесс, так что в реальности обёртка часто вообще не создаётся. Но поведение программы должно оставаться таким, будто она создаётся, — спецификация это гарантирует.

## Свойство, записанное в примитив, пропадает

Поскольку обёртка временная, записать в примитив свойство не получится:

```js
let label = 'x';
label.test = 5; // в обычном (нестрогом) режиме молча игнорируется
console.log(label.test); // undefined
```

Присваивание создало свойство у временной обёртки, и она тут же исчезла. При чтении создалась уже новая обёртка без всякого свойства `test`.

В строгом режиме (`'use strict'`) та же запись приводит к ошибке `TypeError: Cannot create property 'test' on string 'x'`. Модули и классы всегда работают в строгом режиме, поэтому в современном коде вы увидите именно ошибку, а не молчаливый пропуск.

## Не создавайте обёртки вручную

Синтаксис `new String('a')`, `new Number(1)`, `new Boolean(false)` существует, но пользоваться им не стоит. Результат — настоящий объект, а не примитив:

```js
console.log(typeof 'a'); // string
console.log(typeof new String('a')); // object
console.log(new String('a') === 'a'); // false
console.log(new String('a') == 'a'); // true — объект приводится к примитиву
console.log(new String('a') == new String('a')); // false — разные объекты
```

Особенно коварен `Boolean`: любой объект в условии даёт `true`, даже если внутри лежит `false` или `0`:

```js
if (new Number(0)) {
  console.log('это выполнится'); // объект всегда truthy
}
```

А вот вызывать эти же функции **без** `new` — нормально и полезно. Так выполняется приведение типов, и результат — примитив:

```js
console.log(typeof Number('5')); // number
console.log(typeof String(5)); // string
console.log(typeof new String(5)); // object
```

## У null и undefined методов нет

Обёрток для `null` и `undefined` не существует. Любая попытка обратиться к их свойствам завершается ошибкой:

```js
try {
  null.toString();
} catch (e) {
  console.log(e.message); // Cannot read properties of null (reading 'toString')
}
```

Это одна из самых частых ошибок времени выполнения в реальных программах. Защититься можно проверкой значения либо оператором опциональной цепочки `?.`, который остановит вычисление и вернёт `undefined`, если слева `null` или `undefined`.

## Методы у чисел и литералов

Метод можно вызвать у литерала в скобках: `(5).toFixed(2)` даёт `'5.00'`. Скобки не случайны: запись `5.toFixed(2)` — синтаксическая ошибка, потому что после `5.` парсер ждёт дробную часть. Рабочие варианты: `(5).toFixed(2)`, `5..toFixed(2)` (вторая точка — уже оператор доступа) или переменная.

```js
console.log((5).toFixed(2)); // 5.00
console.log(7..toString(2)); // 111 — число 7 в двоичной системе
```

## Откуда берутся методы

Методы обёрток лежат в их прототипах — например, `String.prototype`. Туда можно добавить собственный метод, и он появится у всех строк:

```js
String.prototype.shout = function () {
  return this.toUpperCase() + '!';
};
console.log('hi'.shout()); // HI!
```

Так делали в прошлом, и называется это расширением встроенных прототипов. Делать это в рабочем коде не рекомендуется: можно столкнуться с будущими методами стандарта и с чужим кодом. Допустимое исключение — полифилы, которые добавляют отсутствующую стандартную функциональность.

Заметьте, что внутри такого метода `this` в нестрогом режиме — это объект-обёртка (`typeof this` даёт `'object'`), а в строгом — сам примитив (`'string'`).

## Типичные ошибки

- Ожидать, что присваивание `str.prop = 1` сохранится: у примитивов нет собственных свойств.
- Писать `new Boolean(...)` или `new Number(...)` ради «приведения типов» — получится объект, а не примитив.
- Сравнивать `new String('a') === 'a'` и удивляться `false`.
- Вызывать метод у значения, которое может оказаться `null` или `undefined`, без проверки.

## Коротко

- У примитивов нет своих свойств, но при обращении к методу движок временно оборачивает значение в объект `String`, `Number`, `Boolean` и т. п.
- Записать свойство в примитив нельзя: в нестрогом режиме оно тихо пропадёт, в строгом — ошибка `TypeError`.
- `new String(...)` и подобные конструкторы создают объекты; без `new` те же функции выполняют приведение типов и возвращают примитивы.
- У `null` и `undefined` нет ни методов, ни свойств — обращение к ним вызывает `TypeError`.
- Методы строк и чисел возвращают новые значения: сами примитивы неизменяемы.
