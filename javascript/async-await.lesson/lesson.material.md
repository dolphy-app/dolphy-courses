# Async/await

Цепочки `then` лучше колбэков, но всё равно читаются хуже обычного последовательного кода. Синтаксис `async/await` позволяет писать асинхронную логику так, будто она синхронная: «подожди результат, потом иди дальше». Под капотом всё те же промисы, поэтому всё, что вы знаете про них (цепочки, ошибки, `Promise.all`), остаётся в силе. После урока вы сможете писать и читать асинхронный код на `async/await`, обрабатывать ошибки через `try..catch` и не терять параллельность.

## async-функции

Ключевое слово `async` перед функцией означает: эта функция **всегда возвращает промис**. Возвращённое значение автоматически оборачивается в выполненный промис:

```js
async function f() {
  return 1;
}

console.log(f()); // Promise { 1 }
f().then((v) => console.log(v)); // 1
```

Если вернуть промис, он «разворачивается»:

```js
async function g() {
  return Promise.resolve('распаковано');
}

g().then((v) => console.log(v)); // распаковано
```

Исключение внутри `async`-функции превращается в отклонение возвращённого промиса:

```js
async function fail() {
  throw new Error('упс');
}

fail().catch((e) => console.log('поймали', e.message)); // поймали упс
```

`async` можно ставить перед объявлением, функциональным выражением, стрелкой и методом класса или объекта:

```js
const arrow = async (x) => x * 2;
class Api {
  async load() {
    return 'данные';
  }
}

arrow(4).then(console.log); // 8
new Api().load().then(console.log); // данные
```

## await

Внутри `async`-функции можно использовать `await`. Он приостанавливает *эту функцию* до тех пор, пока промис не завершится, и возвращает его значение. Остальная программа при этом продолжает работать: функция «замирает» и освобождает поток.

```js
const delay = (ms, value) => new Promise((resolve) => setTimeout(() => resolve(value), ms));

async function show() {
  console.log('начало');
  const value = await delay(10, 'значение');
  console.log('получили', value);
  return value.toUpperCase();
}

const result = show();
console.log('код после вызова');
result.then((v) => console.log('итог', v));
// начало
// код после вызова
// получили значение
// итог ЗНАЧЕНИЕ
```

Выполнение `show()` идёт синхронно до первого `await`, а дальше управление возвращается вызывающему коду. Продолжение после `await` — это микрозадача, как обработчик `then` (в уроке про микрозадачи вы это видели).

Важные детали:

- `await` можно использовать только внутри `async`-функций (и на верхнем уровне ES-модулей). В обычной функции и в обычном скрипте это синтаксическая ошибка. В примерах и заданиях курса код — обычный скрипт, поэтому `await` в них допустим только внутри `async`-функции.
- `await value` для не-промиса просто возвращает значение, но всё равно уступает управление (продолжение будет в микрозадаче).
- `await` работает и с thenable-объектами.
- Если промис отклонён, `await` **бросает** ошибку на этом месте.

## Ошибки: try..catch

Раз отклонение превращается в исключение, то обрабатывать его можно обычным `try..catch`, как в синхронном коде:

```js
async function safe() {
  try {
    await Promise.reject(new Error('плохо'));
  } catch (e) {
    console.log('try/catch:', e.message); // try/catch: плохо
    return 'запасное';
  } finally {
    console.log('finally');
  }
}

safe().then(console.log);
// try/catch: плохо
// finally
// запасное
```

Если ошибку не поймать, `async`-функция вернёт отклонённый промис, и его можно обработать снаружи через `.catch(...)`. Отличить два стиля просто: внутри `async`-функции удобнее `try..catch`, а на границе (там, где вы вызываете её из обычного кода) обычно ставят `.catch`.

Тонкость с `return`: если нужно поймать ошибку промиса, возвращаемого из `try`, нужен именно `return await`. Без него промис возвращается наружу, функция выходит из `try` и `catch` его уже не видит:

```js
const failLater = () =>
  new Promise((_, reject) => setTimeout(() => reject(new Error('поздняя ошибка')), 5));

async function noAwait() {
  try {
    return failLater(); // catch не сработает
  } catch {
    return 'поймали внутри';
  }
}

async function withAwait() {
  try {
    return await failLater(); // ошибка бросается здесь, внутри try
  } catch {
    return 'поймали внутри';
  }
}

noAwait().catch((e) => console.log('снаружи:', e.message)); // снаружи: поздняя ошибка
withAwait().then(console.log); // поймали внутри
```

## Последовательно и параллельно

Самая частая потеря производительности — `await` для независимых операций друг за другом. Каждый следующий `await` ждёт завершения предыдущего:

```js
async function sequential() {
  const a = await delay(30, 'a'); // ждём 30 мс
  const b = await delay(30, 'b'); // потом ещё 30 мс
  return [a, b]; // всего около 60 мс
}

async function parallel() {
  const [a, b] = await Promise.all([delay(30, 'a'), delay(30, 'b')]);
  return [a, b]; // около 30 мс
}
```

Если шаги зависят друг от друга, последовательность оправдана. Если нет, стартуйте операции вместе, а ждите их результатов вместе через `Promise.all`. Другой вариант: запустить обе операции, сохранить промисы в переменные и только потом `await` каждую.

## Циклы и await

В цикле `for..of`, `for` и `while` `await` работает ожидаемо: итерации выполняются по очереди.

```js
async function doubleAll(items) {
  const out = [];
  for (const x of items) {
    await delay(2);
    out.push(x * 2);
  }
  return out;
}

doubleAll([1, 2, 3]).then(console.log); // [ 2, 4, 6 ]
```

А вот `forEach`, `map` и подобные методы не знают об `async`: колбэк возвращает промис, а метод его игнорирует. Код после `forEach` не дождётся ни одной итерации:

```js
async function trap() {
  const out = [];
  [1, 2, 3].forEach(async (x) => {
    await delay(5);
    out.push(x);
  });
  return out.length; // 0, ни одна итерация ещё не закончила
}

trap().then(console.log); // 0
```

Для параллельной обработки используйте `Promise.all(items.map(async (x) => ...))`, для последовательной — обычный `for..of`.

## Вызов async из обычного кода

Результат вызова `async`-функции — промис, поэтому из обычной функции надо работать с ним через `then`/`catch`. Если вы забыли `await` внутри `async`-функции, вы получите промис вместо значения:

```js
async function forgot() {
  const p = delay(5, 'x'); // без await
  return typeof p;
}

forgot().then(console.log); // object
```

Это источник тихих багов: условие `if (promise)` всегда истинно, а сравнение с промисом даёт не то, что вы ожидали.

## Типичные ошибки

- Забыть `await`: вместо значения получить промис, а необработанные отклонения всплывают позже.
- Использовать `await` в обычной функции или в `forEach`-колбэке без `async`.
- Последовательные `await` для независимых запросов вместо `Promise.all`.
- Ожидать, что `forEach(async ...)` дождётся завершения.
- Вернуть промис из `try` без `await`, рассчитывая на `catch` рядом.
- Игнорировать ошибки: вызвать `async`-функцию и не обработать её отклонение (в Node.js это `unhandledRejection`).

## Коротко

- `async function` всегда возвращает промис; `return x` выполняет его значением `x`, `throw` отклоняет.
- `await` приостанавливает async-функцию до завершения промиса и возвращает значение либо бросает ошибку; продолжение — микрозадача.
- Ошибки ловятся через `try..catch`; чтобы поймать отклонение возвращаемого промиса, нужен `return await`.
- Независимые операции запускайте параллельно через `Promise.all`.
- В `forEach` и `map` `await` не работает «как в цикле»: используйте `for..of` или `Promise.all`.
