# Строгий режим

JavaScript развивается с обратной совместимостью: старый код продолжает работать, даже если в нём остались странности. Чтобы можно было исправлять ошибки языка, не ломая старые сайты, в стандарте ES5 появился **строгий режим** — выбор в пользу более безопасных правил.

## Как включить

Строгий режим включается директивой `'use strict'` (или `"use strict"`). Она должна быть **первой инструкцией** скрипта или функции — перед ней разрешены только комментарии:

```js
'use strict';

// дальше весь скрипт выполняется в строгом режиме
```

Если поставить директиву внутрь функции, строгим станет только тело этой функции:

```js
function strictOne() {
  'use strict';
  return this === undefined;
}
function looseOne() {
  return this === undefined;
}
console.log(strictOne(), looseOne()); // true false
```

Если перед директивой стоит другая инструкция, это уже не директива, а обычная строка, и режим не включится. Выключить строгий режим после включения нельзя.

```js
console.log('привет');
'use strict'; // не директива: стоит не первой
```

## Что меняется

Самое заметное изменение — **присвоение необъявленной переменной**. В обычном режиме оно тихо создаёт глобальную переменную, а опечатка в имени превращается в трудноуловимую ошибку. В строгом — это ошибка:

```js
function loose() {
  counter = 5; // создаёт глобальную переменную
  return typeof counter;
}
function strict() {
  'use strict';
  try {
    counter2 = 5;
  } catch (error) {
    return error.name + ': ' + error.message;
  }
}
console.log(loose());  // number
console.log(strict()); // ReferenceError: counter2 is not defined
```

Другие отличия:

- при обычном вызове функции `this` равен `undefined`, а не глобальному объекту;
- запись в свойство, доступное только для чтения (например, у замороженного объекта), выбрасывает `TypeError`, а не молча игнорируется;
- повтор имён параметров (`function f(a, a)`) — синтаксическая ошибка;
- восьмеричные литералы вида `010` запрещены;
- часть слов (например, `public`, `interface`) зарезервирована для будущего.

```js
const frozen = Object.freeze({ a: 1 });
frozen.a = 2;          // в обычном режиме молча ничего не делает
console.log(frozen.a); // 1

function tryWrite() {
  'use strict';
  try {
    frozen.a = 2;
  } catch (error) {
    return error.name;
  }
}
console.log(tryWrite()); // TypeError
```

## Нужно ли писать директиву

В современном коде строгий режим чаще всего включён автоматически:

- в **ES-модулях** (файлы с `import`/`export`);
- в теле **классов**.

Остальной код — обычные скрипты и файлы Node.js в формате CommonJS — выполняется в нестрогом режиме, если директивы нет. Поэтому для скриптов её по-прежнему стоит ставить.

## Типичные ошибки

- Поставить `'use strict'` не первой строкой: она молча перестаёт работать.
- Ожидать, что директива в одной функции повлияет на соседние.
- Забыть объявить переменную цикла или счётчика и получить `ReferenceError` — это не вина режима, а выявленный им баг.
- Полагаться на то, что в обычной функции `this` указывает на глобальный объект.

## Коротко

- `'use strict'` включает безопасные правила для скрипта или функции.
- Директива работает только в начале скрипта или тела функции.
- Присвоение необъявленной переменной в строгом режиме — `ReferenceError`.
- Модули и классы строгие по умолчанию.
