# Цепочка промисов

Главное преимущество промисов перед колбэками — их можно соединять в цепочки. Вместо «пирамиды» вложенных функций получается плоский список шагов, где каждый следующий получает результат предыдущего. Чтобы цепочки работали предсказуемо, нужно понять одну идею: **`then` всегда возвращает новый промис**.

## Результат передаётся дальше

Обработчик `then` может вернуть значение, и оно станет результатом нового промиса, который вернул сам `then`. Следующий `then` в цепочке получит это значение:

```js
Promise.resolve(1)
  .then((v) => {
    console.log(v); // 1
    return v * 2;
  })
  .then((v) => {
    console.log(v); // 2
    return v * 2;
  })
  .then((v) => {
    console.log(v); // 4
  });
```

Если обработчик ничего не вернул, следующий получит `undefined`:

```js
Promise.resolve(1)
  .then((v) => {
    v * 5; // забыли return
  })
  .then((v) => console.log(v)); // undefined
```

Забытый `return` — самая частая ошибка в цепочках: значение «теряется», а дальше появляется `undefined` в самых неожиданных местах.

## Это не то же самое, что несколько then на одном промисе

Цепочка означает `p.then(...).then(...)`: каждый шаг получает результат предыдущего. А вот несколько вызовов `then` на **одном и том же** промисе — это независимые обработчики, каждый из которых получает *исходное* значение:

```js
const p = Promise.resolve(1);
p.then((v) => {
  console.log('A', v); // A 1
  return v + 1;
});
p.then((v) => {
  console.log('B', v); // B 1
  return v + 1;
});
```

Здесь `B` получает `1`, а не `2`: возвращаемое значение первого `then` никому не передаётся, ведь это не цепочка. Это сильно сбивает с толку тех, кто пришёл из мира колбэков.

## Возврат промиса из обработчика

Самое важное свойство: если обработчик возвращает **промис**, цепочка *дожидается* его, и следующий `then` получит уже его результат, а не сам промис. Благодаря этому асинхронные шаги выстраиваются друг за другом:

```js
const delay = (ms, value) => new Promise((resolve) => setTimeout(() => resolve(value), ms));

delay(10, 'первый')
  .then((v) => {
    console.log(v); // первый
    return delay(10, 'второй');
  })
  .then((v) => {
    console.log(v); // второй
    return 'третий'; // обычное значение тоже подходит
  })
  .then((v) => console.log(v)); // третий
```

Так выглядит последовательная загрузка: пользователь, потом его записи, потом комментарии. Каждый шаг — функция, возвращающая промис, и их можно просто подставлять в цепочку:

```js
function getUser(id) {
  return delay(5, { id, name: 'U' + id });
}

function getPosts(user) {
  return delay(5, [user.name + ':p1', user.name + ':p2']);
}

getUser(1)
  .then(getPosts)
  .then((posts) => console.log(posts)); // [ 'U1:p1', 'U1:p2' ]
```

Если нужно использовать данные с предыдущих шагов, вкладывайте продолжение внутрь обработчика (получится ограниченная вложенность) или копите результаты в объекте. Бездумно вкладывать `then` в `then` — значит вернуться к пирамиде.

## Thenable

Промисом для цепочки считается любой объект с методом `then`. Если обработчик вернёт такой объект, цепочка вызовет его `then` и дождётся `resolve`:

```js
const thenable = {
  then(resolve) {
    setTimeout(() => resolve('thenable!'), 5);
  },
};

Promise.resolve(1)
  .then(() => thenable)
  .then((v) => console.log(v)); // thenable!
```

Это нужно для совместимости с библиотеками, у которых были свои «промисоподобные» объекты до появления стандартных.

## Что случается с ошибкой и пропуском обработчика

Если в обработчике `then` брошено исключение или возвращён отклонённый промис, то новый промис отклоняется, а следующие `then` без обработчика ошибки **пропускаются**, пока не встретится `catch`:

```js
Promise.resolve('a')
  .then(() => {
    throw new Error('boom');
  })
  .then(() => console.log('пропущено'))
  .catch((e) => console.log('поймали', e.message)) // поймали boom
  .then(() => console.log('цепочка продолжилась')); // цепочка продолжилась
```

После `catch` цепочка снова становится «зелёной»: если `catch` вернул значение, оно уйдёт в следующий `then`. Подробнее об ошибках — в следующем уроке.

Если в `then` передан не функция (`undefined`, `null`, число), то обработчик просто пропускается, а результат проходит дальше без изменений:

```js
Promise.resolve(3)
  .then(null)
  .then(5)
  .then((v) => console.log(v)); // 3
```

## then(a, b) и then(a).catch(b)

Это не одно и то же. Во втором варианте `catch` поймает ещё и ошибку, брошенную внутри `a`, а в `then(a, b)` обработчик `b` обслуживает только предыдущий промис: ошибка из `a` в тот же `then` не попадёт.

```js
const bad = Promise.resolve(1);

bad.then(
  () => {
    throw new Error('в обработчике успеха');
  },
  () => console.log('b'), // не сработает
).catch((e) => console.log('поймано ниже:', e.message));
// поймано ниже: в обработчике успеха
```

## Типичные ошибки

- Забыть `return` внутри `then`: следующий шаг получит `undefined`.
- Вместо цепочки навесить `then` несколько раз на один промис, ожидая «пробрасывания» результата.
- Начать новую цепочку внутри обработчика и не вернуть её: внешняя цепочка не дождётся внутренней, а ошибки внутренней останутся необработанными.
- Вкладывать `then` в `then` вместо плоской цепочки.
- Создавать лишний `new Promise` вокруг того, что уже возвращает промис (если функция уже даёт промис, возвращайте его как есть).

## Коротко

- `then` всегда возвращает новый промис; возвращённое из обработчика значение становится его результатом.
- Если вернуть промис (или thenable), цепочка дождётся его результата.
- Несколько `then` на одном промисе — независимые обработчики, а не цепочка.
- Без `return` следующий шаг получит `undefined`.
- Ошибка проходит по цепочке до ближайшего `catch` (или второго аргумента `then`), пропуская `then` без обработчика ошибки.
