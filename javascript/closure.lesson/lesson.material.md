# Область видимости и замыкания

Функции в JavaScript — полноценные значения: их можно создавать внутри других функций, возвращать и передавать. Из-за этого возникает вопрос: откуда внутренняя функция берёт переменные, когда её вызывают позже и совсем в другом месте? Ответ — **замыкание**: функция запоминает окружение, в котором была создана. Эта тема — основа для счётчиков, фабрик функций, мемоизации и приватных данных.

## Блоки и область видимости

Переменные `let` и `const` видны только внутри блока `{ ... }`, в котором объявлены: это тело `if`, цикла, функции или просто пара фигурных скобок.

```js
let x = 'снаружи';
{
  let x = 'внутри';
}
console.log(x); // снаружи
```

Переменная внутреннего блока может «затенять» одноимённую внешнюю: поиск идёт от ближайшего блока наружу.

Цикл `for (let i = 0; ...)` создаёт переменную `i` на каждую итерацию заново: это важно для замыканий (см. ниже). `function`-объявление внутри блока в строгом режиме тоже видно только в этом блоке; в нестрогом режиме у такого объявления есть исторические странности, поэтому функции внутри `if` лучше не объявлять, а присваивать переменной выражением.

## Лексическое окружение

Когда движок запускает скрипт, функцию или блок, он создаёт скрытый объект — **лексическое окружение**. У него две части:

1. **Environment Record** — таблица «имя переменной → значение»;
2. **ссылка на внешнее окружение** — то, внутри которого окружение создано.

Поиск имени идёт по цепочке: сначала в текущем окружении, потом во внешнем, и так до глобального. Если имени нигде нет — `ReferenceError`.

Любая функция при создании получает скрытое свойство `[[Environment]]` — ссылку на окружение, где она появилась. Именно по нему при вызове строится цепочка поиска. Это и есть замыкание: функция «несёт с собой» своё место рождения, а не место вызова.

```js
let v = 'глобальная';

function f() {
  return v;
}
function h() {
  let v = 'локальная в h';
  return f(); // f создана снаружи, h для неё не внешняя
}

console.log(h()); // глобальная
```

Такая модель называется **лексической областью видимости**: что видит функция, определяется местом в тексте программы, а не стеком вызовов.

## Переменные «живые»

Функция обращается к переменной в момент вызова и видит её **текущее** значение, а не копию на момент создания:

```js
let name = 'Анна';

function sayHi() {
  return 'Привет, ' + name;
}

name = 'Борис';
console.log(sayHi()); // Привет, Борис
```

Каждый вызов функции создаёт **новое** окружение со своими локальными переменными. Поэтому счётчики, созданные одной фабрикой, независимы:

```js
function makeCounter() {
  let count = 0;
  return () => ++count;
}

const a = makeCounter();
const b = makeCounter();
console.log(a(), a(), b(), a()); // 1 2 1 3
```

После выхода из `makeCounter` её окружение не пропадает: на него ссылается `[[Environment]]` возвращённой функции, а пока есть достижимая ссылка, сборщик мусора память не освободит. Когда на функцию никто больше не ссылается, вместе с ней освободится и окружение.

## Зона недоступности (TDZ)

Переменная `let`/`const` существует в окружении с самого начала блока, но до строки объявления находится в «мёртвой зоне»: обращение к ней — `ReferenceError`. Из-за этого локальная переменная не «просвечивает» внешнюю одноимённую:

```js
let x = 1;
function g() {
  console.log(x); // ReferenceError: Cannot access 'x' before initialization
  let x = 2;
}
g();
```

## Замыкания в циклах

Благодаря тому, что `for (let ...)` делает новую `i` на каждый шаг, функции, созданные в теле цикла, запоминают каждая своё значение:

```js
const fns = [];
for (let i = 0; i < 3; i++) {
  fns.push(() => i);
}
console.log(fns.map((fn) => fn())); // [ 0, 1, 2 ]
```

Если же счётчик объявлен снаружи цикла (общая переменная на всех), все функции увидят одно и то же итоговое значение — так работает, например, `while` с внешней `let i`. Исправление: завести переменную внутри тела цикла (`const j = i;`) и замкнуть её.

## Частые приёмы

**Фабрика функций.** Окружение хранит настройки:

```js
const sum = (a) => (b) => a + b;
console.log(sum(1)(2)); // 3
```

**Приватное состояние.** Переменная недоступна снаружи, но видна методам:

```js
function createCounter() {
  let n = 0;
  return { up: () => ++n, down: () => --n };
}
const c = createCounter();
c.up();
c.up();
console.log(c.down()); // 1
console.log(createCounter().down()); // -1
```

**Параметризованные функции для методов массива** — `arr.filter(inBetween(3, 6))`, `arr.sort(byField('age'))`: функция-фабрика запоминает границы или имя поля.

## Типичные ошибки

- Считать, что замыкание хранит **значение** переменной. Оно хранит **ссылку на окружение**, поэтому видит последние изменения.
- Ждать, что две разные фабричные функции делят состояние: у каждого вызова фабрики своё окружение.
- Забыть про TDZ: объявить `let` ниже по блоку, чем используется.
- Объявлять функцию внутри `if` и вызывать её снаружи — результат зависит от режима (строгий/нестрогий).
- Удерживать в замыкании большие данные дольше нужного: пока функция достижима, окружение живёт.

## Коротко

- `let`/`const` ограничены блоком; поиск имён идёт от внутреннего окружения к внешнему.
- Функция запоминает окружение места создания (`[[Environment]]`), а не места вызова.
- Окружение «живое»: функция видит текущие значения внешних переменных.
- Каждый вызов функции создаёт новое окружение — отсюда независимые счётчики.
- `for (let i ...)` даёт новую `i` на каждой итерации — замыкания в цикле работают как ожидается.
