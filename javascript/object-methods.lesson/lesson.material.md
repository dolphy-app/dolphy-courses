# Методы объекта и this

Объекты обычно описывают сущности: пользователя, заказ, корзину. Но у сущности есть не только данные, но и действия: войти, оплатить, добавить товар. В JavaScript действия — это функции, лежащие в свойствах объекта. Здесь мы научимся их создавать и разберёмся со словом `this`, которое устроено в JavaScript необычно и является источником множества ошибок.

## Что такое метод

Функция, сохранённая в свойстве объекта, называется *методом*. Создать её можно функциональным выражением:

```js
const user = { name: 'Анна', age: 30 };

user.sayHi = function () {
  return 'Привет!';
};

console.log(user.sayHi()); // Привет!
```

Можно и взять заранее объявленную функцию:

```js
function sayHi() {
  return 'Привет!';
}

const user = {};
user.sayHi = sayHi;      // скобок нет: передаём саму функцию, а не вызываем её
console.log(user.sayHi()); // Привет!
```

Стиль, когда программа строится из объектов, которые хранят данные и умеют выполнять действия, называют объектно-ориентированным программированием (ООП).

### Сокращённая запись

В литерале объекта слово `function` и двоеточие можно опустить:

```js
const longForm = {
  sayHi: function () { return 'Привет'; },
};

const shortForm = {
  sayHi() { return 'Привет'; },    // то же самое, но короче
};
```

Записи не полностью равноценны: метод в сокращённой форме не может быть вызван с `new` и имеет доступ к `super` (о нём — в разделе про наследование). Для обычных методов это неважно, поэтому почти всегда используют короткую запись:

```js
const shortForm = { sayHi() {} };
try {
  new shortForm.sayHi();
} catch (e) {
  console.log(e.message); // shortForm.sayHi is not a constructor
}
```

## `this` внутри метода

Методу обычно нужны данные из «своего» объекта. Для этого служит ключевое слово `this`. Его значение — объект, *стоящий перед точкой* при вызове метода.

```js
const user = {
  name: 'Анна',
  sayHi() {
    return 'Привет, ' + this.name; // this — это user
  },
};

console.log(user.sayHi()); // Привет, Анна
```

Можно было бы обратиться к объекту по имени переменной (`user.name`), но это ненадёжно. Пусть ссылку скопировали, а исходную переменную затёрли:

```js
let user = {
  name: 'Анна',
  sayHi() {
    return 'Привет, ' + user.name; // жёсткая привязка к имени переменной
  },
};

const admin = user;
user = null;

try {
  admin.sayHi();
} catch (e) {
  console.log(e.message); // Cannot read properties of null (reading 'name')
}
```

Если бы метод использовал `this.name`, вызов `admin.sayHi()` отработал бы без ошибки: `this` — это `admin`, то есть тот самый объект.

## `this` не привязан к объекту

Во многих языках `this` жёстко связан с объектом, в котором объявлен метод. В JavaScript это не так: `this` вычисляется в момент *вызова* и зависит только от того, как вызвали функцию. Использовать `this` можно в любой функции, даже той, что не принадлежит объекту:

```js
function describe() {
  return this.name;
}

const cat = { name: 'Мурка' };
const dog = { name: 'Шарик' };

cat.say = describe;     // одна и та же функция в двух объектах
dog.say = describe;

console.log(cat.say());     // Мурка (this === cat)
console.log(dog.say());     // Шарик (this === dog)
console.log(dog['say']());  // Шарик — с квадратными скобками то же самое
```

Правило: при вызове `obj.method()` внутри `method` значение `this` равно `obj`. Сама функция `describe` не знает, кому она принадлежит; всё решает запись вызова.

С одной стороны, это даёт гибкость: одну функцию можно использовать как метод разных объектов. С другой — легко ошибиться, как показывает следующий раздел.

### Вызов без объекта

Если функцию вызвать без «точки», то объекта перед точкой нет. В строгом режиме (`'use strict'`) `this` тогда равен `undefined`, и обращение `this.name` приводит к ошибке. В нестрогом режиме `this` — глобальный объект (в браузере `window`, в Node.js `globalThis`), и ошибки не будет, но будет `undefined` вместо имени: это историческое поведение, которое строгий режим исправил. Код в модулях и классах всегда строгий.

```js
'use strict';

const user = {
  name: 'Анна',
  sayHi() {
    return 'Привет, ' + this.name;
  },
};

const f = user.sayHi;  // взяли функцию из объекта
try {
  f();                 // вызываем без объекта
} catch (e) {
  console.log(e.message); // Cannot read properties of undefined (reading 'name')
}
```

Это называют «потерей `this`». Она случается, когда метод передают как значение: в `setTimeout(user.sayHi, 1000)`, в обработчик события или в другую функцию. Способы борьбы (`bind`, стрелочные обёртки) вы изучите позже; пока запомните, что `user.sayHi` и `user.sayHi()` — совершенно разные выражения: в первом метод только извлекается, во втором вызывается с `this === user`.

### `this` в литерале объекта

Объектный литерал `{...}` *не создаёт* своего `this`. В выражении `ref: this` берётся `this` из окружающего кода — в данном случае из функции `makeUser`:

```js
'use strict';

function makeUser() {
  return {
    name: 'John',
    ref: this,           // this функции makeUser, а не нового объекта
  };
}

try {
  makeUser().ref.name;   // makeUser вызвана без объекта → this === undefined
} catch (e) {
  console.log(e.message); // Cannot read properties of undefined (reading 'name')
}
```

А вот так всё работает, потому что `ref` — метод, и `this` вычисляется при его вызове:

```js
function makeUser() {
  return {
    name: 'John',
    ref() { return this; },
  };
}

console.log(makeUser().ref().name); // John
```

## Стрелочные функции и `this`

У стрелочных функций нет собственного `this`. Обращаясь к `this`, они берут его из внешней обычной функции — той, внутри которой созданы. Это удобно, когда внутри метода нужна небольшая вспомогательная функция, которая «видит» тот же `this`:

```js
'use strict';

const user = {
  firstName: 'Илья',
  run() {
    const arrow = () => this.firstName;       // this — из run()
    function plain() { return this === undefined; } // свой this
    return [arrow(), plain()];
  },
};

console.log(user.run()); // [ 'Илья', true ]
```

В обычной вложенной функции `this` определяется её собственным вызовом, а не внешним методом, и в строгом режиме он `undefined`. По этой причине стрелки — обычный выбор для коллбэков внутри методов. Зато стрелку не стоит делать самим методом объекта, если ей нужен `this` этого объекта.

## Цепочки вызовов

Если метод ничего полезного не возвращает, ему можно вернуть `this`. Тогда вызовы выстраиваются в цепочку — приём, на котором построены многие библиотеки:

```js
const ladder = {
  step: 0,
  up() { this.step++; return this; },
  down() { this.step--; return this; },
  show() { console.log(this.step); return this; },
};

ladder.up().up().down().show(); // 1
```

Каждый вызов возвращает тот же объект, и следующий метод вызывается уже у него. Для длинных цепочек по строке на вызов читается лучше:

```js
ladder
  .up()
  .up()
  .show(); // 3
```

## Типичные ошибки

> [!WARNING]
>
> - Обращение к объекту по имени переменной внутри метода вместо `this`.
> - Передача метода как значения (`setTimeout(obj.method, 0)`) и удивление, куда пропал `this`.
> - Мысль, что `this` определяется местом, где функция объявлена. Он определяется способом вызова (кроме стрелок, которые берут его извне).
> - Ожидание, что `this` в объектном литерале указывает на создаваемый объект.
> - Забытый `return this` в методе, который должен участвовать в цепочке: следующее звено получит `undefined`.

## Коротко

> [!TIP]
>
> - Метод — функция, лежащая в свойстве объекта; в литерале его можно записать как `name() { ... }`.
> - `this` внутри метода — объект перед точкой в момент вызова: `obj.method()` → `this === obj`.
> - Значение `this` вычисляется при вызове; одна функция может быть методом нескольких объектов. Вызов без объекта даёт `undefined` в строгом режиме и глобальный объект в нестрогом.
> - У стрелочных функций своего `this` нет, он берётся из внешней функции.
> - Возврат `this` из метода позволяет строить цепочки вызовов.
