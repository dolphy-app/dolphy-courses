# Обработка ошибок: try..catch

Даже хороший код иногда падает: сервер вернул не тот JSON, пользователь ввёл не то, а в переменной оказался `null`. Если ничего не делать, скрипт остановится на первой же ошибке. Конструкция `try..catch` позволяет перехватить ошибку и продолжить работу, а не «умереть» на месте.

## Синтаксис

```js
try {
  // код, в котором может возникнуть ошибка
} catch (error) {
  // что делать, если ошибка возникла
}
```

Работает так: выполняется блок `try`. Если ошибок нет, блок `catch` пропускается. Если на какой-то строке произошла ошибка, остаток `try` **не выполняется**, управление сразу переходит в `catch`, а сама ошибка попадает в переменную `error`.

```js
try {
  console.log('a');
  null.x; // ошибка
  console.log('b'); // не выполнится
} catch (error) {
  console.log('c');
}
// a
// c
```

Важные детали:

- `try..catch` ловит только **выполняемые** ошибки (runtime errors). Синтаксическая ошибка в самом коде (например, лишняя скобка) обнаруживается при разборе и до выполнения `try` дело не доходит.
- Конструкция работает **синхронно**. Если внутри `try` вы вызвали `setTimeout(callback, 0)`, то ошибка внутри `callback` случится позже, когда `try..catch` уже закончится, и не будет перехвачена. Для асинхронного кода нужен `try..catch` внутри самой функции-колбэка — позже вы увидите ещё и способы для промисов.
- Блок `catch` можно записать без переменной, если сама ошибка не нужна: `catch { ... }`.

## Объект ошибки

Когда ошибка возникает, JavaScript создаёт объект с описанием. У него есть главные свойства:

| Свойство | Что содержит |
|---|---|
| `name` | имя типа ошибки, например `"TypeError"` |
| `message` | текстовое описание |
| `stack` | строка со стеком вызовов (нестандартное, но есть везде) |

```js
try {
  undefinedVar;
} catch (e) {
  console.log(e.name); // ReferenceError
  console.log(e.message); // undefinedVar is not defined
}

try {
  null.x;
} catch (e) {
  console.log(e.name); // TypeError
}
```

Самые частые встроенные типы: `ReferenceError` (обращение к необъявленной переменной), `TypeError` (значение не того типа: вызвали не функцию, прочитали свойство у `null`), `SyntaxError` (например, `JSON.parse` получил некорректный JSON), `RangeError` (значение вне допустимого диапазона, скажем `new Array(-1)`). Тексты `message` зависят от движка и версии, поэтому в коде опирайтесь на `name` или `instanceof`, а не на точный текст.

## Зачем это нужно: разбор JSON

Классический пример — данные, которые приходят снаружи и могут оказаться некорректными:

```js
function readUser(json) {
  try {
    return JSON.parse(json);
  } catch {
    return null; // некорректные данные — «нет пользователя»
  }
}

console.log(readUser('{"name":"Ann"}')); // { name: 'Ann' }
console.log(readUser('{oops')); // null
```

## Генерация ошибок: throw

Оператор `throw` бросает ошибку сам. Технически бросить можно что угодно, даже число, но принято бросать объекты `Error` или его наследников: у них есть `stack` и понятное имя.

```js
function parseUser(json) {
  const user = JSON.parse(json);
  if (!user.name) {
    throw new SyntaxError('У пользователя нет имени');
  }
  return user;
}

try {
  parseUser('{"age": 30}');
} catch (e) {
  console.log(e.name + ': ' + e.message); // SyntaxError: У пользователя нет имени
}
```

Данные формально корректны как JSON, но не годятся для нашей задачи, поэтому мы сами объявляем это ошибкой. Выбор типа — дело смысла: `TypeError` для неверного типа аргумента, `RangeError` для значения вне допустимых границ, свои классы — в следующем уроке.

## Проброс исключений

Блок `catch` ловит **все** ошибки из `try`, в том числе неожиданные: опечатку, `null` там, где его не ждали. Если вы ожидали только «плохой JSON», а поймали `TypeError` из-за бага, молча проглотить её значит спрятать баг. Правило: обрабатывайте то, что знаете, остальное **пробрасывайте** дальше через `throw`.

```js
function parse(json) {
  try {
    return JSON.parse(json);
  } catch (e) {
    if (e instanceof SyntaxError) {
      return null; // знакомая ситуация
    }
    throw e; // незнакомая — пусть узнает тот, кто выше
  }
}

console.log(parse('{x')); // null
```

Проброшенная ошибка уйдёт в ближайший внешний `try..catch`, а если такого нет, скрипт аварийно завершится (в Node.js) с выводом стека — это как раз то, что нужно при настоящем баге.

## finally

Необязательный блок `finally` выполняется **всегда**: и после успешного `try`, и после `catch`, и даже если из `try` или `catch` сделан `return`, `break` или `continue`.

```js
function f() {
  try {
    return 'try';
  } finally {
    console.log('finally');
  }
}

console.log(f());
// finally
// try
```

Сначала выполняется `finally`, потом функция возвращает значение. Типичное применение — «убрать за собой»: закрыть ресурс, сбросить флаг «идёт загрузка», остановить таймер — независимо от исхода.

Неожиданность: если `finally` сам делает `return`, он **перебивает** результат `try`/`catch` и даже подавляет брошенную ошибку.

```js
function g() {
  try {
    return 'try';
  } finally {
    return 'finally';
  }
}

console.log(g()); // finally
```

Поэтому `return` в `finally` обычно не пишут. Блок `finally` можно использовать и без `catch`: ошибка тогда пойдёт дальше, но очистка всё равно произойдёт.

## Глобальный перехват

Если ошибка не поймана нигде, её увидит окружение. В Node.js для этого есть событие `process.on('uncaughtException', ...)`, в браузере — `window.onerror`. Это способ **записать** ошибку в журнал перед падением, а не способ продолжить работу как ни в чём не бывало.

## Типичные ошибки

- Обернуть в `try` весь код подряд. Тогда любая ошибка превращается в «что-то пошло не так», и найти причину трудно. Оборачивайте только то, что действительно может упасть и что вы умеете обработать.
- Пустой `catch {}`: ошибка исчезает без следа.
- Ожидать, что `try..catch` поймает ошибку из `setTimeout` или из колбэка, который вызовется позже.
- Опираться на точный текст `message`: он отличается между движками и версиями.
- Писать `return` в `finally` и случайно терять ошибку или результат.

## Коротко

- `try..catch` перехватывает ошибки времени выполнения в **синхронном** коде; при ошибке остаток `try` пропускается.
- В объекте ошибки смотрите на `name`, `message`, `stack`; ветвитесь по `instanceof` или `name`, не по тексту.
- `throw` бросает любое значение, но лучше `Error` и его наследников.
- Обработали то, что ожидали, остальное пробросьте обратно через `throw`.
- `finally` выполняется всегда, его `return` перебивает остальные.
