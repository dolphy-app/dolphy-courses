# Промисификация

Большая часть старых и системных API живёт на колбэках: `fs.readFile`, `setTimeout`, множество сторонних библиотек. Промисы удобнее, а `async/await` ещё удобнее, но они работают только с промисами. Промисификация — это превращение функции, принимающей колбэк, в функцию, возвращающую промис. Делается она за несколько строк и часто пригождается на границе «старый код — новый код».

## Идея

Пусть есть функция в стиле Node.js: последним аргументом принимает колбэк `(err, result)`.

```js
function loadData(id, callback) {
  setTimeout(() => {
    if (id > 0) {
      callback(null, { id });
    } else {
      callback(new Error('bad id'));
    }
  }, 5);
}
```

Создадим вручную её промис-версию. Внутрь нового промиса помещаем вызов оригинала, а в качестве колбэка передаём функцию, которая либо отклоняет промис ошибкой, либо выполняет его результатом:

```js
function loadDataP(id) {
  return new Promise((resolve, reject) => {
    loadData(id, (err, result) => {
      if (err) reject(err);
      else resolve(result);
    });
  });
}

loadDataP(1).then((data) => console.log(data)); // { id: 1 }
loadDataP(-1).catch((e) => console.log(e.message)); // bad id
```

Теперь к этой функции применимы цепочки, `Promise.all` и `await`. Ключевая мысль: **колбэк вызывается ровно один раз**, и это ровно то, что нужно промису, который тоже завершается один раз. Повторные вызовы колбэка промис просто игнорирует.

## Универсальная обёртка

Писать такую обёртку для каждой функции незачем. Напишем вспомогательную функцию `promisify(f)`, которая принимает функцию с колбэком и возвращает промис-версию:

```js
function promisify(f) {
  return function (...args) {
    return new Promise((resolve, reject) => {
      function callback(err, result) {
        if (err) reject(err);
        else resolve(result);
      }
      args.push(callback); // колбэк — последний аргумент
      f.call(this, ...args);
    });
  };
}

const loadDataP = promisify(loadData);
loadDataP(1).then(console.log); // { id: 1 }
```

Обратите внимание на `f.call(this, ...args)`. Если промисифицировать метод объекта, ему нужен правильный `this`. Если `this` потерять, метод может упасть:

```js
const obj = {
  base: 10,
  calc(x, callback) {
    setTimeout(() => callback(null, this.base + x), 1);
  },
};

obj.calcP = promisify(obj.calc);
obj.calcP(5).then((v) => console.log(v)); // 15
```

Здесь обёртка вызывается как `obj.calcP(...)`, поэтому `this` внутри равен `obj` и передаётся дальше.

## Когда колбэк получает несколько значений

Иногда колбэк вызывается как `callback(err, a, b)`. Промис выполняется одним значением, поэтому лишнее приходится собирать в массив. Расширим обёртку необязательным флагом:

```js
function promisify(f, manyArgs = false) {
  return function (...args) {
    return new Promise((resolve, reject) => {
      args.push((err, ...results) => {
        if (err) reject(err);
        else resolve(manyArgs ? results : results[0]);
      });
      f.call(this, ...args);
    });
  };
}

function twoResults(callback) {
  setTimeout(() => callback(null, 'a', 'b'), 1);
}

promisify(twoResults, true)().then(console.log); // [ 'a', 'b' ]
promisify(twoResults)().then(console.log); // a
```

Без флага остальные значения теряются — это нужно учитывать, прежде чем промисифицировать функцию, которая возвращает больше одного результата.

## Готовые решения

В Node.js промисификация уже есть в стандартной библиотеке: `util.promisify(fn)` делает ровно то же самое для error-first колбэков, а многие модули (`fs/promises`, `timers/promises`) сразу предлагают промис-версии API. В примерах этого курса нет доступа к `require` и `import`, поэтому мы пишем обёртку сами, но в проекте на Node.js используйте готовое, а свои обёртки оставляйте для случаев, когда стандартной нет.

```js
// в обычном скрипте Node.js
import { promisify } from 'node:util';

const loadDataP = promisify(loadData);
```

Обратное преобразование тоже возможно (`util.callbackify`), но встречается редко.

## Что промисификация не умеет

- **События и повторяющиеся колбэки.** `setInterval` или `emitter.on('data', cb)` вызывают колбэк много раз, а промис завершается один раз. Промисифицировать можно только операции с *единственным* результатом.
- **Колбэки с другим порядком аргументов.** Если ошибка не первая (`callback(result, err)`) или формат другой, нужна своя обёртка, а не универсальная.
- **Колбэки без ошибки** (`callback(result)`): их нужно выполнить, а не проверять `err`; для них также пишут отдельную обёртку.

Ещё одна тонкость: проверка `if (err)` смотрит на «истинность». Если API вызовет `callback(0, 'x')`, это будет считаться успехом. Для Node.js-стиля это нормально (ошибки — объекты), но для нестандартных API стоит проверить.

## Типичные ошибки

- Передать в `reject` не ошибку, а строку или `undefined`.
- Забыть вызвать `reject`/`resolve` на одной из веток: промис остаётся в ожидании навсегда.
- Забыть про `this` при промисификации методов.
- Промисифицировать функцию, которая вызывает колбэк несколько раз: первый результат выигрывает, остальные теряются.
- Не заметить, что колбэк получает несколько результатов, и потерять все, кроме первого.
- Вернуть результат оригинальной функции вместо промиса: оригинал с колбэком обычно возвращает `undefined`.

## Коротко

- Промисификация превращает функцию с колбэком `(err, result)` в функцию, возвращающую промис: ошибка → `reject`, результат → `resolve`.
- Универсальная обёртка принимает функцию, добавляет свой колбэк последним аргументом и вызывает оригинал, сохраняя `this`.
- Несколько значений в колбэке придётся собрать в массив, иначе останется только первое.
- Подходит только для операций с единственным результатом.
- В Node.js есть `util.promisify` и модули `fs/promises`, `timers/promises`.
