# Приватные и защищённые свойства

Один из принципов объектно-ориентированного программирования — **инкапсуляция**: объект показывает наружу небольшой понятный интерфейс, а детали реализации прячет. Так внутренности можно менять, не ломая тех, кто пользуется классом. В уроке — три уровня доступа, соглашение о «защищённых» полях и настоящие приватные члены `#name`.

## Внутренний и внешний интерфейс

У кофемашины снаружи — кнопки, внутри — насос и нагреватель. Пользователю не нужно знать, как они устроены, и он не должен их трогать. Применительно к классам:

- **публичные** свойства и методы — внешний интерфейс, доступны всем;
- **приватные** — только внутри самого класса;
- **защищённые** — внутри класса и его наследников (в JavaScript такой уровень не встроен в язык и реализуется соглашением).

## Защищённые поля по соглашению

Распространённая договорённость: имя поля, которое не предназначено для внешнего использования, начинают с подчёркивания. Язык при этом никак не защищает: это просто пометка «руками не трогать».

```js
class CoffeeMachine {
  _waterAmount = 0;

  set waterAmount(value) {
    if (value < 0) {
      value = 0;
    }
    this._waterAmount = value;
  }

  get waterAmount() {
    return this._waterAmount;
  }

  constructor(power) {
    this._power = power;
  }

  get power() {
    return this._power;
  }
}

const machine = new CoffeeMachine(100);
machine.waterAmount = -10;

console.log(machine.waterAmount); // 0
console.log(machine.power); // 100
machine.power = 500;
console.log(machine.power); // 100
```

Свойство `power` только для чтения: есть геттер, а сеттера нет. В нестрогом режиме запись молча игнорируется; внутри модулей и в классах (строгий режим) была бы ошибка `TypeError`. Наследники `CoffeeMachine` могут обращаться к `_waterAmount` — по договорённости.

Вместо пары `get/set` иногда делают единые методы `getWaterAmount()` / `setWaterAmount()`. Это длиннее, зато можно принимать несколько аргументов. А геттеры/сеттеры выглядят как обычные поля, что удобно.

## Настоящие приватные члены: #name

Современный стандарт добавил язык-уровневую приватность. Поле или метод, имя которых начинается с `#`, видны **только внутри тела класса**. Снаружи обратиться к ним нельзя вообще, и даже наследники их не получают.

```js
class CoffeeMachine {
  #waterLimit = 200;

  #fixWaterAmount(value) {
    if (value < 0) return 0;
    if (value > this.#waterLimit) return this.#waterLimit;
    return value;
  }

  setWaterAmount(value) {
    this.waterAmount = this.#fixWaterAmount(value);
  }
}

const machine = new CoffeeMachine();
machine.setWaterAmount(500);

console.log(machine.waterAmount); // 200
console.log(machine.waterLimit); // undefined
console.log(Object.keys(machine)); // [ 'waterAmount' ]
```

Попытка прочитать `machine.#waterLimit` вне класса — не просто `undefined`, а синтаксическая ошибка: код даже не запустится. Поэтому в примере выше мы проверяем непривилегированное обращение `machine.waterLimit` (без `#`) — это другое, несуществующее свойство.

Приватные поля не попадают ни в `Object.keys`, ни в `JSON.stringify`, ни в спред, а обратиться к ним через `this['#name']` нельзя: имя с `#` — не строковый ключ, а отдельный механизм.

```js
class Account {
  #balance = 0;
  owner = 'Аня';

  deposit(sum) {
    this.#balance += sum;
    return this;
  }

  get balance() {
    return this.#balance;
  }
}

const acc = new Account().deposit(50).deposit(25);

console.log(acc.balance); // 75
console.log(JSON.stringify(acc)); // {"owner":"Аня"}
console.log({ ...acc }); // { owner: 'Аня' }
console.log(acc['#balance']); // undefined
```

### Приватность и наследование

Приватные члены **не наследуются как поля с именем**: потомок не видит `#x` родителя по этому имени (попытка обратиться — синтаксическая ошибка). Если потомку нужен доступ, родитель предоставляет защищённый метод или геттер.

```js
class Base {
  #secret = 'тайна';
  reveal() {
    return this.#secret;
  }
}
class Child extends Base {
  show() {
    return this.reveal().toUpperCase();
  }
}

console.log(new Child().show()); // ТАЙНА
```

Приватное поле реально лежит в объекте-экземпляре, поэтому метод родителя спокойно работает и для экземпляра потомка.

### Проверка наличия: #x in obj

Оператор `in` умеет проверять приватное имя — это надёжный способ узнать, создан ли объект данным классом (в отличие от `instanceof`, который можно обмануть через смену прототипа).

```js
class Token {
  #id = 1;
  static isToken(value) {
    return #id in value;
  }
}

console.log(Token.isToken(new Token())); // true
console.log(Token.isToken({})); // false
console.log(Token.isToken(Object.create(Token.prototype))); // false
```

Последний случай: объект создан без конструктора, поле `#id` не инициализировано, значит `#id in value` — `false`.

### Приватные статические члены и методы

Приватными бывают статические поля и методы, геттеры/сеттеры: `static #counter`, `#compute() {}`, `get #value() {}`. Правило одно: доступ — только из тела класса.

## Типичные ошибки

- Считать подчёркивание защитой: `obj._x` по-прежнему доступно и изменяемо.
- Пытаться читать `obj.#x` снаружи — `SyntaxError`.
- Ожидать, что `#x` потомка и родителя — одно и то же поле: у каждого класса свои приватные имена, и такие поля не конфликтуют.
- Вызывать приватный метод у объекта, не созданного этим классом: будет `TypeError`.
- Забывать, что при сериализации (`JSON.stringify`) приватные данные не попадают в результат.

## Коротко

- Инкапсуляция — открытый интерфейс снаружи, детали внутри.
- Подчёркивание `_name` — лишь договорённость о «защищённых» членах.
- `#name` — настоящая приватность: доступ только внутри тела класса, снаружи это синтаксическая ошибка.
- Приватные поля не видны в `Object.keys`, `JSON.stringify` и спреде; наследники обращаются к ним через методы родителя.
- `#x in obj` проверяет, прошёл ли объект инициализацию данным классом.
