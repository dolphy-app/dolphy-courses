# Стиль кода

Код читают гораздо чаще, чем пишут: вы сами, коллеги, вы же — через полгода. Единый стиль делает чтение быстрее, а некоторые правила заодно защищают от ошибок. После урока вы будете знать общепринятые соглашения JavaScript, понимать, зачем за ними стоят, и уметь автоматизировать проверку линтером.

Важная оговорка: правил, обязательных для всех, здесь нет. Это договорённости. Главные вопросы при выборе стиля — «что сделает код понятнее?» и «что поможет не ошибиться?».

## Фигурные скобки

В JavaScript принят «египетский» стиль: открывающая скобка стоит на той же строке, что и ключевое слово, перед ней — пробел, закрывающая — на отдельной строке.

```js
function check(n) {
  if (n < 0) {
    return 'отрицательное';
  }
  return 'неотрицательное';
}

console.log(check(-3)); // отрицательное
```

Для однострочных `if` скобки не обязательны, но лучше их ставить. Причина — не в эстетике, а в надёжности. Допустим, вы дописываете строку в ветку без скобок:

```js
const log = [];
const n = 5;

if (n < 0)
  log.push('ошибка: n < 0');
  log.push('выходим'); // отступ обманывает: к if эта строка не относится

console.log(log); // [ 'выходим' ]
```

Отступы в JavaScript ничего не значат, и второй `push` выполняется всегда. С фигурными скобками такой ошибки не бывает. Допустимый компромисс — очень короткий вариант в одну строку, например `if (n < 0) return null;`. Вариант «условие на одной строке, действие на следующей, без скобок» — худший.

## Отступы и пустые строки

Горизонтальные отступы — 2 или 4 пробела (или табуляция): выбирает команда, но внутри проекта всё должно быть одинаково. Пробелы распространены больше.

Вертикальные отступы — пустые строки между логическими блоками. Хорошая функция читается как абзацы: подготовка, основная работа, результат.

```js
function pow(x, n) {
  let result = 1;

  for (let i = 0; i < n; i++) {
    result *= x;
  }

  return result;
}

console.log(pow(2, 10)); // 1024
```

Если вы видите больше десятка строк подряд без единой пустой, то, скорее всего, блок пора разбить или вынести в функцию.

## Длина строки

Длинные горизонтальные строки читать неудобно, глаз теряется. Максимум обычно задают в команде: 80 или 120 символов. Длинное условие разбивают так, чтобы каждое слагаемое стояло на своей строке; строки-шаблоны позволяют переносы внутри самих обратных кавычек.

```js
const user = { age: 20, active: true, banned: false };

if (
  user.age >= 18 &&
  user.active &&
  !user.banned
) {
  console.log('доступ разрешён'); // доступ разрешён
}
```

## Точка с запятой

Ставьте `;` после каждой инструкции. JavaScript умеет вставлять их сам (автоматическая вставка), но делает это не всегда так, как вы ожидали. Классический пример — `return` с переносом строки:

```js
function makeBox(width) {
  return
  {
    width: width
  };
}

console.log(makeBox(1)); // undefined
```

После `return` движок вставляет точку с запятой сразу в конце строки, поэтому функция возвращает `undefined`, а фигурные скобки превращаются в безобидный блок с меткой. Правильно — начинать выражение на той же строке: `return {`. Есть и стили без точек с запятой (например, StandardJS), но они требуют знания всех подводных камней. Если не уверены, ставьте точки с запятой.

## Не накапливайте вложенность

Глубокая вложенность (`if` внутри `if` внутри цикла) заставляет держать в голове много условий. Два приёма помогают её сократить. В цикле — `continue` для пропуска ненужных элементов. В функции — **ранний возврат** (guard clause): исключительные случаи обрабатываем сразу и выходим, дальше идёт основной сценарий без `else`.

```js
function pow(x, n) {
  if (!Number.isInteger(n) || n < 0) {
    throw new RangeError('n должно быть целым и неотрицательным');
  }

  let result = 1;
  for (let i = 0; i < n; i++) {
    result *= x;
  }
  return result;
}

console.log(pow(5, 0)); // 1
```

Вариант с большим блоком `else` ведёт себя так же, но основная логика в нём «уехала» вправо, а ошибочный случай описан в самом конце.

## Где размещать функции

Бывает три порядка: сначала вспомогательные функции, затем код; сначала код, затем функции; смешанный. Чаще предпочитают второй: читатель сначала видит, *что* происходит, и ему не обязательно углубляться в детали, если имена функций говорят сами за себя. Работает это благодаря всплытию объявлений (Function Declaration):

```js
console.log(twice(4)); // 8

function twice(x) {
  return x * 2;
}
```

Но для стрелочной функции в `const` такой порядок не сработает: переменная ещё не инициализирована.

```js
try {
  console.log(triple(4));
} catch (err) {
  console.log(err.name); // ReferenceError
}
const triple = (x) => x * 3;
```

## Руководства по стилю и линтеры

Готовые руководства (Google JavaScript Style Guide, Airbnb, StandardJS) закрывают мелочи: кавычки, пробелы, имена. Команде не нужно придумывать правила самой, достаточно выбрать одно руководство.

Следить за соблюдением правил вручную долго и неприятно, поэтому это делает **линтер** — инструмент статического анализа. Самый популярный сегодня — ESLint. Он находит нарушения стиля и настоящие ошибки: неиспользуемые и необъявленные переменные, недостижимый код, опечатки. Поэтому линтер полезен, даже если вам не важен стиль. Обычно его подключают к редактору и запускают перед коммитом, а файл настроек лежит в корне проекта.

Отдельная категория — форматтеры (например, Prettier): они не проверяют, а сами переписывают код в единый вид, избавляя от споров о пробелах.

## Типичные ошибки

> [!WARNING]
>
> - Правило «в одну строку без скобок» плюс дописывание кода позже — и уже не то, что задумывали.
> - Перенос строки после `return`, `break` или `continue` — вставляется `;`.
> - Смешивание стилей в одном файле: часть отступов по 2 пробела, часть по 4.
> - Споры о вкусовых правилах вместо автоматической проверки.

## Коротко

> [!TIP]
>
> - Скобки: египетский стиль, у `if` лучше всегда использовать блок `{ ... }`.
> - Отступы единые, пустые строки разделяют логические блоки, длина строки ограничена.
> - Точки с запятой ставьте всегда, а после `return` выражение начинайте на той же строке.
> - Ранний `return` и `continue` уменьшают вложенность.
> - Выбирайте готовое руководство по стилю и доверьте проверку линтеру.
