# Function Expression

В JavaScript функция — не особая конструкция «над» языком, а обычное значение, такое же, как число или строка. Её можно положить в переменную, скопировать, передать в другую функцию и вернуть из функции. Из этого вытекает второй способ создавать функции — Function Expression (функциональное выражение). После урока вы сможете отличать его от Function Declaration, понимать, когда каждая из функций становится доступной, и писать код с колбэками.

## Два способа создать функцию

До сих пор мы писали функции так — это *Function Declaration* (объявление функции):

```js
function sayHi() {
  return 'Привет';
}
```

Есть и второй синтаксис — *Function Expression*: функция создаётся внутри выражения, например справа от `=`:

```js
let sayHi = function () {
  return 'Привет';
};

console.log(sayHi()); // Привет
```

Здесь после слова `function` нет имени — для функционального выражения оно необязательно. Читается запись буквально: «создать функцию и положить её в переменную `sayHi`». Отличить один вид от другого просто: если `function` стоит в начале инструкции, это объявление; если функция оказалась частью другого выражения (правая часть присваивания, аргумент вызова, элемент условного оператора) — это выражение.

Точка с запятой после `}` во втором примере нужна не «функции», а инструкции присваивания `let sayHi = …;`. Так же вы ставите её после `let x = 5;`. После объявления `function sayHi() {…}` точка с запятой не нужна — это не выражение.

## Функция — это значение

Раз функция — значение, имя функции без скобок означает саму функцию, а не её запуск. Скобки `()` — это оператор вызова:

```js
function sayHi() {
  return 'Привет';
}

console.log(typeof sayHi); // function
console.log(String(sayHi)); // function sayHi() {\n  return 'Привет';\n}
```

Строковое представление функции — её исходный текст. Многие языки запускают функцию при любом упоминании имени, но JavaScript не из их числа.

Значение можно копировать:

```js
function sayHi() {
  return 'Привет';
}

let func = sayHi; // копируем функцию, не вызывая
console.log(func()); // Привет
console.log(func === sayHi); // true — это один и тот же объект

let result = sayHi(); // а здесь в переменную попадёт РЕЗУЛЬТАТ вызова
console.log(typeof result); // string
```

Копия и оригинал — один и тот же объект функции, у него просто стало два имени. Поэтому, если переприсвоить одно из них, второе продолжит работать:

```js
function greet() {
  return 'x';
}

let g = greet;
greet = null;
console.log(typeof g, g()); // function x
console.log(typeof greet); // object
```

## Колбэки

Функцию-значение можно передать аргументом. Функция, которую передают, чтобы её вызвали позже, называется *колбэком* (от «call back» — «вызвать обратно»). Вот функция, которая вызывает одну из двух переданных функций в зависимости от ответа:

```js
function ask(isYes, yes, no) {
  if (isYes) return yes();
  return no();
}

function onYes() {
  return 'Вы согласились';
}
function onNo() {
  return 'Вы отказались';
}

console.log(ask(true, onYes, onNo)); // Вы согласились
```

В браузере вместо `isYes` обычно стоит результат `confirm(question)`, но в Node.js его нет, поэтому мы передаём готовый ответ. Суть не меняется: `ask` не знает, что именно делать, — это решает тот, кто её вызвал.

Если колбэк нужен только в одном месте, имя ему не требуется. Функциональное выражение можно записать прямо в аргументе:

```js
console.log(
  ask(
    false,
    function () { return 'да'; },
    function () { return 'нет'; },
  ),
); // нет
```

Такие функции без имени называются анонимными. Снаружи `ask` они недоступны — они не присвоены ни одной переменной, — и именно этого мы хотим.

Обратите внимание на скобки при передаче: `ask(true, onYes, onNo)` передаёт функции, а `ask(true, onYes(), onNo())` сначала вызвала бы их и передала строки.

## Когда создаётся функция

Главное практическое отличие двух синтаксисов — момент создания.

Function Declaration обрабатывается ещё до выполнения кода: на подготовительном этапе движок находит все объявления в скрипте (или блоке) и создаёт функции. Поэтому вызывать такую функцию можно выше места объявления:

```js
console.log(hi('Вася')); // Привет, Вася

function hi(name) {
  return `Привет, ${name}`;
}
```

Function Expression создаётся, только когда выполнение доходит до него. До этого момента переменная либо недоступна, либо пуста:

```js
try {
  late('Вася');
} catch (e) {
  console.log(e.name + ': ' + e.message);
  // ReferenceError: Cannot access 'late' before initialization
}

let late = function (name) {
  return name;
};
```

С `let` и `const` вы получите `ReferenceError`, потому что переменная ещё в «мёртвой зоне». С `var` ошибка будет другой: переменная уже существует, но равна `undefined`, а вызвать `undefined` нельзя:

```js
try {
  late2('Вася');
} catch (e) {
  console.log(e.name + ': ' + e.message); // TypeError: late2 is not a function
}

var late2 = function (name) {
  return name;
};
```

Запомните различие в сообщениях: `ReferenceError` — «переменная ещё не инициализирована», `TypeError: … is not a function` — «переменная есть, но в ней не функция».

## Область видимости в блоке

Второе отличие связано с блоками `{…}`. В строгом режиме (`'use strict'`, модули и классы) Function Declaration внутри блока видна во всём этом блоке, но не снаружи:

```js
'use strict';
{
  function inner() {
    return 1;
  }
  console.log(inner()); // 1
}
console.log(typeof inner); // undefined
// inner() здесь дало бы ReferenceError: inner is not defined
```

Из-за этого объявление функции в ветках `if` не решает задачу «выбрать функцию по условию, а пользоваться ею потом»: после блока имя пропадает.

Важная оговорка про нестрогий режим. В обычном скрипте (без `'use strict'`) браузеры и Node.js следуют историческому правилу совместимости: объявление в блоке дополнительно «выпускает» имя наружу, как `var`, — когда выполнение доходит до объявления. Код с функциями в `if` может «случайно» работать в одном режиме и ломаться в другом. Не опирайтесь на это поведение.

Надёжный способ — объявить переменную снаружи и присвоить ей функциональное выражение:

```js
let age = 30;
let welcome;

if (age < 18) {
  welcome = function () { return 'Привет!'; };
} else {
  welcome = function () { return 'Здравствуйте!'; };
}

console.log(welcome()); // Здравствуйте!
```

Это же можно записать короче, с условным оператором:

```js
let age = 30;

let welcome = age < 18
  ? function () { return 'Привет!'; }
  : function () { return 'Здравствуйте!'; };

console.log(welcome()); // Здравствуйте!
```

## Что выбирать

| | Function Declaration | Function Expression |
|---|---|---|
| Где | отдельная инструкция | часть выражения |
| Доступна до строки с кодом | да | нет |
| Видимость в блоке (строгий режим) | только внутри блока | как у переменной, куда записана |
| `;` в конце | не нужна | нужна как у присваивания |
| Имя обязательно | да | нет |

Практическое правило: по умолчанию используйте Function Declaration. Её можно вызвать выше по файлу, поэтому основной код пишут сверху, а вспомогательные функции — ниже, и такую запись легче заметить глазами. К Function Expression переходите, когда нужно создать функцию по условию, передать безымянный колбэк или записать функцию в переменную, объект или массив.

## Типичные ошибки

> [!WARNING]
>
> - Вызвали функциональное выражение выше места, где оно записано: `ReferenceError` для `let`/`const` и `TypeError` для `var`.
> - Поставили скобки при передаче колбэка: `run(hello())` вместо `run(hello)`. Функция сработает сразу, а `run` получит её результат:
>
> ```js
> function run(cb) {
>   cb();
> }
> function hello() {
>   console.log('hi');
>   return 'done';
> }
>
> try {
>   run(hello()); // hi — вызвалась сразу
> } catch (e) {
>   console.log(e.name + ': ' + e.message); // TypeError: cb is not a function
> }
> ```
>
> - Объявили функцию внутри `if` и вызвали после блока — в строгом режиме имени уже нет.
> - Забыли `;` после функционального выражения: если следующая строка начнётся с `(` или `[`, JavaScript склеит их в один вызов.

## Коротко

> [!TIP]
>
> - Функция — значение: её можно присвоить, скопировать, передать и вернуть. Скобки `()` её запускают, без них вы работаете с самой функцией.
> - Function Declaration — отдельная инструкция, создаётся до выполнения кода и доступна во всём блоке. Function Expression — часть выражения, создаётся, когда выполнение до неё дошло.
> - Колбэк — функция, которую передают другой функции, чтобы та вызвала её позже; для разового колбэка удобно анонимное функциональное выражение.
> - Функция, нужная после условия, создаётся через присваивание выражения заранее объявленной переменной, а не через объявление в `if`.
> - По умолчанию выбирайте Function Declaration, а Function Expression — когда объявление не подходит.
