# Рекурсия и стек

Рекурсия — это приём, при котором функция в процессе работы вызывает саму себя. Он удобен там, где задачу можно свести к такой же задаче, но поменьше: обход вложенных данных, связные списки, деревья. В этом уроке разберём, как рекурсия устроена «под капотом» (стек вызовов), как её писать без бесконечных вызовов и когда лучше обойтись циклом.

## Два обязательных элемента

У рекурсивной функции всегда есть две части:

1. **База** — случай, который решается напрямую, без самовызова.
2. **Шаг** — самовызов с *более простыми* данными, которые приближают нас к базе.

```js
function pow(x, n) {
  if (n === 1) return x; // база
  return x * pow(x, n - 1); // шаг: задача стала меньше на единицу
}

console.log(pow(2, 10)); // 1024
```

Здесь степень `n` на каждом шаге уменьшается, и рано или поздно мы упираемся в `n === 1`. Если шаг не приближает к базе, вызовы не закончатся никогда:

```js
function forever(n) {
  return forever(n + 1);
}
forever(0); // RangeError: Maximum call stack size exceeded
```

Ту же функцию можно записать короче через тернарный оператор: `n === 1 ? x : x * pow(x, n - 1)`. Это дело вкуса, но структура «база + шаг» остаётся.

## Контекст выполнения и стек вызовов

Когда JavaScript вызывает функцию, он создаёт **контекст выполнения**: запись, в которой лежат аргументы, локальные переменные и место в коде, куда нужно вернуться. Если внутри функции происходит новый вызов, текущий контекст «замораживается» и кладётся в **стек вызовов**, а поверх него создаётся контекст нового вызова. Когда вызов завершается, его контекст снимается со стека, и работа продолжается с замороженной точки.

Важное следствие: у каждого рекурсивного вызова **свои** локальные переменные и параметры. Вызов `pow(2, 3)` не знает, что внутри него живёт `pow(2, 2)`, он просто ждёт его результата.

Порядок вывода хорошо показывает, как стек растёт и сжимается:

```js
function countdown(n) {
  if (n === 0) return;
  console.log('вниз', n);
  countdown(n - 1);
  console.log('вверх', n);
}

countdown(2);
// вниз 2
// вниз 1
// вверх 1
// вверх 2
```

Всё, что стоит *до* рекурсивного вызова, выполняется по пути «вниз» (от большего `n` к меньшему), а всё, что *после*, — по пути «вверх», в обратном порядке. Этим пользуются, например, чтобы обойти список в обратном направлении.

## Глубина рекурсии ограничена

Каждый контекст занимает память, поэтому размер стека конечен. Точное число зависит от движка и размера кадров; в Node.js порядок величины — около десяти тысяч вложенных вызовов. При переполнении выбрасывается `RangeError: Maximum call stack size exceeded`.

Поэтому для задач вроде «сумма чисел от 1 до `n`» при больших `n` лучше цикл (или формула `n * (n + 1) / 2`):

```js
function sumToLoop(n) {
  let sum = 0;
  for (let i = 1; i <= n; i++) sum += i;
  return sum;
}

console.log(sumToLoop(100)); // 5050
console.log(100 * (100 + 1) / 2); // 5050
```

Любую рекурсию можно переписать циклом (иногда с явным стеком-массивом). Рекурсивная запись обычно короче и яснее, цикл — экономнее по памяти и немного быстрее, потому что не создаёт контекст на каждый шаг.

## Рекурсивные структуры данных

Рекурсия особенно хороша для данных, которые устроены сами по себе рекурсивно: «часть — такая же структура, только меньше».

Пример: компания, состоящая из отделов, которые могут содержать подотделы. Лист структуры — массив сотрудников.

```js
const company = {
  dev: [{ salary: 1000 }, { salary: 1600 }],
  ops: {
    junior: [{ salary: 700 }],
    lead: [{ salary: 1500 }],
  },
};

function totalSalary(dep) {
  if (Array.isArray(dep)) {
    return dep.reduce((sum, person) => sum + person.salary, 0); // база
  }
  let sum = 0;
  for (const sub of Object.values(dep)) {
    sum += totalSalary(sub); // шаг: подотдел — задача поменьше
  }
  return sum;
}

console.log(totalSalary(company)); // 4800
```

Глубина вложенности нам заранее неизвестна — рекурсия справляется с этим сама, а цикл потребовал бы явного стека.

**Связный список** — ещё один пример. Это цепочка объектов, у каждого есть значение и ссылка на следующий (`null` — конец):

```js
const list = { value: 1, next: { value: 2, next: { value: 3, next: null } } };

function listLength(node) {
  return node === null ? 0 : 1 + listLength(node.next);
}

console.log(listLength(list)); // 3
```

Преимущество списка перед массивом: вставка и удаление в начале — это просто смена ссылки, без сдвига всех элементов. Недостаток — нет доступа по индексу, нужно идти по цепочке.

## Типичные ошибки

> [!WARNING]
>
> - **Нет базы или шаг не приближает к ней.** Результат — `RangeError`. Проверяйте крайние значения: `0`, пустой массив, `null`.
> - **Двойные вызовы.** Наивное вычисление чисел Фибоначчи `fib(n - 1) + fib(n - 2)` пересчитывает одни и те же значения, число вызовов растёт экспоненциально. Лечится запоминанием результатов или циклом.
> - **Забытый `return`.** Без `return` перед рекурсивным вызовом результат теряется, и функция вернёт `undefined`.
>
> ```js
> function fibNaive(n) {
>   return n <= 1 ? n : fibNaive(n - 1) + fibNaive(n - 2);
> }
> console.log(fibNaive(10)); // 55
> ```

## Коротко

> [!TIP]
>
> - Рекурсия = база (без самовызова) + шаг (самовызов с меньшей задачей).
> - Каждый вызов получает собственный контекст выполнения; контексты лежат в стеке вызовов.
> - Код до самовызова выполняется «вниз», код после — «вверх» в обратном порядке.
> - Глубина стека конечна: слишком глубокая или бесконечная рекурсия даёт `RangeError`.
> - Рекурсия естественна для вложенных данных и деревьев; для простых счётных задач часто лучше цикл.
