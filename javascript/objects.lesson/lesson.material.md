# Объекты

Семь из восьми типов данных JavaScript — примитивы: строка, число, логическое значение и так далее. Каждый такой тип хранит ровно одно простое значение. Для наборов данных и более сложных сущностей служит восьмой тип — объект. Почти всё, что вы будете писать на JavaScript, так или иначе упирается в объекты, поэтому с ними стоит разобраться в первую очередь.

Объект — это набор *свойств*. Свойство состоит из ключа и значения: по ключу значение можно прочитать, изменить или удалить. Ключ — строка (или символ, об этом типе позже), значение — что угодно: число, строка, функция, другой объект.

## Создание объекта

Есть два синтаксиса. На практике почти всегда пишут литерал с фигурными скобками:

```js
const empty = {};                // литерал объекта
const same = new Object();       // «конструктор объекта», встречается редко

const user = {
  name: 'Анна',  // ключ name, значение 'Анна'
  age: 30,       // ключ age, значение 30
};               // «висячая» запятая после последнего свойства допустима

console.log(user); // { name: 'Анна', age: 30 }
```

Висячая запятая удобна: добавляя или переставляя строки, вы не следите за запятыми, а в списке изменений остаётся меньше шума.

## Чтение, запись и удаление

Свойство читают и пишут через точку. Новое свойство появляется просто присваиванием, удаляет свойство оператор `delete`:

```js
const user = { name: 'Анна', age: 30 };

user.isAdmin = true;   // добавили
user.age = 31;         // изменили
delete user.name;      // удалили

console.log(user); // { age: 31, isAdmin: true }
```

Обращение к несуществующему свойству не ошибка, а `undefined`. Ошибка будет, только если читать свойство у самого `undefined` или `null`:

```js
const user = { age: 31 };

console.log(user.email); // undefined
console.log(user.address.city); // TypeError: Cannot read properties of undefined (reading 'city')
```

### Объект в `const`

Ключевое слово `const` запрещает *переприсвоить переменную*, но не меняет содержимое объекта, на который она указывает:

```js
const config = { debug: false };
config.debug = true;           // можно
config.level = 3;              // можно
// config = { debug: true };   // TypeError: Assignment to constant variable.
console.log(config); // { debug: true, level: 3 }
```

Сделать сами свойства неизменяемыми можно, но другими средствами — о них позже.

## Квадратные скобки

Запись через точку требует, чтобы ключ выглядел как обычное имя переменной: без пробелов и дефисов, не с цифры. Для остальных ключей есть доступ через квадратные скобки, куда подставляется *выражение*, дающее строку:

```js
const user = {};
user['likes birds'] = true;
console.log(user['likes birds']); // true
delete user['likes birds'];
console.log(user); // {}
```

Главное преимущество скобок — имя свойства может лежать в переменной или вычисляться на лету. Точка так не умеет: после неё всегда идёт буквальное имя.

```js
const user = { name: 'Анна', key: 'age', age: 30 };
const key = 'name';

console.log(user[key]); // Анна — имя взято из переменной key
console.log(user.key);  // age — это свойство с именем "key"
```

### Вычисляемые свойства

Скобки работают и внутри литерала. Такая запись называется *вычисляемым свойством*:

```js
const field = 'color';
const car = {
  [field]: 'red',            // ключ — значение переменной field
  [field + 'Code']: 7,       // ключ можно собрать из выражения
};

console.log(car); // { color: 'red', colorCode: 7 }
```

## Короткая запись свойств

Часто значение берут из переменной с тем же именем, что и ключ. Тогда имя можно не повторять:

```js
function makeUser(name, age) {
  return { name, age };  // то же, что { name: name, age: age }
}

console.log(makeUser('Олег', 25)); // { name: 'Олег', age: 25 }
```

Короткие и обычные свойства можно смешивать в одном литерале.

## Какие бывают ключи

На имена свойств не действуют ограничения, как на имена переменных: зарезервированные слова допустимы.

```js
const obj = { for: 1, let: 2, return: 3 };
console.log(obj.for + obj.let + obj.return); // 6
```

Любой ключ, который не строка и не символ, превращается в строку. Поэтому числовой ключ и его строковая запись — одно и то же свойство:

```js
const obj = { 0: 'тест' };
console.log(obj[0], obj['0']); // тест тест
console.log(Object.keys(obj)); // [ '0' ]
```

Но превращение идёт по правилам преобразования в строку: `1.0` — это число `1`, а значит ключ `'1'`; `'01'` — уже другая строка. Если в качестве ключа подставить сам объект, получится `'[object Object]'` — почти всегда это ошибка.

Единственное неудобное имя — `__proto__`: его нельзя сделать примитивом. Присваивание `obj.__proto__ = 5` молча игнорируется, потому что за этим именем скрыта ссылка на прототип объекта. К теме мы вернёмся, когда будем изучать наследование.

## Проверка существования: `in`

Сравнение `obj.prop === undefined` обычно отвечает на вопрос «есть ли свойство». Но оно не отличит отсутствующее свойство от существующего со значением `undefined`. Для точной проверки есть оператор `in`: слева имя свойства (строка), справа объект.

```js
const user = { name: 'Анна', nick: undefined };

console.log('name' in user);           // true
console.log('age' in user);            // false
console.log(user.nick === undefined);  // true — свойство есть, значение undefined
console.log('nick' in user);           // true

const key = 'name';
console.log(key in user);              // true — без кавычек берётся значение переменной
```

Имейте в виду: `in` смотрит и в цепочку прототипов, поэтому `'toString' in {}` даёт `true`. Для проверки только собственных свойств есть `Object.hasOwn(obj, key)`:

```js
console.log('toString' in {});            // true
console.log(Object.hasOwn({}, 'toString')); // false
```

Значение `undefined` в данных лучше не использовать: для «пусто» или «неизвестно» есть `null`.

## Перебор: `for..in`

Цикл `for..in` проходит по ключам объекта:

```js
const user = { name: 'Анна', age: 30, isAdmin: true };

for (const key in user) {
  console.log(key, user[key]);
}
// name Анна
// age 30
// isAdmin true
```

Имя переменной цикла выбирайте сами (`key`, `prop`), объявлять её можно через `let` или `const`.

### Порядок свойств

Порядок обхода детерминирован, но не всегда совпадает с порядком добавления. Ключи, являющиеся *целыми неотрицательными числами* (в виде строки, например `'1'` или `'41'`), идут первыми по возрастанию. Остальные — в порядке создания.

```js
const codes = { '49': 'Германия', '41': 'Швейцария', '1': 'США' };
console.log(Object.keys(codes)); // [ '1', '41', '49' ]

const user = { name: 'Анна' };
user.surname = 'Ли';
user.age = 25;
console.log(Object.keys(user)); // [ 'name', 'surname', 'age' ]

const mixed = { '-1': 'a', '1.5': 'b', '01': 'c', '3': 'd' };
console.log(Object.keys(mixed)); // [ '3', '-1', '1.5', '01' ]
```

Если нужен порядок «как добавили», а ключи похожи на числа, добавьте к ним префикс, например `'+49'`: такой ключ уже не целое число, и сортировка не сработает. Для упорядоченных данных чаще берут массив или `Map`.

## Типичные ошибки

> [!WARNING]
>
> - `user.key`, когда имя лежит в переменной `key`: нужно `user[key]`.
> - Сравнение с `undefined` там, где значение может быть самим `undefined`: используйте `in`.
> - Расчёт на порядок «добавления» при числовых ключах.
> - Мысль, что `const obj` защищает содержимое объекта.
> - Чтение вложенного свойства у отсутствующего объекта: `user.address.city`.

## Коротко

> [!TIP]
>
> - Объект — набор пар «ключ: значение»; ключи — строки или символы, значения — любые.
> - Через точку обращаются к «простым» ключам, через `[]` — к любым и к ключам из переменных; в литерале то же даёт `[expr]: value`.
> - `delete obj.key` удаляет свойство, `'key' in obj` проверяет наличие, `for (const k in obj)` перебирает ключи.
> - Целочисленные ключи в обходе идут первыми по возрастанию, остальные — в порядке создания.
> - `const` защищает переменную, а не содержимое объекта.
