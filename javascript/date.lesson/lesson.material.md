# Дата и время

Встроенный объект `Date` хранит момент времени и умеет раскладывать его на год, месяц, день и так далее. Работать с ним нужно аккуратно: месяцы нумеруются с нуля, часовой пояс влияет на результат, а арифметика дат выполняется «через числа». В этом уроке разберём создание дат, чтение и изменение компонентов, автоматическую коррекцию, сравнение, разбор строк и форматирование.

В примерах используются методы с приставкой `UTC`: они не зависят от часового пояса компьютера, поэтому результаты одинаковы у всех. Обычные версии (`getFullYear`, `getHours` и т. д.) делают то же самое, но в **локальном** поясе.

## Что внутри Date

Внутри объект хранит одно число — количество миллисекунд с полуночи 1 января 1970 года по UTC (так называемое «время Unix», только в миллисекундах). Это число называется временной меткой (timestamp). Всё остальное — вычисляемое представление.

```js
const epoch = new Date(0);
console.log(epoch.toISOString()); // '1970-01-01T00:00:00.000Z'
console.log(new Date(Date.UTC(2024, 0, 1)).getTime()); // 1704067200000
```

## Создание

| Вызов | Что получится |
|---|---|
| `new Date()` | текущий момент |
| `new Date(ms)` | момент по числу миллисекунд от 1970 года |
| `new Date('строка')` | разбор строки (см. ниже) |
| `new Date(год, месяц, день, часы, мин, сек, мс)` | компоненты в **локальном** поясе; обязательны год и месяц |
| `Date.UTC(год, месяц, …)` | число миллисекунд для компонентов в UTC |

Чтобы создать фиксированную дату независимо от пояса, оборачивайте `Date.UTC` в `new Date`:

```js
const d = new Date(Date.UTC(2024, 0, 31, 10, 30, 15, 500));
console.log(d.toISOString()); // '2024-01-31T10:30:15.500Z'
```

Здесь важная особенность: **месяцы нумеруются с 0** (январь — `0`, декабрь — `11`), а дни месяца — с 1. Дни недели (`getUTCDay`) считаются с 0 = воскресенье.

```js
console.log(d.getUTCFullYear()); // 2024
console.log(d.getUTCMonth());    // 0 — январь
console.log(d.getUTCDate());     // 31
console.log(d.getUTCDay());      // 3 — среда
console.log(d.getUTCHours());    // 10
```

Для года есть `getFullYear` (не `getYear`: он устарел). Метка времени — `getTime()`; текущую метку без создания объекта возвращает `Date.now()`.

## Изменение компонентов

Есть парные методы-сеттеры: `setUTCFullYear`, `setUTCMonth`, `setUTCDate`, `setUTCHours` и другие. Они **меняют существующий объект** и возвращают новую метку времени.

```js
const date = new Date(Date.UTC(2024, 0, 15));
date.setUTCDate(20);
console.log(date.toISOString()); // '2024-01-20T00:00:00.000Z'
```

Если нужна копия с изменениями — создайте её: `new Date(date)` или `new Date(date.getTime())`. Иначе вы измените исходный объект, на который ссылаются другие части программы.

## Автоисправление

Если передать значение вне допустимого диапазона, `Date` переносит излишек в следующий компонент. Этим удобно пользоваться для арифметики:

```js
const a = new Date(Date.UTC(2024, 1, 29));   // 29 февраля 2024 (високосный)
a.setUTCDate(a.getUTCDate() + 1);
console.log(a.toISOString()); // '2024-03-01T00:00:00.000Z'

const b = new Date(Date.UTC(2024, 0, 31));
b.setUTCMonth(1);             // «31 февраля» -> 2 марта
console.log(b.toISOString()); // '2024-03-02T00:00:00.000Z'
```

Нулевой день означает «последний день предыдущего месяца» — поэтому число дней в месяце считают так:

```js
const daysIn = (year, month) => new Date(Date.UTC(year, month + 1, 0)).getUTCDate();
console.log(daysIn(2024, 1)); // 29
console.log(daysIn(2023, 1)); // 28
```

Ещё один пример: `new Date(Date.UTC(2024, 0, 1, 24))` — это `2024-01-02T00:00:00.000Z`.

## Приведение к числу и сравнение

При вычитании даты превращаются в числа (миллисекунды), поэтому разница — это длительность:

```js
const start = new Date(Date.UTC(2024, 0, 1));
const end = new Date(Date.UTC(2024, 0, 3));
console.log(end - start);              // 172800000
console.log((end - start) / 864e5);    // 2 — дня (864e5 мс в сутках)
console.log(start < end);              // true
```

Операторы `<` и `>` работают с датами, а вот `==` и `===` сравнивают **ссылки**, как у любых объектов. Для проверки равенства момента сравнивайте числа:

```js
console.log(start == new Date(start));         // false
console.log(+start === +new Date(start));      // true
```

Вычитая даты, учтите, что «сутки = 864e5 мс» не всегда соответствует календарному дню в локальном поясе при переходе на летнее время; в UTC такой проблемы нет.

## Разбор строк

Конструктор и `Date.parse(str)` понимают формат ISO `YYYY-MM-DDTHH:mm:ss.sssZ`. Буква `Z` означает UTC, а вместо неё можно указать смещение (`+03:00`). Результат `Date.parse` — метка времени либо `NaN` для некорректной строки.

```js
console.log(Date.parse('2024-03-05T10:00:00Z'));      // 1709632800000
console.log(Date.parse('2024-03-05T10:00:00+03:00')); // 1709622000000
console.log(new Date('2024-03-05').toISOString());    // '2024-03-05T00:00:00.000Z'
console.log(new Date('abc').getTime());               // NaN
```

Строка только с датой `'2024-03-05'` трактуется как UTC, а строка с датой и временем без `Z` — как локальное время. Другие форматы (`'03/05/2024'`) зависят от реализации — избегайте их.

Некорректная дата — это объект `Invalid Date`, чья метка равна `NaN`. Проверять её надо через `Number.isNaN(d.getTime())`.

## Вывод

`toISOString()` даёт строку в UTC и подходит для хранения и обмена данными; тот же результат даёт `JSON.stringify` для даты. Из неё легко получить «только дату»:

```js
console.log(new Date(Date.UTC(2024, 5, 15)).toISOString().slice(0, 10)); // '2024-06-15'
```

Для читаемого вывода пользователю используют `toLocaleDateString` / `toLocaleString` или `Intl.DateTimeFormat` с указанием локали и пояса (`timeZone: 'UTC'`). Метод `toString()` зависит от пояса машины.

## Типичные ошибки

- Месяц `1` — это февраль, а не январь.
- Проверка `date1 === date2` вместо сравнения `getTime()`.
- Изменение даты, пришедшей в функцию, вместо работы с копией.
- Использование локальных методов в тестах и серверном коде: результаты зависят от пояса машины.
- Функция `Date()` без `new` возвращает строку с текущим временем, а не объект.
- Двузначный год в `Date.UTC(99, …)` превращается в `1999`.

## Коротко

- `Date` хранит миллисекунды от 1970-01-01T00:00:00Z; месяцы нумеруются с 0.
- Для независимости от пояса используйте `Date.UTC` и методы `getUTC…`/`setUTC…`.
- Сеттеры меняют объект на месте; копируйте через `new Date(date)`.
- Выход за диапазон приводит к автопереносу: `day = 0` — последний день прошлого месяца.
- Вычитание дат даёт миллисекунды; `==` на датах сравнивает ссылки.
- `Date.parse` понимает ISO-строки, а для неверной строки даёт `NaN`.
