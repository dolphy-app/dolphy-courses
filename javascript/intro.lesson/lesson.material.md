# Введение в JavaScript

JavaScript появился как язык для «оживления» веб-страниц, а сегодня работает в браузерах, на серверах, в мобильных и настольных приложениях. В этом уроке — что это за язык, где он выполняется, где искать достоверную информацию и чем пользоваться при написании кода.

## Что такое JavaScript

Программы на JavaScript называют **скриптами**. Скрипт хранится и передаётся как обычный текст; отдельной ручной компиляции перед запуском не требуется. Скрипт выполняет **движок** — программа, которая читает код, превращает его в машинные инструкции и запускает.

Название вводит в заблуждение: к языку Java JavaScript не относится. Когда-то он назывался LiveScript, а имя поменяли ради популярности Java. Сейчас это самостоятельный язык со своей спецификацией — **ECMAScript**.

Движки есть у каждого браузера, и у них есть собственные имена:

| Движок | Где используется |
|---|---|
| V8 | Chrome, Edge, Opera, а также Node.js и Deno |
| SpiderMonkey | Firefox |
| JavaScriptCore | Safari, а также Bun |

Движок не просто «читает построчно». Он разбирает текст, компилирует его и ещё на ходу наблюдает за выполнением, подстраивая машинный код под реальные данные. Поэтому современный JavaScript работает быстро.

## Окружение определяет возможности

Сам по себе язык — это числа, строки, объекты, функции, промисы и так далее. Всё остальное даёт **окружение**, в котором запущен движок.

В **браузере** доступны страница (`document`), окно (`window`), события мыши и клавиатуры, сетевые запросы, хранилище данных на стороне клиента. Но по соображениям безопасности браузерный скрипт не может свободно читать файлы пользователя, обращаться к другим вкладкам и сайтам с другого источника без разрешения сервера или запускать произвольные программы.

В **Node.js** всё иначе: нет страницы и `window`, зато есть доступ к файловой системе, сети и процессам. Один и тот же язык, разные «возможности из коробки».

Эти различия важны на практике. Код ниже работает одинаково в любом окружении, потому что использует только возможности языка:

```js
const prices = [120, 80, 45];
const total = prices.reduce((sum, price) => sum + price, 0);
console.log(total); // 245
```

А вот так — только в браузере, потому что `document` создаёт браузер, а не язык:

```js
// только в браузере
document.title = 'Привет';
```

В Node.js такая строка завершится ошибкой `ReferenceError: document is not defined`. Курс выполняет код в Node.js, поэтому браузерные API в заданиях не понадобятся; где они упоминаются, это отмечено словами «в браузере».

## Языки поверх JavaScript

Синтаксис JavaScript развивается ежегодно, а браузеры внедряют новшества с разной скоростью. Эту проблему решают **транспайлеры** (например, Babel): они переводят новый синтаксис в старый, понятный всем движкам. Дополнительно используются **полифилы** — скрипты, которые добавляют отсутствующие функции.

Есть и языки, которые переводятся в JavaScript: TypeScript добавляет проверку типов, поэтому его выбирают для больших проектов. Они не заменяют знание JavaScript — результат всё равно запускается как JavaScript.

## Где искать информацию

- **Спецификация ECMAScript** — самый точный источник, но читать её сложно. Нужна, когда спорные детали поведения не удаётся прояснить иначе.
- **MDN Web Docs** — основной справочник: описание синтаксиса, объектов, методов, примеры и сведения о поддержке.
- **Таблицы совместимости** (например, caniuse.com и таблицы на MDN) показывают, какие функции поддерживает какая версия браузера или Node.js.

Привычка «проверить в MDN» экономит время: часто вопрос «а как это работает?» решается за минуту.

## Редактор кода и инструменты разработчика

Писать код можно в любом текстовом редакторе, но удобнее среда с подсветкой, автодополнением, подсказками об ошибках и отладчиком. Распространены лёгкие редакторы (например, VS Code) и полноценные IDE (например, WebStorm). Выбор вкуса — оба подойдут для курса.

Браузер встраивает **инструменты разработчика** (открываются по F12 или Ctrl+Shift+I, на macOS — Cmd+Option+I). Вкладка *Console* показывает сообщения об ошибках и результат `console.log`, а также позволяет выполнять команды прямо там. Вкладка *Sources* даёт отладчик с точками останова. В Node.js то же самое: ошибки пишутся в терминал, а `console.log` печатает в стандартный вывод.

```js
console.log('Привет'); // Привет
console.log(2 + 3);    // 5
```

## Типичные ошибки

- Путать Java и JavaScript: это разные языки с разной историей и средой выполнения.
- Считать, что возможность «есть в JavaScript», если она есть в браузере. `window`, `document` и `alert` — часть браузерного окружения, а не языка.
- Искать информацию по случайным форумам вместо документации: устаревшие ответы бывают очень убедительными.
- Использовать новую возможность языка, не проверив поддержку у целевых пользователей.

## Коротко

- JavaScript — самостоятельный язык, стандарт которого называется ECMAScript; к Java он не относится.
- Код выполняет движок: V8, SpiderMonkey, JavaScriptCore и другие.
- Возможности зависят от окружения: браузер даёт работу со страницей, Node.js — с файлами и сетью.
- Транспайлеры и полифилы позволяют писать современный код для старых окружений.
- Основные источники знаний: MDN и спецификация; поддержку проверяют по таблицам совместимости.
- Для отладки — консоль браузера или терминал Node.js и `console.log`.
