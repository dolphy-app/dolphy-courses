# Объект функции и NFE

В JavaScript функция — это значение особого типа: **объект**, который можно вызвать. Поэтому у неё есть свойства, ей можно добавлять свои, а переменная с функцией ничем принципиально не отличается от переменной с массивом. В этом уроке разберём встроенные свойства `name` и `length`, пользовательские свойства и именованные функциональные выражения (NFE).

## Свойство `name`

У функции есть имя, доступное через `name`:

```js
function hello() {}
console.log(hello.name); // hello
```

Интересно, что имя определяется даже у анонимных функций: если функцию присваивают переменной, параметру по умолчанию или свойству объекта, движок берёт имя оттуда. Это называется *контекстным именем*:

```js
const arrow = () => {};
const expr = function () {};
const obj = { method() {}, ['k' + 1]: function () {} };

console.log(arrow.name); // arrow
console.log(expr.name); // expr
console.log(obj.method.name); // method
console.log(obj.k1.name); // k1
console.log((function () {}).name === ''); // true
```

Если контекста нет (например, функция лежит в массиве или возвращается напрямую), `name` — пустая строка. Имя полезно в сообщениях об ошибках и при отладке. Присвоить новое имя нельзя: `fn.name = 'x'` в нестрогом режиме молча ничего не делает, в строгом — `TypeError`, потому что свойство только для чтения.

## Свойство `length`

`length` — количество параметров функции. Но считаются только параметры **до первого со значением по умолчанию**; rest-параметр не считается:

```js
function f(a, b = 1, ...rest) {}
console.log(f.length); // 1
console.log((function (a, b) {}).length); // 2
console.log(((a) => a).length); // 1
```

`length` часто используют для интроспекции: например, функция-обработчик проверяет, сколько аргументов ожидает переданный колбэк, и вызывает его по-разному. Это основа некоторых механизмов «полиморфизма» функций.

## Собственные свойства

Функции можно добавлять любые свойства, как обычному объекту:

```js
function counter() {
  counter.count = (counter.count || 0) + 1;
  return counter.count;
}

counter();
counter();
console.log(counter.count); // 2
```

Здесь состояние хранится прямо в функции. Не путайте это с локальными переменными: `var count` внутри функции живёт в её окружении и снаружи **не** является свойством:

```js
function f() {
  var count = 0;
}
console.log(f.count); // undefined
```

Отличие от замыкания: состояние в свойстве доступно и снаружи (его можно прочитать и перезаписать), а переменная замыкания — приватна. Выбирайте по задаче: нужен публичный доступ — свойство, нужна инкапсуляция — замыкание. Свойства удобны и для «меток» (`handler.id = 1`), и для служебных методов (`counter.reset = ...`).

Такие свойства **перечисляемые** (видны в `Object.keys`), а `name` и `length` — нет:

```js
function f(a, b) {}
f.id = 1;
console.log(Object.keys(f)); // [ 'id' ]
console.log(f.length); // 2
```

## Именованное функциональное выражение (NFE)

У функции-выражения можно задать имя, которое будет видно **только внутри** неё:

```js
const fact = function inner(n) {
  return n <= 1 ? 1 : n * inner(n - 1);
};

console.log(fact(4)); // 24
console.log(typeof inner); // undefined
console.log(fact.name); // inner
```

Зачем это нужно? Чтобы функция могла надёжно вызывать себя по имени, не завися от внешней переменной. Допустим, внешнюю переменную с функцией перезаписали:

```js
let f = function g(n) {
  return n <= 1 ? 1 : n * g(n - 1);
};

const copy = f;
f = null;
console.log(copy(5)); // 120
```

Если бы функция вызывала себя через `f`, второй вызов упал бы: `f` уже `null`. С NFE внутреннее имя `g` ссылается на саму функцию и не зависит от внешних переменных.

Это механизм именно для **функциональных выражений**. У объявления (`function g() {}`) имя и так видно снаружи, а «внутреннего» имени отдельно нет. Стрелочные функции NFE не поддерживают: у них нет места для имени.

## Трюк: функция, превращающаяся в число

Объект функции можно настроить так, чтобы он приводился к числу. Метод `valueOf` вызывается при арифметике и сравнении, поэтому цепочка вызовов может накапливать сумму и «выглядеть» числом:

```js
function sum(a) {
  let total = a;
  function inner(b) {
    total += b;
    return inner;
  }
  inner.valueOf = () => total;
  return inner;
}

console.log(+sum(1)(2)(3)); // 6
console.log(sum(1)(2) == 3); // true
```

Практической пользы в таком коде мало, но он хорошо показывает, что функция — обычный объект со свойствами.

## Типичные ошибки

- Считать, что `length` включает параметры со значениями по умолчанию и rest.
- Полагаться на `name` у анонимных функций из массивов — он пуст.
- Ожидать, что имя NFE доступно снаружи: `typeof inner` — `'undefined'`.
- Путать локальную переменную функции со свойством самой функции.
- Хранить в свойстве функции то, что должно быть приватным.

## Коротко

- Функция — объект: у неё есть свойства, и ей можно добавлять свои.
- `name` определяется из контекста; у «ничьих» функций он пуст.
- `length` — число параметров до первого значения по умолчанию, rest не считается.
- NFE — функция-выражение с именем, видимым только внутри: надёжная рекурсия без внешних переменных.
- Свойство функции — публичное состояние; переменная замыкания — приватное.
