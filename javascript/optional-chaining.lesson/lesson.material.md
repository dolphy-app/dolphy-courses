# Опциональная цепочка ?.

Обращение к свойству у `undefined` или `null` — одна из самых частых ошибок в JavaScript. Оператор `?.` позволяет читать вложенные данные так, чтобы отсутствующее звено не роняло программу. Вы научитесь применять три формы оператора и понимать, когда вычисление «обрывается».

## Проблема

Допустим, адрес у пользователя необязателен:

```js
const user = { name: "Ира" };
try {
  console.log(user.address.street);
} catch (e) {
  console.log(e.name); // TypeError
}
```

`user.address` равно `undefined`, а читать свойство `street` у `undefined` нельзя. Раньше это обходили проверками:

```js
const user = {};
console.log(user.address && user.address.street && user.address.street.name); // undefined
```

Работает, но путь `user.address` повторяется снова и снова. К тому же `&&` реагирует на любое «ложное» значение (`0`, `""`), а не только на отсутствие.

## Синтаксис ?.

Выражение `a?.b` читает `b`, если `a` не `null` и не `undefined`. Иначе вычисление прекращается и результат — `undefined`.

```js
const user = {};
console.log(user.address?.street);        // undefined
console.log(user.address?.street?.name);  // undefined
console.log(null?.length);                // undefined
console.log("abc"?.length);               // 3
```

Важно: `?.` проверяет **только** `null` и `undefined`. Значения `0`, `""`, `false` считаются существующими:

```js
console.log(""?.length);       // 0
console.log(0?.toFixed(1));    // 0.0
console.log(false?.toString()); // false
```

Ставить `?.` нужно только там, где значение действительно может отсутствовать. Если `user` обязан быть объектом, пишите `user.address?.street`, а не `user?.address?.street`: иначе настоящая ошибка (пропал сам `user`) будет молча скрыта.

## Короткое замыкание

Если левая часть равна `null`/`undefined`, ничего правее не вычисляется: остаток цепочки пропускается вместе с побочными эффектами.

```js
let i = 0;
const obj = null;
obj?.[i++];
console.log(i); // 0 — i++ не выполнялся

const user = {};
console.log(user.address?.street.name.first); // undefined, ошибки нет
```

Во втором примере после `?.` идут обычные точки, но пропускается вся цепочка целиком. Правда, замыкание действует лишь внутри одного выражения-цепочки: если часть заключить в скобки, оно прекращается.

```js
const user = {};
try {
  (user.address?.street).name;
} catch (e) {
  console.log(e.name); // TypeError
}
```

## Три формы

**`a?.b`** — свойство.

**`a?.[expr]`** — доступ по ключу, в том числе вычисляемому:

```js
const config = { limits: { daily: 5 } };
const key = "daily";
console.log(config.limits?.[key]);   // 5
console.log(config.quotas?.[key]);   // undefined
```

**`a?.(args)`** — вызов функции, которая может отсутствовать:

```js
const user = {
  name: "Лев",
  sayHi() { return "Привет, " + this.name; }
};
console.log(user.sayHi?.());  // Привет, Лев
console.log(user.sayBye?.()); // undefined
```

В последней форме проверяется именно то, что стоит слева от `?.(`. Если свойство есть, но это не функция (например, число), вызов всё равно упадёт с `TypeError`: `?.` не заменяет проверку типа.

```js
const o = { run: 5 };
try { o.run?.(); } catch (e) { console.log(e.name); } // TypeError
```

При вызове через `obj.method?.()` контекст `this` сохраняется — это обычный вызов метода.

## Чтение, удаление, но не запись

`?.` можно использовать для чтения и в `delete`:

```js
const user = { name: "Ася" };
delete user?.name;
console.log(user); // {}
```

А вот присваивание не допускается: `user?.name = "Боб"` — синтаксическая ошибка. Запись в несуществующий объект не имеет смысла, и язык её запрещает.

```js
try {
  new Function('const u = {}; u?.name = "Боб";');
} catch (e) {
  console.log(e.name); // SyntaxError
}
```

## Типичные ошибки

- **Везде `?.`.** Лишний оператор маскирует опечатки и реальные баги: код «молча» возвращает `undefined` там, где должен был упасть и показать проблему.
- **Ожидание проверки на «пусто».** `""?.length` — это `0`, а не `undefined`.
- **Вызов не-функции.** `obj.prop?.()` не спасёт, если `prop` — не функция.
- **Присваивание.** `a?.b = 1` не скомпилируется.
- **Скобки.** `(a?.b).c` разрывает цепочку.

## Коротко

- `a?.b` возвращает `undefined`, если `a` — `null` или `undefined`, иначе читает `b`.
- Формы: `a?.b`, `a?.[key]`, `a?.(...)`.
- Оператор срабатывает только на `null`/`undefined`, не на другие «ложные» значения.
- Остаток цепочки при обрыве не вычисляется (в том числе побочные эффекты).
- Использовать для чтения и вызова, но не для записи; ставить только там, где данные необязательны.
