# Операторы сравнения

Сравнения возвращают булево значение и лежат в основе условий и циклов. Для чисел всё очевидно, но со строками, разными типами, `null` и `undefined` у JavaScript есть правила, которые нужно знать, чтобы не получить неожиданный `true`.

## Операторы

Доступны `>`, `<`, `>=`, `<=`, а также равенство `==`, `===` и неравенство `!=`, `!==`. Результат всегда `true` или `false`:

```js
console.log(2 > 1);  // true
console.log(2 == 1); // false
console.log(2 != 1); // true
const result = 5 > 4;
console.log(result); // true
```

## Сравнение строк

Строки сравниваются посимвольно, «по словарю», но порядок определяется кодами символов Unicode, а не алфавитом. Сначала сравниваются первые символы; если они равны, вторые, и так далее; более короткая строка при равном начале считается меньшей.

```js
console.log('Bee' > 'Be');      // true
console.log('Glow' < 'Glee');   // false
console.log('a' < 'b');         // true
console.log('Z' < 'a');         // true (код заглавной буквы меньше)
console.log('a' > 'A');         // true
```

Поэтому сортировка строк «как в словаре» с разным регистром или с буквами вроде `ä` без специального сравнения даёт неожиданный порядок. Для языковых правил есть `localeCompare`.

```js
console.log('a'.localeCompare('b')); // -1
console.log(['b', 'a', 'C'].sort());  // [ 'C', 'a', 'b' ]
console.log(['b', 'a', 'C'].sort((x, y) => x.localeCompare(y))); // [ 'a', 'b', 'C' ]
```

## Сравнение разных типов

Если типы операндов различаются, оба значения сначала превращаются в числа — как в уроке о преобразованиях:

```js
console.log('2' > 1);      // true
console.log('01' == 1);    // true
console.log(true == 1);    // true
console.log('0' == false); // true
console.log(0 == '');      // true
```

Нюанс: если **оба** операнда строки, сравнение строковое, а не числовое:

```js
console.log('2' > '12'); // true
console.log(2 > '12');   // false
```

## Строгое равенство

Проблема обычного `==`: он не отличает `0` от `false` и от пустой строки. Оператор строгого равенства `===` сравнивает без приведения типов: значения разных типов никогда не равны.

```js
console.log(0 == false);   // true
console.log(0 === false);  // false
console.log('' == false);  // true
console.log('1' === 1);    // false
```

В реальном коде по умолчанию используют `===` и `!==`, а `==` оставляют для редких сознательных случаев.

Объекты сравниваются по ссылке: два разных объекта не равны, даже если выглядят одинаково.

```js
console.log({} == {});   // false
console.log([1] === [1]); // false
```

## null и undefined

При строгом сравнении они различны. При нестрогом равенстве они равны друг другу и **больше ничему**:

```js
console.log(null === undefined); // false
console.log(null == undefined);  // true
console.log(null == 0);          // false
console.log(undefined == 0);     // false
```

Здесь живёт знаменитая странность. Операторы `>`, `<`, `>=`, `<=` приводят `null` к числу `0`, а `undefined` — к `NaN`. Равенство же `==` для `null` особое и такого приведения не делает.

```js
console.log(null > 0);   // false
console.log(null == 0);  // false
console.log(null >= 0);  // true
console.log(undefined > 0);  // false
console.log(undefined >= 0); // false
```

Получается, что `null` не больше нуля и не равен нулю, но «больше или равен». Любое сравнение с `undefined` (кроме равенства с `null`) даёт `false`, потому что `NaN` не равен и не сравним ни с чем. Чтобы избежать неоднозначности, проверяйте `null` и `undefined` отдельно и строго.

Идиома `value == null` проверяет оба значения сразу:

```js
function isNullish(value) {
  return value == null;
}
console.log(isNullish(null), isNullish(undefined), isNullish(0)); // true true false
```

## NaN

`NaN` не равен ничему, даже самому себе, поэтому проверяют `Number.isNaN(x)` (или `Object.is(x, NaN)`):

```js
console.log(NaN == NaN);          // false
console.log(Number.isNaN(NaN));   // true
console.log(Object.is(NaN, NaN)); // true
```

## Типичные ошибки

- Использовать `==`, где нужен `===`: `0 == ''` — истина.
- Сравнивать строки с числами как числа: `'10' < '9'` — истина (оба значения строки).
- Рассчитывать, что разные объекты с одинаковым содержимым равны.
- Проверять `x === NaN` вместо `Number.isNaN(x)`.
- Сравнивать `null` с нулём через `>=` и ожидать симметрии с `==`.

## Коротко

- Результат сравнения — всегда булево значение.
- Строки сравниваются по кодам символов; для языковых правил — `localeCompare`.
- При разных типах значения приводятся к числам; две строки — сравниваются как строки.
- `===` не приводит типы и безопаснее `==`; объекты равны только по ссылке.
- `null == undefined` истинно, но больше ни с чем `==` не даёт `true`; в `>=` и `<=` `null` работает как `0`.
- `NaN` не равен ничему.
