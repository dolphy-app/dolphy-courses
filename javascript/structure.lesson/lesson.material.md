# Структура кода

Чтобы читать чужой код и не попадать в ловушки синтаксиса, нужно знать три вещи: как разделяются инструкции, когда точка с запятой необязательна и как писать комментарии.

## Инструкции

Программа состоит из **инструкций** — отдельных команд. Обычно каждую пишут на своей строке и заканчивают точкой с запятой:

```js
const a = 2;
const b = 3;
console.log(a + b); // 5
```

Несколько инструкций можно поместить в одну строку, но читать такое неудобно:

```js
const x = 1; const y = 2; console.log(x + y); // 3
```

## Точка с запятой и автоматическая вставка

Часто точку с запятой можно опустить: если инструкция заканчивается переводом строки, движок сам вставит `;`. Эта возможность называется **автоматической вставкой точки с запятой** (ASI):

```js
const a = 1
const b = 2
console.log(a + b) // 3
```

Но движок вставляет `;` не всегда, а только когда следующая строка *не может быть продолжением* предыдущей. Если она может, перевод строки игнорируется. Поэтому такой код работает, хотя выглядит странно:

```js
const total = 1 +
  2
console.log(total) // 3
```

Опасность возникает, когда следующая строка начинается с `(`, `[`, `+`, `-`, `/` или обратной кавычки. Тогда движок честно склеит две строки:

```js
let x = 5
let y = x
(1 + 2).toString()
// TypeError: x is not a function
```

Движок прочитал это как `let y = x(1 + 2).toString()` — вызов числа как функции. Из-за таких ловушек многие команды пишут точки с запятой всегда, а другие — никогда, но тогда ставят `;` в начале опасных строк. В этом курсе мы пишем их всегда.

### Вставка после return

Ещё одна неожиданность: перевод строки сразу после `return` считается концом инструкции.

```js
function getValue() {
  return
    42;
}
console.log(getValue()); // undefined
```

Функция вернула `undefined`, а `42` стало недостижимой инструкцией. Чтобы значение возвращалось, его начинают на той же строке, что и `return`. Для длинных выражений открывают скобку на этой же строке:

```js
function getSum(a, b) {
  return (
    a +
    b
  );
}
console.log(getSum(1, 2)); // 3
```

## Комментарии

Комментарии не выполняются. Однострочный начинается с `//`, а многострочный заключён между `/*` и `*/`:

```js
// Это комментарий в одну строку
console.log(1); // можно и после кода

/* Многострочный
   комментарий */
console.log(2); // 2
```

Вложенные многострочные комментарии не поддерживаются: первый же `*/` закончит комментарий, и остаток будет разобран как код — получится ошибка синтаксиса.

Хороший комментарий объясняет, **зачем** сделано что-то неочевидное, а не пересказывает код. Если комментарий нужен, чтобы понять, что делает строка, чаще стоит переименовать переменные или разбить код на функции.

## Типичные ошибки

- Начинать строку со скобки или `[` в коде без точек с запятой: строка присоединится к предыдущей.
- Разделять `return` и возвращаемое значение переводом строки.
- Пытаться вложить `/* ... */` один в другой.
- Писать комментарии, которые устарели после правки кода.

## Коротко

- Инструкции разделяются `;` или переводом строки, но перевод строки работает не всегда.
- Если следующая строка может быть продолжением выражения (`(`, `[`, `+`...), точка с запятой не вставится.
- После `return` перевод строки заканчивает инструкцию.
- Комментарии: `//` и `/* */`; вложенные многострочные не работают.
