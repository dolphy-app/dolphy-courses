# Юникод и устройство строк

Строка в JavaScript кажется простой: набор символов, у которого есть `length` и индексы. На самом деле строка внутри — последовательность 16-битных значений, а «символ», который видит человек, может состоять из одного, двух и даже десятка таких значений. Из-за этого `'😀'.length` равно 2, а два визуально одинаковых слова могут оказаться неравными. В этом уроке разберём, как устроены строки, и какие инструменты есть для работы с ними правильно.

## Кодовые точки и кодовые единицы

Стандарт Юникод присваивает каждому символу номер — **кодовую точку** (code point). Записывают её как `U+0041` (латинская `A`) или `U+1F600` (смайлик 😀). Всего кодовых точек больше миллиона: от `U+0000` до `U+10FFFF`.

JavaScript хранит строки в кодировке UTF-16: каждый элемент строки — **кодовая единица** (code unit), число от 0 до 65535. Кодовые точки до `U+FFFF` занимают одну единицу. Всё, что выше (эмодзи, редкие иероглифы, математические буквы), записывается **суррогатной парой** — двумя единицами подряд: первая из диапазона `0xD800–0xDBFF`, вторая из `0xDC00–0xDFFF`.

```js
const smile = '😀';
console.log(smile.length);          // 2
console.log(smile.charCodeAt(0));   // 55357 (0xD83D, старший суррогат)
console.log(smile.charCodeAt(1));   // 56832 (0xDE00, младший суррогат)
console.log(smile.codePointAt(0));  // 128512 (0x1F600, настоящая кодовая точка)
```

Отсюда главное правило: `length`, индексы `str[i]`, `charAt`, `charCodeAt`, `slice`, `substring`, `split('')` работают с **кодовыми единицами**, а не с символами. Разрезав суррогатную пару, вы получите «осиротевший» суррогат — бессмысленный полусимвол.

```js
console.log('😀'.split(''));             // [ '\ud83d', '\ude00' ]
console.log('a😀b'.slice(0, 2).length);  // 2 ('a' и половина эмодзи)
```

Во втором примере срез `slice(0, 2)` содержит `'a'` и половину эмодзи — строку длиной 2, которая отображается как мусор.

## Создание символов по номеру

Для записи символов в литералах есть escape-последовательности:

- `\xNN` — две hex-цифры, кодовая точка до `U+00FF`;
- `\uNNNN` — четыре hex-цифры, одна кодовая единица;
- `\u{N...}` — от одной до шести hex-цифр, любая кодовая точка.

```js
console.log('\u0041');        // A
console.log('\u{1F600}');     // 😀
console.log('\u{1F600}' === '😀'); // true
```

Для получения символа из числа служат `String.fromCharCode` (принимает кодовые единицы, поэтому для больших номеров нужно самому считать пару) и `String.fromCodePoint` (принимает кодовую точку целиком):

```js
console.log(String.fromCodePoint(0x1F600) === '😀'); // true
```

Обратная операция — `codePointAt(pos)`. Она смотрит на единицу в позиции `pos`: если там старший суррогат и следом младший, вернёт номер всей точки. Но позиция по-прежнему в единицах: для `'😀'` вызов `codePointAt(1)` вернёт `56832` — номер одиночного младшего суррогата.

## Итерация по символам

Строковый итератор (его используют `for...of`, spread, `Array.from`) идёт **по кодовым точкам**, а не по единицам:

```js
console.log([...'a😀b'].length);        // 3
console.log(Array.from('a😀b').length); // 3
console.log('a😀b'.length);             // 4
for (const ch of 'a😀') console.log(ch); // a, затем 😀
```

Поэтому правильный разворот строки — `[...str].reverse().join('')`, а не `str.split('').reverse().join('')` (последний ломает суррогатные пары — они меняются местами внутри себя).

```js
console.log([...'a😀b'].reverse().join('')); // b😀a
```

Аналогично обрезка по числу символов: `[...str].slice(0, n).join('')`.

## Флаг `u` в регулярных выражениях

Без флага `u` регулярное выражение тоже видит единицы: точка `.` сопоставляется с одной единицей, а значит эмодзи «состоит из двух символов».

```js
console.log('a😀b'.replace(/./g, 'x'));  // xxxx
console.log('a😀b'.replace(/./gu, 'x')); // xxx
console.log(/^.$/u.test('😀'));          // true
console.log(/^.$/.test('😀'));           // false
```

С флагом `u` появляются и **свойства Юникода** `\p{...}`: выбор символов по категории или письменности. Без `u` `\p{L}` — это просто буква `p` и далее фигурные скобки.

```js
console.log(/\p{L}/u.test('ж'));                        // true (буква)
console.log(/^\p{Script=Cyrillic}+$/u.test('привет'));  // true
console.log(/\p{Lu}/u.test('a'));                       // false (заглавная буква)
console.log(/\p{Emoji}/u.test('😀'));                   // true
console.log(/\p{L}/.test('ж'));                         // false (нет флага u)
```

Это удобный способ проверять «буква любого языка», вместо `[а-яa-z]`, который не охватит ни `ё` в диапазоне, ни немецкие умлауты.

## Нормализация

Один и тот же видимый символ можно записать разными последовательностями. Буква `é` — это либо одна точка `U+00E9`, либо `e` плюс combining-знак «акут» `U+0301`. На экране они идентичны, но для JavaScript это разные строки.

```js
const composed = '\u00e9';
const decomposed = 'e\u0301';
console.log(composed === decomposed);                 // false
console.log(composed.length, decomposed.length);      // 1 2
console.log(decomposed.normalize() === composed);     // true
console.log(composed.normalize('NFD') === decomposed); // true
```

`str.normalize(form)` приводит строку к одной из канонических форм:

| Форма | Что делает |
|---|---|
| `NFC` (по умолчанию) | собирает символы с диакритикой в одну точку, где возможно |
| `NFD` | разбирает на базовый символ и combining-знаки |
| `NFKC`, `NFKD` | дополнительно заменяет «совместимые» формы: `'ﬁ'` → `'fi'`, `'①'` → `'1'` |

Перед сравнением, поиском или использованием строки как ключа (имена пользователей, пути, теги) строки из внешнего мира стоит нормализовать. Иначе «Café» из одного источника не найдётся в «Café» из другого.

## Графемы: символ глазами человека

Даже кодовая точка — не всегда то, что пользователь считает одним символом. Минимальная единица «как воспринимает человек» называется **графемным кластером**. Семейный эмодзи 👨‍👩‍👧 — это пять кодовых точек (три человека и два невидимых соединителя `U+200D`), то есть восемь кодовых единиц. Флаг 🇷🇺 — две «региональные» точки.

```js
const family = '👨‍👩‍👧';
console.log(family.length);       // 8
console.log([...family].length);  // 5
const seg = new Intl.Segmenter('en', { granularity: 'grapheme' });
console.log([...seg.segment(family)].length); // 1
console.log([...seg.segment('🇷🇺🇺🇸')].length); // 2
```

`Intl.Segmenter` (есть в Node 22) делит текст на графемы, слова или предложения. Если нужно ограничить длину поля «по символам» так, как её видит пользователь, используйте его.

## Корректность строки

Строка, содержащая одиночный суррогат, называется «неправильно сформированной». JSON, URL-кодирование и `TextEncoder` с ней работают плохо. В ES2024 появились методы:

```js
console.log('\ud83d'.isWellFormed());     // false
console.log('😀'.isWellFormed());         // true
console.log('\ud83dx'.toWellFormed());    // �x (одиночный суррогат заменён на U+FFFD)
```

`encodeURIComponent('\ud83d')` бросает `URIError`, а `encodeURIComponent('😀')` даёт корректные `%F0%9F%98%80` — в UTF-8 это 4 байта.

## Сравнение и регистр

Оператор `<` сравнивает кодовые единицы, а не «алфавитный порядок»: `'ä' < 'z'` будет `false`, потому что код `ä` (228) больше кода `z` (122). Для естественного порядка есть `localeCompare` (подробнее — в уроке про `Intl`).

Преобразование регистра тоже зависит от языка: `'ß'.toUpperCase()` даёт `'SS'` (длина строки изменилась), а `'I'.toLocaleLowerCase('tr')` — турецкую `'ı'`.

## Типичные ошибки

> [!WARNING]
>
> - Считать `str.length` числом символов для пользовательского ввода.
> - Разворачивать или обрезать строку через `split('')` / `slice` и ломать эмодзи.
> - Сравнивать строки через `===` без нормализации, когда они пришли из разных систем.
> - Писать диапазоны вроде `[а-я]` для проверки «буква» и забывать про `ё`, иные языки и флаг `u`.
> - Забывать, что даже `[...str]` не решает проблему составных эмодзи и combining-знаков — для графем нужен `Intl.Segmenter`.

## Коротко

> [!TIP]
>
> - Строка JS — последовательность UTF-16 кодовых единиц; символы выше `U+FFFF` занимают две единицы.
> - `length`, индексы, `slice`, `split('')` считают единицы; `for...of`, spread, `Array.from` и `codePointAt` с `fromCodePoint` работают с кодовыми точками.
> - Флаг `u` у регулярок включает работу с точками и свойства `\p{...}`.
> - `normalize()` приводит эквивалентные записи к одной форме; делайте это перед сравнением внешних строк.
> - Для «символов, как их видит человек» используйте `Intl.Segmenter` с `granularity: 'grapheme'`.
