# setTimeout и setInterval

Иногда функцию нужно вызвать не сейчас, а чуть позже — через секунду или регулярно, раз в несколько сотен миллисекунд. Для этого есть планировщики `setTimeout` и `setInterval`. Они не входят в сам язык (их описывают стандарты окружений), но есть и в браузерах, и в Node.js, и работают почти одинаково.

## setTimeout: отложенный вызов

```js
setTimeout(func, delay, arg1, arg2, ...)
```

Первый параметр — функция (не строка с кодом!), второй — задержка в миллисекундах, остальные — аргументы, которые будут переданы функции при вызове.

```js
function greet(name, mark) {
  console.log('Привет, ' + name + mark);
}

setTimeout(greet, 10, 'Аня', '!'); // через 10 мс: Привет, Аня!
console.log('сначала это');
```

Вывод:

```
сначала это
Привет, Аня!
```

Текущий код всегда дорабатывает до конца, и только потом планировщик берётся за отложенные задачи. Передавайте именно функцию: `setTimeout(greet('Аня'), 10)` вызовет `greet` немедленно, а в таймер попадёт её результат (`undefined`): браузер молча ничего не запланирует, а Node.js бросит `TypeError` с кодом `ERR_INVALID_ARG_TYPE`.

## Отмена: clearTimeout

`setTimeout` возвращает идентификатор таймера. В браузере это число, в Node.js — объект `Timeout`. Его передают в `clearTimeout`, чтобы отменить вызов, пока он не случился.

```js
const id = setTimeout(() => console.log('не выведется'), 20);
clearTimeout(id);

setTimeout(() => console.log('выведется'), 30);
// выведется
```

Повторная отмена или отмена уже сработавшего таймера безвредна: ничего не происходит.

## setInterval: повторяющийся вызов

`setInterval` принимает те же аргументы, но вызывает функцию снова и снова, пока её не остановит `clearInterval`.

```js
let ticks = 0;
const timer = setInterval(() => {
  ticks++;
  console.log('тик', ticks);
  if (ticks === 3) clearInterval(timer);
}, 10);
// тик 1
// тик 2
// тик 3
```

Остановка изнутри — обычный приём: идентификатор доступен в замыкании. Если не вызвать `clearInterval`, в Node.js процесс не завершится, пока таймер жив.

## Вложенный setTimeout вместо setInterval

У `setInterval` есть тонкость: отсчёт идёт от момента запуска, а не от момента окончания предыдущего вызова. Если функция работает долго, пауза между вызовами сокращается, а то и исчезает совсем. Вложенный `setTimeout` планирует следующий вызов уже после работы, поэтому пауза между окончанием одного и началом другого гарантирована:

```js
let n = 0;
function tick() {
  n++;
  console.log('вызов', n);
  if (n < 3) setTimeout(tick, 10);
}
setTimeout(tick, 10);
// вызов 1
// вызов 2
// вызов 3
```

Бонус: задержку можно менять от шага к шагу (например, увеличивать при ошибках) — с `setInterval` так не выйдет.

## Нулевая задержка

`setTimeout(func, 0)` (или без второго аргумента) не вызывает функцию мгновенно. Она выполнится после завершения текущего синхронного кода и уже стоящих перед ней микрозадач (например, колбэков промисов):

```js
setTimeout(() => console.log('таймер'), 0);
Promise.resolve().then(() => console.log('микрозадача'));
console.log('синхронный код');
// синхронный код
// микрозадача
// таймер
```

Этим пользуются, чтобы «отложить на потом», не блокируя текущую работу. Реальная задержка обычно не нулевая: браузеры ограничивают её снизу (около 4 мс при глубокой вложенности), а Node.js приводит 0 к 1 мс.

## Задержка — «не раньше», а не «ровно»

Указанное время — минимум. Если в этот момент занят поток (идёт тяжёлый код), вызов сдвинется. Поэтому не стройте логику на точных миллисекундах; полагайтесь на порядок событий. Два таймера с разными задержками выполнятся в порядке возрастания задержек, а с равными — в порядке создания:

```js
setTimeout(() => console.log('B'), 20);
setTimeout(() => console.log('A'), 10);
setTimeout(() => console.log('C'), 20);
// A
// B
// C
```

## Контекст `this`

Если в таймер передать метод объекта без привязки, он потеряет `this` (подробнее — в уроке про `bind`). В Node.js `this` внутри колбэка — сам объект `Timeout`, поэтому ошибка может не бросить исключение, а тихо дать `undefined`:

```js
const user = {
  name: 'Ира',
  hello() {
    console.log(this === user);
  },
};
setTimeout(user.hello, 10); // false
setTimeout(() => user.hello(), 20); // true
```

## Типичные ошибки

> [!WARNING]
>
> - `setTimeout(f(), 100)` вместо `setTimeout(f, 100)`.
> - Забыть остановить `setInterval` — утечка и бесконечная работа.
> - Ожидать точной задержки или того, что `setTimeout(f, 0)` сработает сразу.
> - Потерять идентификатор и не суметь отменить таймер.

## Коротко

> [!TIP]
>
> - `setTimeout(f, ms, ...args)` вызывает `f` один раз через не менее чем `ms` миллисекунд; `clearTimeout(id)` отменяет.
> - `setInterval(f, ms, ...args)` вызывает `f` повторно; останавливается `clearInterval(id)`.
> - Вложенный `setTimeout` гарантирует паузу между вызовами и позволяет менять задержку.
> - Нулевая задержка означает «после текущего кода», но не «немедленно»; микрозадачи идут раньше таймеров.
> - Задержка — минимум; в логике опирайтесь на порядок, а не на точное время.
