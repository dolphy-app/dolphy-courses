# Сборка мусора

В JavaScript нет ни `malloc`, ни `free`: вы создаёте строки, объекты и функции, а память под них выделяется сама. Освобождается она тоже сама — этим занимается *сборщик мусора* движка. Знать, как он принимает решения, полезно по двум причинам: так проще понять, почему «лишний» объект иногда не пропадает (утечки памяти), и почему он пропадает, даже если на него кто-то ссылается.

## Достижимость

Главное понятие — *достижимость*. Значение считается достижимым, если до него можно добраться из «корней» по ссылкам. Достижимые значения гарантированно остаются в памяти.

Корни — это значения, которые удалить нельзя в принципе:

- текущая выполняющаяся функция: её параметры и локальные переменные;
- другие функции из цепочки вызовов, которая привела к текущей, и их переменные;
- глобальные переменные;
- некоторые внутренние значения движка.

Всё остальное достижимо, если на него есть ссылка из корня или из другого достижимого значения. Если в глобальной переменной лежит объект, а в его свойстве — ссылка на второй объект, то второй тоже достижим, как и всё, на что ссылается он.

Всё, что недостижимо, сборщик имеет право удалить. «Имеет право» — не «обязан немедленно»: когда именно он сработает, решает движок, и повлиять на это из кода нельзя.

## Одна ссылка

```js
let user = { name: 'John' };   // глобальная переменная → объект
```

Пока `user` хранит ссылку, объект достижим. Стоит затереть единственную ссылку, и он становится мусором:

```js
user = null;                    // на объект больше никто не указывает
```

Сам по себе `null` ничего не «удаляет»: просто путь от корня к объекту исчез.

## Две ссылки

Если ссылку успели скопировать, одной потери недостаточно:

```js
let user = { name: 'John' };
let admin = user;     // теперь два пути к одному объекту

user = null;
console.log(admin.name); // John — объект достижим через admin
```

Объект удалят только после того, как исчезнет и вторая ссылка (`admin = null`).

## Входящие и исходящие ссылки

Для достижимости имеют значение только *входящие* ссылки — те, что ведут к объекту от корня. Ссылки, которые объект сам хранит на другие объекты, ему не помогают.

Возьмём семью:

```js
function marry(man, woman) {
  woman.husband = man;
  man.wife = woman;

  return { father: man, mother: woman };
}

let family = marry({ name: 'John' }, { name: 'Ann' });
```

Теперь `family` указывает на два объекта, а John и Ann ссылаются друг на друга. До John можно добраться двумя путями: `family.father` и `family.mother.husband`. Если убрать только один из них, объект всё равно достижим по другому:

```js
delete family.father;
console.log(family.mother.husband.name); // John — второй путь жив
```

А когда уберём и второй, у John не останется входящих ссылок из достижимой части:

```js
delete family.mother.husband;
console.log(family); // { mother: { name: 'Ann' } }
```

John недостижим, хотя у него самого есть исходящая ссылка `wife` на Ann. Он будет удалён вместе с тем, что доступно только через него.

## Недостижимый «остров»

Объекты, ссылающиеся друг на друга, не спасают друг друга. Если вся группа отрезана от корней, она исчезает целиком:

```js
let family = marry({ name: 'John' }, { name: 'Ann' });
family = null;
```

После этого и John, и Ann, и объект-семья недостижимы: у John и Ann есть входящие ссылки, но только из таких же недостижимых объектов. Это принципиальное отличие от простого «подсчёта ссылок» (счётчика входящих ссылок на объект), который циклы не умеет освобождать. Для сборщика с точкой отсчёта в корнях цикл — не проблема.

## Алгоритм пометок

Основной алгоритм называется *mark-and-sweep* («пометить и вымести»). Он периодически выполняет такие шаги:

1. Помечает все корни.
2. Обходит ссылки из помеченных значений и помечает то, на что они указывают. Уже посещённые не обходятся повторно — поэтому циклы не вызывают бесконечного обхода.
3. Повторяет, пока не останется непосещённых ссылок.
4. Удаляет всё непомеченное.

Тот же обход в виде кода (набросок для понимания, а не настоящий сборщик):

```js
function mark(roots) {
  const seen = new Set();
  const stack = [...roots];

  while (stack.length > 0) {
    const obj = stack.pop();
    if (seen.has(obj)) continue;        // уже посещали — защита от циклов
    seen.add(obj);

    for (const value of Object.values(obj)) {
      if (typeof value === 'object' && value !== null) {
        stack.push(value);
      }
    }
  }
  return seen;
}

const a = { name: 'a' };
const b = { name: 'b' };
const c = { name: 'c' };
const d = { name: 'd' };
a.next = b; b.next = a;     // цикл a ↔ b, достижим из корня
c.next = d; d.next = c;     // другой цикл c ↔ d, остров
a.owner = { x: 1 };

const marked = mark([a]);
console.log(marked.size);   // 3 (a, b и объект owner)
console.log(marked.has(b)); // true
console.log(marked.has(c)); // false — будет удалён
```

Образно: из каждого корня льётся краска и течёт по всем ссылкам; всё, что осталось сухим, уходит.

## Оптимизации

Простой обход всей памяти заметно тормозил бы программу, поэтому движки применяют приёмы:

- **Поколения.** Объекты делят на «новые» и «старые». Большинство объектов живёт очень недолго, поэтому молодых проверяют часто и дёшево, а те, что пережили несколько проверок, становятся «старыми» и проверяются реже.
- **Инкрементальность.** Обход дробят на небольшие порции, чередуя их с работой программы, чтобы не было долгих пауз.
- **Простой процессора.** Часть работы откладывают на моменты, когда программа ничего не делает.

Конкретика различается между движками (V8, SpiderMonkey, JavaScriptCore) и меняется от версии к версии, поэтому на уровне языка важна только идея достижимости.

## Утечки памяти

Раз удаляется только недостижимое, «утечка» в JavaScript — это объект, который вам уже не нужен, но до которого всё ещё можно добраться. Типичные причины:

```js
const cache = {};                  // живёт, пока жив скрипт

function remember(obj) {
  cache.last = obj;                // кеш держит ссылку
}

let order = { id: 1 };
remember(order);
order = null;                      // объект всё равно достижим: cache.last → объект
console.log(cache.last.id);        // 1
```

Так же держат объекты забытые глобальные переменные, растущие без очистки массивы и `Map`, обработчики событий, которые никто не снял, и замыкания, в которых хранятся большие данные. Лечение одно: убрать лишнюю ссылку (`cache.last = null`, `delete cache.key`, очистка коллекции).

## Типичные ошибки

- «Присвою `null` — память освободится сразу». Нет: вы лишь убрали ссылку; удалять объект или нет и когда — решает сборщик.
- «Пока на объект кто-то ссылается, он не удалится». Неверно: важны ссылки от корней. Группа взаимосвязанных объектов может быть недостижима целиком.
- Искать способ «вызвать сборку мусора из кода». В обычном JavaScript такого средства нет; в Node.js есть флаг `--expose-gc`, но это инструмент для отладки.
- Считать, что исходящие ссылки объекта удерживают его самого. Удерживают только входящие.

## Коротко

- Память под значения выделяется и освобождается автоматически.
- Значение остаётся в памяти, пока оно достижимо из корней: локальных и глобальных переменных, цепочки вызовов.
- Недостижимым может стать целый «остров» объектов, даже если они ссылаются друг на друга.
- Основной алгоритм — mark-and-sweep: пометить достижимое, удалить остальное; движки ускоряют его по-разному.
- Утечка — это ненужный, но всё ещё достижимый объект; чтобы его освободить, уберите последнюю ссылку.
