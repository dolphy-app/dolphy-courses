# WeakMap и WeakSet

Обычные `Map` и `Set` держат свои ключи и значения «крепко»: пока коллекция жива, объекты внутри неё не удалит сборщик мусора. Это удобно, но порой превращается в утечку памяти. `WeakMap` и `WeakSet` — «слабые» варианты, которые не мешают сборщику мусора убрать объект. В этом уроке разберём, как они устроены, чем ограничены и для каких задач нужны.

## Проблема: коллекция удерживает объект

Вспомните правило сборки мусора: объект живёт, пока до него можно добраться от корней (глобальных переменных, стека вызовов). Ссылка из `Map` — тоже ссылка:

```js
let user = { name: 'Анна' };
const cache = new Map();
cache.set(user, 'данные о пользователе');

user = null;
console.log(cache.size); // 1 — объект всё ещё достижим через cache
```

Переменная `user` обнулена, но объект остаётся в памяти: на него ссылается ключ в `cache`. Если кэш живёт долго, а ключей много, память растёт, пока вы вручную не вызовете `cache.delete`.

## WeakMap

`WeakMap` устроен как `Map`, но с двумя отличиями:

1. **Ключом может быть только объект** (а также несвязанный с реестром символ). Примитивы — строки, числа — недопустимы.
2. Ссылка на ключ **слабая**: если на объект-ключ больше нет других ссылок, запись можно удалить из памяти вместе со значением.

```js
const weak = new WeakMap();
const key = {};

weak.set(key, 'значение');
console.log(weak.get(key)); // 'значение'
console.log(weak.has(key)); // true
console.log(weak.delete(key)); // true
console.log(weak.has(key)); // false

weak.set('str', 1); // TypeError: Invalid value used as weak map key
```

Методов у `WeakMap` всего четыре: `set`, `get`, `has`, `delete`. Нет `size`, `clear`, `keys()`, `values()`, `entries()`, `forEach` и итерации вообще:

```js
const w = new WeakMap();
console.log(typeof w.size);              // 'undefined'
console.log(typeof w.forEach);           // 'undefined'
console.log(typeof w[Symbol.iterator]);  // 'undefined'
```

### Почему нельзя перебрать или узнать размер

Момент, когда сборщик мусора удалит запись, зависит от движка и не определён. Если бы можно было спросить `size` или перебрать ключи, результат менялся бы непредсказуемо от запуска к запуску. Поэтому спецификация такого интерфейса не даёт: вы можете спросить только про конкретный объект, который у вас уже есть в руках.

## Зачем это нужно

### Дополнительные данные об объекте

Классическая задача: нужно привязать к объекту данные, не изменяя его и не продлевая ему жизнь. Пока объект существует — данные доступны; как только объект ушёл — данные исчезли вместе с ним.

```js
const visitsCount = new WeakMap();

function countVisit(user) {
  const count = visitsCount.get(user) ?? 0;
  visitsCount.set(user, count + 1);
}

let alice = { name: 'Alice' };
countVisit(alice);
countVisit(alice);
console.log(visitsCount.get(alice)); // 2

alice = null; // объект и его счётчик станут доступны для сборки
```

Была бы вместо `WeakMap` обычная `Map`, пришлось бы помнить об очистке.

### Кэш результатов

Кэширование результата тяжёлой функции для объекта-аргумента: пока объект жив, результат переиспользуется, после — освобождается.

```js
const cache = new WeakMap();

function process(obj) {
  if (!cache.has(obj)) {
    cache.set(obj, Object.keys(obj).length); // «тяжёлое» вычисление
  }
  return cache.get(obj);
}

const data = { a: 1, b: 2 };
console.log(process(data)); // 2
console.log(process(data)); // 2, из кэша
```

### Приватные данные

До появления приватных полей классов (`#field`) в `WeakMap` хранили скрытое состояние экземпляров: карта известна только модулю, снаружи к ней не добраться.

## WeakSet

`WeakSet` — слабое множество. Хранит только объекты, методы `add`, `has`, `delete`, без `size` и перебора. Типичное применение — пометка «этот объект уже обработан / посещён».

```js
const seen = new WeakSet();
const a = {};
const b = {};

seen.add(a);
console.log(seen.has(a)); // true
console.log(seen.has(b)); // false
console.log(seen.has({})); // false — это новый объект

seen.add(1); // TypeError
```

Если объект исчезнет из остальной программы, он исчезнет и из `WeakSet`, а значит, пометки не будут копиться бесконечно.

## Сводка отличий

| | Map / Set | WeakMap / WeakSet |
|---|---|---|
| Ключи (значения для Set) | любые | только объекты |
| Ссылка на ключ | сильная | слабая |
| `size`, перебор, `clear` | есть | нет |
| Подходит для | основных данных | вспомогательных данных об объектах |

Значения `WeakMap` (не ключи) удерживаются ровно до тех пор, пока жив ключ; сам объект-ключ из значения можно не ссылать — иначе значение само продлит жизнь ключу и запись не удалится.

## Типичные ошибки

> [!WARNING]
>
> - Пытаться положить в `WeakMap` строку или число как ключ — получите `TypeError`.
> - Ожидать `weakMap.size` или `for...of` по `WeakSet`.
> - Считать, что запись исчезнет «сразу» после обнуления переменной: сборщик работает, когда решит движок, и проверить это из кода нельзя.
> - Использовать `WeakMap` там, где ключи нужно перечислять, — для этого есть `Map`.

## Коротко

> [!TIP]
>
> - `WeakMap` и `WeakSet` не мешают сборщику мусора удалять объекты-ключи.
> - Ключи `WeakMap` и значения `WeakSet` — только объекты.
> - Доступны лишь `set/get/has/delete` и `add/has/delete`; размера и перебора нет.
> - Идеально подходят для вспомогательных данных об объекте: кэш, счётчики, пометки.
> - Если нужно перебирать или считать записи — берите обычные `Map` и `Set`.
