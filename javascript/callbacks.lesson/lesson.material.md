# Колбэки

Многие действия в JavaScript не завершаются мгновенно: прочитать файл, сходить на сервер, подождать таймер. Программа не должна «стоять» и ждать, поэтому такие функции работают **асинхронно**: они запускают действие и сразу возвращают управление, а результат сообщают позже. Самый простой способ получить результат — передать функцию, которую вызовут по готовности. Такая функция называется **колбэком** (callback, «функция обратного вызова»). Это основа, на которой потом вырастут промисы и `async/await`, поэтому важно понять её сильные и слабые стороны.

## Что такое колбэк

Колбэк — это просто функция, которую передают другой функции как аргумент в расчёте, что та вызовет её в нужный момент. Колбэки бывают синхронными и асинхронными. Синхронный вызывается прямо внутри функции, до того как она вернёт управление:

```js
const doubled = [1, 2, 3].map((x) => x * 2);
console.log(doubled); // [ 2, 4, 6 ]
```

Асинхронный вызывается позже, когда закончилось длительное действие. Простейший источник асинхронности — `setTimeout`:

```js
console.log('before');
setTimeout(() => console.log('timer'), 0);
console.log('after');
// before
// after
// timer
```

Даже с задержкой `0` колбэк таймера выполнится только после того, как закончится текущий синхронный код. Эту механику мы подробнее разберём в уроке про микрозадачи.

## Свой асинхронный API

Напишем функцию, которая «загружает» пользователя. Настоящего сервера у нас нет, поэтому имитируем задержку таймером. Принятое в Node.js соглашение — «error-first callback»: первым аргументом колбэк получает ошибку (или `null`, если всё хорошо), вторым — результат:

```js
function fetchUser(id, callback) {
  setTimeout(() => {
    if (id < 0) {
      callback(new Error('Нет такого id'));
    } else {
      callback(null, { id, name: 'User' + id });
    }
  }, 10);
}

console.log('начали');
fetchUser(1, (err, user) => {
  if (err) {
    console.log('ошибка:', err.message);
    return;
  }
  console.log('получили', user);
});
console.log('продолжаем');
// начали
// продолжаем
// получили { id: 1, name: 'User1' }
```

Результат функции `fetchUser` нельзя вернуть через `return`: к моменту, когда он появится, сама функция давно завершилась. Поэтому всё, что должно произойти *после* получения данных, нужно положить **внутрь** колбэка. Код «после» вызова выполнится раньше результата.

Почему ошибка идёт первым аргументом? Потому что её нельзя бросить через `throw` и поймать снаружи: `try..catch` вокруг вызова `fetchUser` не сработает, ведь колбэк запустится уже после выхода из `try`. Ошибку приходится передавать как обычное значение, а получатель обязан проверять её **сразу**, до использования результата.

## Колбэк в колбэке

Когда несколько асинхронных действий нужно выполнить по очереди, каждое следующее запускают из колбэка предыдущего:

```js
function step(name, callback) {
  setTimeout(() => {
    console.log(name);
    callback(null);
  }, 5);
}

step('a', (err) => {
  if (err) return;
  step('b', (err) => {
    if (err) return;
    step('c', (err) => {
      console.log('готово');
    });
  });
});
// a
// b
// c
// готово
```

Три шага ещё читаются. Но добавьте обработку ошибки на каждом уровне, ветвление и ещё пару шагов — и код превращается в «пирамиду судьбы» (callback hell): вложенность растёт вправо, ошибки обрабатываются в десяти местах, а порядок выполнения приходится выстраивать в голове.

Частично помогает рефакторинг: вынести каждый шаг в именованную функцию верхнего уровня и передавать по имени.

```js
function stepA(done) {
  setTimeout(() => done(null, 'A'), 5);
}

function stepB(prev, done) {
  setTimeout(() => done(null, prev + 'B'), 5);
}

function main() {
  stepA((err, a) => {
    if (err) return console.log('ошибка', err);
    stepB(a, (err, ab) => {
      if (err) return console.log('ошибка', err);
      console.log(ab); // AB
    });
  });
}

main();
```

Вложенность стала меньше, но нить повествования всё равно разорвана на куски: чтобы понять порядок, приходится прыгать по файлу. Именно эту проблему и решают промисы — следующая тема.

## Подводные камни колбэков

- **Колбэк, который вызван дважды.** Ничто не мешает функции вызвать его два раза или ни разу. Получатель не может это ни проверить, ни запретить.

```js
function bad(callback) {
  callback(null, 1);
  callback(null, 2); // забыли return после первого вызова
}

bad((err, value) => console.log('value', value));
// value 1
// value 2
```

- **Потерянный `this`.** Метод, переданный как колбэк, теряет объект:

```js
const counter = {
  n: 5,
  show() {
    return this && this.n;
  },
};

function run(callback) {
  return callback();
}

console.log(run(counter.show)); // undefined
console.log(run(() => counter.show())); // 5
```

В строгом режиме (модули ES, тела классов) `this` в таком вызове равен `undefined`, поэтому без проверки `this &&` обращение `this.n` бросило бы `TypeError`. В обычном режиме `this` — глобальный объект, у которого нет свойства `n`. Чтобы сохранить объект, оберните вызов в стрелку или используйте `bind`.

- **Смешение синхронного и асинхронного вызова.** Если функция иногда вызывает колбэк сразу (например, при ошибке аргументов), а иногда позже, поведение программы становится непредсказуемым. Правило: колбэк вызывается либо всегда синхронно, либо всегда асинхронно. Если нужно отложить, используйте `setTimeout(..., 0)` или `queueMicrotask`.

- **Ошибка внутри колбэка** после выхода из `try` уже не будет поймана внешним `try..catch`.

## Типичные ошибки

> [!WARNING]
>
> - Попытка получить результат через `return` из асинхронной функции: возвращается `undefined`, данные приходят позже.
> - Забыли проверить `err` и сразу работают с `result` — получают `undefined` и `TypeError`.
> - Забыли `return` после вызова колбэка с ошибкой, и код продолжает выполняться дальше.
> - Ждут, что `try..catch` поймает ошибку из асинхронного колбэка.

## Коротко

> [!TIP]
>
> - Колбэк — функция, переданная другой функции для вызова «потом».
> - Асинхронная функция не возвращает результат через `return`, он приходит в колбэк позже.
> - Соглашение Node.js: `callback(err, result)`; ошибку проверяют первой.
> - Последовательные асинхронные шаги порождают вложенность («пирамиду судьбы»); именованные функции только смягчают проблему.
> - Колбэк должен вызываться ровно один раз и всегда одинаково: либо синхронно, либо асинхронно.
