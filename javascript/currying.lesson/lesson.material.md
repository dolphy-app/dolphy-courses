# Каррирование

Каррирование — приём, при котором функция от нескольких аргументов превращается в цепочку функций от одного аргумента: вместо `f(a, b, c)` вызывают `f(a)(b)(c)`. Название — по имени математика Хаскелла Карри. В JavaScript приём не встроен в язык, но легко строится на замыканиях, и его часто используют для создания «заготовок» функций.

## Зачем это нужно

Главная польза — **частичное применение**: зафиксировать часть аргументов один раз и получить более специализированную функцию.

```js
function log(level, message) {
  return `[${level}] ${message}`;
}

const logWarn = (message) => log('WARN', message);
console.log(logWarn('disk is almost full')); // [WARN] disk is almost full
```

Здесь `logWarn` — частично применённая `log`: уровень «зашит», остаётся только сообщение. Такую функцию удобно передавать в `map`, в обработчики и в другие места, где ожидается один аргумент.

## Частичное применение без каррирования: bind

Если `this` не важен, заготовку делает `bind`: аргументы после первого фиксируются.

```js
function sum(a, b, c) {
  return a + b + c;
}

const add5 = sum.bind(null, 5);
console.log(add5(1, 2)); // 8
console.log(add5.length); // 2
```

Первый аргумент `bind` — это `this` (здесь он не нужен, поэтому `null`). Обратите внимание: `length` у результата уменьшился на число зафиксированных аргументов. Недостаток `bind` — он всегда требует передать `this` и фиксирует аргументы только слева.

Универсальная функция частичного применения без привязки `this` пишется в одну строку:

```js
const partial = (fn, ...preset) => (...rest) => fn(...preset, ...rest);

const add = partial((a, b, c) => a + b + c, 10);
console.log(add(1, 2)); // 13
```

## Настоящее каррирование

Каррированная функция принимает аргументы порциями: пока их набралось меньше, чем нужно, она возвращает новую функцию и ждёт остальных. Как только аргументов достаточно — вызывает исходную.

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return (...more) => curried.apply(this, args.concat(more));
  };
}

const volume = (w, h, d) => w * h * d;
const c = curry(volume);

console.log(c(2)(3)(4)); // 24
console.log(c(2, 3)(4)); // 24
console.log(c(2)(3, 4)); // 24
console.log(c(2, 3, 4)); // 24
```

Разберём, как это работает:

1. `fn.length` — число объявленных параметров исходной функции. Это и есть «сколько аргументов нужно».
2. Если переданных аргументов хватает, вызываем `fn` с накопленным списком (`apply` сохраняет `this`).
3. Иначе возвращаем обёртку, которая запоминает уже полученные `args` в замыкании и при вызове склеивает их с новыми.

Благодаря замыканию промежуточные функции можно сохранять и использовать повторно: каждая хранит свой набор аргументов, и друг на друга они не влияют.

```js
const volume = (w, h, d) => w * h * d;
const c = curry(volume);   // curry — из примера выше
const base = c(2);
console.log(base(3)(4));   // 24
console.log(base(10)(10)); // 200
```

## Ограничение: length

Каррирование через `fn.length` работает только для функций с фиксированным числом параметров. Параметры по умолчанию и rest-параметры «обрезают» `length`:

```js
const f = (a, b = 1, c) => 0;
const g = (a, ...rest) => 0;
console.log(f.length); // 1
console.log(g.length); // 1
```

У `f` `length` равен 1: подсчёт останавливается на первом параметре со значением по умолчанию. Поэтому `curry(f)` вызовет `f` уже после первого аргумента. Для функций с переменным числом аргументов приходится договариваться иначе, например считать «конец» по пустому вызову:

```js
function sumAll(first) {
  let total = first;
  function next(value) {
    if (value === undefined) return total;
    total += value;
    return next;
  }
  return next;
}

console.log(sumAll(1)(2)(3)()); // 6
```

Обратите внимание, что здесь состояние `total` общее для всех вызовов цепочки: если сохранить `next` и вызвать повторно, накопление продолжится. Это уже не «чистое» каррирование, а функция с состоянием.

```js
const s = sumAll(1);
s(2);
console.log(s()); // 3
```

## Где это применяют на практике

Типичный случай — функции-«фабрики» обработчиков и преобразователей. Вместо того чтобы каждый раз писать стрелку-обёртку, каррированная функция сразу даёт нужную заготовку:

```js
const multiply = (k) => (x) => x * k;
const triple = multiply(3);
console.log([1, 2, 3].map(triple)); // [3, 6, 9]
```

Здесь `multiply` каррирована «вручную»: она принимает один аргумент и возвращает функцию от второго. Так пишут, когда число аргументов заранее известно и универсальный `curry` не нужен. Преимущество — читаемость вызова и явный порядок аргументов: сначала то, что меняется редко (настройка), потом то, что меняется часто (данные). Поэтому в каррированных API данные обычно идут последним аргументом.

## Типичные ошибки

> [!WARNING]
>
> - **Каррирование функции с параметрами по умолчанию или rest.** `length` меньше, чем вы ожидаете, и функция вызывается раньше времени.
> - **Путаница `bind` и каррирования.** `bind` фиксирует аргументы за один раз и возвращает обычную функцию; каррированная функция принимает аргументы любыми порциями.
> - **Лишние аргументы.** В реализации выше при `args.length >= fn.length` все накопленные аргументы уходят в `fn`, в том числе лишние. Для строгих сигнатур это нужно учитывать.
> - **Потерянный `this`.** Если в обёртке использовать `fn(...args)` вместо `fn.apply(this, args)`, метод объекта потеряет контекст.
> - **Избыточность.** Если функция всегда вызывается сразу со всеми аргументами, каррирование только усложняет код.

## Коротко

> [!TIP]
>
> - Каррирование превращает `f(a, b, c)` в `f(a)(b)(c)`; частичное применение фиксирует часть аргументов.
> - Оба приёма строятся на замыканиях: накопленные аргументы живут в области видимости обёртки.
> - `fn.length` — число параметров до первого значения по умолчанию или rest; на нём построен универсальный `curry`.
> - `bind` умеет частично применять аргументы слева, но требует указать `this`.
> - Промежуточные результаты можно переиспользовать, пока они не хранят изменяемое состояние.
